# ADR-011：电脑节点回执保留文件原文

2026-10-06。020完整Windows部署发现，本地节点Markdown末尾换行在上传后丢失。原因是服务端把用于校验字段的`text()`返回值当作文件内容，而该函数会trim。

节点成果仍按现有类型、非空、长度和项目范围校验；写入资产、计算哈希和生成新回执指纹时使用原始字符串，保留开头空格、CRLF、制表符和末尾换行。首版节点协议只传UTF-8文本，这不代表任意二进制传输。

新回执指纹包含`receiptVersion:2`，同一Run精确重传返回原资产，改动任何内容（包括空白）产生幂等冲突，不另建成果。已有旧版回执仍按原trim指纹识别重传，返回既有资产；不改写历史文件，也不声称恢复已丢失的空白。项目/节点许可与撤销、状态核验保持。

实际节点CLI、HTTP下载逐字节核对、新回执精确重传/空白冲突以及旧回执升级重传见[020](../dev/iterations/020-windows-deployment.md)。普通恢复包仍排除节点令牌并撤销配对，恢复后需重新连接。
