# ADR-029 对话修改当前草稿

054接续补充：同一任务重试可从经过校验的祖先尝试宿主回执恢复已保存版本，不限于当前Run回执；Task原始输入与手动冲突保护保持，见[ADR-031](031-draft-retry-receipts.md)。下文为051的原始决定与验证。

日期：2026-10-07。状态：本机实现、工程与真实Pi通过；实际浏览器交互待验收。

问题：草稿界面能手动编辑，但任务只绑定资产，Pi只有新建草稿工具，无法确定“修改这篇”所指原稿。

决定：界面保存当前编辑后提交稿件ID与revision。宿主验证项目、视图和版本，从数据库冻结完整原稿与来源进入Task.context；客户端不提供权威正文。任务幂等回放优先于再次检查已成功提交的旧版本。

只有选中稿件的Pi任务获准read_draft和update_draft。读取使用任务固定内容或同一次Run的宿主更新回执；长文显式分页，单页最多30000字，不把截断当全文。更新完整正文最多300000字，保留空白与CRLF；要求正确ID和固定版本，后来手动更新不自动授予覆盖权限。普通任务和旧许可不会获得新工具。模型正文通过业务工具读取，初始提示只带稿件元数据，避免重复塞入整篇文章。

原稿修改、来源合并、Run.resultDraftIds、事件和completed操作回执在同一SQLite事务提交。失败整体回滚；没有外部副作用的失败可记录failed。已完成回执按操作ID/输入摘要幂等返回，不能重放不同输入；普通工具入口不能绕过回执直接更新。原始内容保存在冻结任务输入，连续更新内容保存在回执。未知中断按既有对账规则处理，不自动重放。

界面保留所有草稿编辑器，发送准备等待正在进行的保存，有限次处理保存期间新增编辑；离线、冲突、保存失败或切换导致卸载时保留指令和本机内容。对话显示当前文章，任务显示已更新稿件数。切换稿件不改变已经捕获的提交对象。

实际读取和采集的新增资料通过完成回执加入来源；保留原稿引用，拒绝跨项目或已删除资料。不能只保留旧来源而遗漏本次新增事实依赖。

验证见[051](../dev/iterations/051-selected-draft-editing.md)：8项新增业务/API场景、145项完整工程检查和3请求真实Pi更新同一合成原稿。浏览器协议限制未绕过；发送前保存与界面切换的实际交互仍待验证。此决策不代表M0通过，不支持任意项目稿件越权修改，也不授权未知代码执行。
