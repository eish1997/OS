# 迭代036：专属ChatGPT会话交接

2026-10-07。035完成平台依赖和后台文件，属于progress。本轮选择远程模型接入准备，保持完整目标active、M0 verifying、M1未启动；不购买资源，不迁移真实账户。

## 实际实现

依据[ADR-023](../../adr/023-chatgpt-session-transfer.md)，将033方案的“只做SSH回调、不转移凭据”改为允许本工作台的选中授权会话受保护转移。来源先冻结，目标保留自己host ID并提交，来源验签后退役，目标负责之后刷新。不读取全局Codex授权文件，不包含在普通备份中，不给用户增加设置。

新增[迁移模块](../../../server/chatgpt-transfer.ts)与[共享授权锁](../../../server/chatgpt-lock.ts)。修改ChatGPTAuth使冻结、迁入未提交和已迁出的记录均禁止读取/刷新及重新授权；迁移状态有明确提示，保持ChatGPT选择，防止API回退。后端四个登录保护的POST接口用于Agent操作：recipient、begin、accept、finalize。来源有未完成模型任务或授权/刷新锁时拒绝变更。

## 本地实际HTTP与文件证据

[新增四项测试](../../../tests/chatgpt-transfer.test.ts)在同一测试进程中使用独立数据目录、两个应用服务与本地签名的合成身份。OpenAI响应被测试fetcher控制，异常外部请求直接拒绝，没有实际账户或推理请求。关闭重建的是应用实例；提交中断由定点写入异常注入，不计作实际杀进程或跨机器故障通过。

- 实际登录、加密包、重复请求、目标host ID及设置保留；来源退役后无本地会话文件且不撤销远端grant。目标实例关闭重建后独立刷新，来源持续拒绝；状态、快照和普通备份不含令牌。
- 错误接收主机、篡改密文、来源不符与伪造回执拒绝，原资料保持；不覆盖已有目标连接。
- 目标写完凭据但active提交中断：两个服务均不能使用，目标实例重建后重试恢复。来源删掉凭据后retired提交中断：保持拒绝，重试完成退役，不重复撤销。
- 排队/运行模型任务、进行中的刷新阻止冻结。测试的“运行”是持久业务状态，刷新是受控异步HTTP契约，不宣称真实模型执行或远程断网已经通过。

初次与最终针对测试各4项通过；排队保护是复核补齐的最终改动。完整回归与代码哈希以[收尾审计](../../../output/dev-evidence/chatgpt-transfer-final-audit.json)为准。035当时的基线另存历史，避免把当前报告算作旧代码。
