# ADR-004：存储写入限制与恢复空间

日期：2026-10-06。状态：本地工程实现/验证通过，生产容量及文件系统配额待部署验证。来源：存储规范第8节、主文档20.6、M0-04/07。之前仅资产500MB有写入限制，其余是只读统计；本轮补齐应用写入入口，不降低部署验收要求。

默认字节上限：整体数据目录2GiB、数据库/索引768MiB、资产500MiB、上传暂存20MiB、原生代理会话组见[ADR-037](037-session-group-capacity.md)（单文件仍128MiB）、执行目录64MiB、运行日志4MiB。至少保留64MiB磁盘可用空间，整体和数据库各预留4MiB给登录、取消、状态、节点心跳、撤销和对账。配置字段见根目录.env.example。数据库统计包括主文件/WAL/SHM，整体统计包含目录内其他文件及凭据大小，内容不进入诊断；外部备份与.runtime启动器日志不计入数据目录配额。

宿主同步写入使用跨进程排他锁，事务内累计保守数据库增长估算，拒绝容量不足、测量失败和链接异常；SQL事务回滚不能留下半个业务对象/事件。资产暂存和预估索引在写文件前检查。SQLite max_page_count另限制数据库主文件增长；journal_size_limit是检查点后的目标，不被宣称为WAL绝对硬上限。已经超过新配置上限的旧数据不自动删除，按实际状态停写并要求调整。

Pi1.0.3公开_persist钩子在写入前检查原生JSONL，首次flush包含缓冲的header/setup/user条目。拒绝写入后标记会话不健康，在后续模型请求前及prompt返回后再次检查，防止SDK事件捕获错误后被当成成功。只启用M0原生追加；未暴露分支/迁移写入给代理，实际模型会话继续仍待API验证。

已知活进程持锁时拒绝新写入；原PID确认不存在后，通过独立恢复锁复核归属并移除临时写入锁。不根据超时杀进程，也不猜测未知锁可删除。锁残缺、PID被复用或恢复锁因崩溃遗留时保留现场，需要核对进程身份后人工处理；只涉及两个临时锁文件，不清理资产。

日志仅记录固定类别/时间，禁止原始错误/凭据正文；到限停止追加并报告丢弃数，已有记录不删除。电脑节点默认独立64MiB目录上限；与主服务数据目录同机时额外共享整体限制。节点回执先写.next再原子重命名，中断保留旧回执；已存在的可信成果按Run对账重用。CLI重复错误抑制且错误输出总量上限1MiB。未知代码执行依然关闭。

应用限制不等于操作系统磁盘隔离：目录外写入、其他程序抢占空间、数据库/WAL真实物理开销和未来未知插件必须由部署文件系统配额、账号权限及容量实测补齐。数据库估算较保守，可能在实际硬上限之前拒绝新增内容；4MiB恢复区不是无限控制请求预算。有效登录会话最多32个，设置页可撤销其他会话；被撤销浏览器退回登录。

证据：[容量测试/全部代码基线](../../output/dev-evidence/verification/report.json)，tests/capacity.test.ts覆盖HTTP停写与读取/导出/取消、SQLite直接SQL、实际Pi原生会话、日志、空间预留、多进程锁/杀进程与节点回执中断；[真实浏览器项目/设备会话](../../output/dev-evidence/ui/project-interactions.json)。没有真实模型、远程手机或独立备份通过证据。
