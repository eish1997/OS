# ADR-020：复用 Caddy 提供 HTTPS 入口

2026-10-07（Asia/Shanghai）。承接用户“像 Codex 一样打开就工作”的要求，部署配置由开发 Agent 管理，不成为日常对话的前置表单。

## 决策

复用官方 Caddy 2.11.7，不在业务服务内实现证书签发或反向代理。[配置](../../deployment/Caddyfile)与[版本锁](../../deployment/caddy-lock.json)进入工程校验范围。业务服务仍只监听回环，由同主机代理访问；公网域名、入口和证书落实后才能提供远程地址。

默认代理绑定 127.0.0.1；部署 Agent 取得真实主机和入口后明确配置公开绑定。固定 HTTP/1.1、HTTP/2，不启用未经验证的 HTTP/3。管理接口关闭，上传请求上限为 10 MiB，读取请求和等待上游响应头有界，事件流没有固定总写入超时。公开部署使用自动证书；独立测试才使用 `tls internal`，且 `skip_install_trust` 防止修改系统信任。

事件流沿用 Caddy 对 `text/event-stream` 的自动及时刷新，不设置负数 `flush_interval`；官方文档说明负数会改变客户端断开时的上游取消行为。[反向代理](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)、[全局选项](https://caddyserver.com/docs/caddyfile/options)。这份配置未设置请求重试或响应缓存，不能通过重试掩盖写入回执的不确定性。

远程模式的写入来源只接受配置的入口。本机 Vite 的 4311 开发来源例外仅限 HTTP 回环部署，不能沿用到 HTTPS 或其他远程地址。显式跨站请求继续拒绝，节点仍使用独立令牌路由。

## 实际验证

[探针](../../scripts/probe-https.ts)启动独立 Windows Caddy 和真实 Node 后端，使用独立数据目录、临时登录与零模型配置，均只绑定 127.0.0.1。测试 CA 只传给该次 Node TLS 请求，证书验证保持开启，未添加到系统/浏览器信任。HTTP/2 也实际验证证书和 ALPN。

[实际结果](../../output/dev-evidence/https-proxy.json)：未授权 401，Secure/HttpOnly/SameSite 登录 Cookie，页面和构建 JS 经 TLS 可读；恶意来源与开发来源 403；10 MiB 原件全字节和 SHA256 一致，超限 413 且不生成资产；第二会话旧版本修改 409、导出保留资料引用。真实 fixture worker 产生两个成果，HTTP/2 事件流持续 65 秒、65 个心跳和 17 个有序事件，首心跳 116ms；撤销后 707ms 内结束流，新请求 401。所有临时进程通过其保留的实际进程句柄结束，主工作台身份保持，零模型请求。

首轮实际测试证明远程部署接受开发来源 201，失败记录随后续探针归档在独立 private 目录；修复后同一探针通过。官方下载最初误用 SHA256 比较官方 SHA512 清单，校验拒绝后没有执行，改用 SHA512 比较通过后才提取根目录单一 exe。版本和哈希见[下载记录](../../output/dev-evidence/caddy-release.json)。这是官方 HTTPS 来源及摘要完整性核验，未验证发布签名；Linux 包未下载或运行。

## 部署边界

尚未提供公网 DNS、公开证书、远程主机或真实跨网络手机证据。当前本机入口维持 HTTP 回环；隔离 HTTPS 测试不把本机升级为公网服务。生产凭据、证书目录权限、受监督启动、文件系统配额/WAL、异地恢复和电脑节点断线/唤醒仍按原部署门槛验收。腾讯比较与 M1 不因代理通过而跳过。

ChatGPT 连接在本机自动模式中保持；远程主机的订阅授权及唯一刷新所有者需单独落实，不能复制整个凭据目录充当部署。用户无需学习上述配置；确需其账户授权或购买资源时，开发 Agent 再提供具体、可理解的选择。
