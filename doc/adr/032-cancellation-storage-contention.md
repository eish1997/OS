# ADR-032 取消请求的存储竞争与原子记录

日期：2026-10-07。关联L-03b/M0-03b、07。实现、24项针对性与159项完整检查通过，已正常应用主服务；证据见[056](../dev/iterations/056-cancellation-contention.md)。

问题：055真实Pi保存稿件后，首次取消HTTP423；独立真实写入进程持锁300ms时，原取消立即失败，没有记录取消，释放后重试才成功。另外，原实现取消标记与run.cancel_requested事件分两次提交，事件写入失败可能留下部分结果。

决定：HTTP取消使用requestCancel，在存储准入竞争时异步等待，获取锁的等待最多1000ms。等待让出事件循环，允许页面读取及调度/心跳继续；只有明确的“其他进程正在写入”准入错误可以等待，业务回调开始后的任何异常都不自动重放。同步cancel供已有宿主调用，仍使用正常同步准入，不把所有数据库写入改成有等待。

获得准入后重新读取Run。已经终止或已记录取消的运行直接返回当前状态；非running任务正常转cancelled；running任务仍先记录取消请求，实际停止由原调度器确认。标记和事件在同一SQLite事务提交或回滚，重复请求保留原时间、版本与唯一事件，不伪报实际进程已经停止。

长时间占用仍有界返回423，Run和活锁保持；异常/损坏锁不删除或接管。请求等待期间任务已由合法写入者完成时返回completed，不把终态改成cancelled。旧未知外部动作、来源、会话与重试协议保持，未增加模型调用或权限。

验证包括真实短/长子进程、并发HTTP取消与读取、合法锁拥有者提交终态、事件写入失败回滚且回调最多一次、损坏锁、排队/终态与原有真实worker取消。该修复不证明历史042或055那次生产锁具体持有人，不替代真实OS/UI和用户价值验收。
