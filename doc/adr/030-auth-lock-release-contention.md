# ADR-030 授权锁释放时的存储争用

日期：2026-10-07。本机修复与验证，关联L-03a/M0-01c、01d、07。不证明历史042交接423的根因。

问题：withChatGPTLock的业务回调已经完成，finally释放auth.lock时另一个真实进程正持有存储写入锁。零等待释放失败，auth.lock留在原进程名下；进程仍活着，后续授权操作会持续被当作在途操作拒绝。独立临时目录实际复现见[修复前](../../output/dev-evidence/auth-release-052-before.json)，只保存合成标记、没有模型或供应商请求。

决定：释放时最多1000毫秒等待存储锁准入，仅重试锁获取，不重跑回调、不回收活写入者。更长争用依然有界失败。回调结束后在进程内记住该路径、该进程生成的完整锁字节；下次同进程操作在存储互斥内只能回收与该完成记录完全一致的锁。活回调没有这种记录，未知ID、不同字节、不同进程、不同平台或损坏/链接记录沿用原保守规则。进程重启不携带这一内存证据，旧进程退出仍按ADR-025验证。

释放也验证文件类型、大小和完整拥有者记录；不只凭id删除。如果回调本身报错而释放同时失败，保留回调原错误，不把真实网络或业务失败改成笼统存储争用。长争用后仍保留确切完成证据，下一操作可恢复；不宣称原外部请求未执行，也不自动重放。

影响：正常短争用无需重启解除授权锁；长争用可能给调用方一次有界错误，后续恢复不会重新执行旧回调。这个1000毫秒是同步存储锁等待上限，可能短暂延迟主服务其他请求；没有扩大网络超时、权限、费用或未知代码能力。

验证：真实自有短进程分别持锁500和2500毫秒；回调最多一次、结果标记保留、恢复后锁删除、改变ID的活锁不能借用完成记录、业务失败原错误保留、其他原有活/死/跨平台/损坏边界不变。见[052迭代](../dev/iterations/052-auth-lock-release-contention.md)及[修复后](../../output/dev-evidence/auth-release-052-after.json)。合成竞争不是实际用户OAuth刷新或历史042故障现场。
