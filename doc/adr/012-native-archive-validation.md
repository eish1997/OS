# ADR-012：会话归档检查与交互接续检查分开

2026-10-06。完整混合容量验证发现，默认会话存储允许128 MiB，但自动备份的恢复检查复用了交互接续的2 MiB限制。已成功保存的8 MiB原生会话因此使整次备份失败，即使资产、数据库、会话和整体容量均在允许范围内。

交互接续保持[ADR-007](007-native-project-continuation.md)的2 MiB首版保护；后台归档检查改用独立的archive模式，覆盖默认128 MiB会话存储范围。仅自动备份恢复校验调用archive，HTTP和Agent工具不能选择该模式。不能将归档成功解释为较大历史已经可以交互接续，也不能将默认范围的证据推广到自定义更大的会话配额。

两种模式继续核对项目目录、路径与链接、JSONL版本3、会话ID、条目链、文件哈希及完整SessionBinding。后台恢复还用固定Pi1.0.3的SessionManager.open和buildSessionContext实际重开，不能只检查文件存在。原文件与恢复文件都不改写；恢复后接续仍须通过交互保护及未知操作对账。

备份继续在所属后台进程内校验，不把大文件解析移回服务端事件循环。不放宽独立存储、所有者、租约、保留或磁盘剩余空间保护；校验失败保留旧恢复点，不产生成功回执。

专项回归使用超过2 MiB的合法会话：交互拒绝、自动备份与干净恢复成功、SDK重开、字节一致。随后破坏源会话身份，下一次备份失败且原成功点保持、自己的暂存目录清理。91项工程检查、实际8/32 MiB归档、混合容量、七点启动扫描及当前产品应用证据见[迭代021](../dev/iterations/021-mixed-capacity.md)；搜索和生产等门槛仍保留，不能据此宣称完整M0通过。
