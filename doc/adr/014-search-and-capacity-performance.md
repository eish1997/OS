# ADR-014：后台搜索与单次容量遍历

2026-10-06。混合容量验证发现，约1 GiB正文的小资料查询超过2秒，写入前容量测量重复遍历同一目录。保持文件为事实来源、权限/项目隔离、哈希、分页和新鲜容量检查，优化执行方式。

搜索原先分别执行完整COUNT和分页LIKE查询；现在一次查询候选ID与元数据，计算总数后选页，仅加载该页的索引正文。实际HTTP和Agent操作在最多两个所属只读子进程中搜索，30秒界限；只传固定数据库/项目/查询参数与基本运行环境，不加载工作台配置或模型凭据。等待所属进程实际退出0且合法回执再交付结果，取消及关闭仅处理自己创建的进程。

子进程核验原文件路径、大小、UTF-8及完整SHA256，片段来自真实文件；索引不一致报告修复ID，宿主再次读取原件并执行原容量约束。使用结果前复核HTTP登录或Agent运行/取消/时限/工具许可，并复核资产项目、状态、版本和哈希。变更或损坏资料不作为有效结果。取消的只读搜索记录failed，不把它当成未知写入副作用。直接同步tool/search调用保持同步，实际Agent executeOperation和HTTP使用后台路径。

界面查询变化、项目切换或组件卸载会撤销之前的fetch；原查询字面量、分页、结果来源和项目视图行为保持。后台进程不会运行模型或打开外部网络。

容量测量在每次准入时重新完整遍历根目录，按第一层归属同时计算整体及分组；不缓存信任旧文件大小。未知根文件计入整体，SQLite主文件/WAL/SHM计入数据库，链接不跟随并报告问题；读目录失败也报告问题。原写入排他锁、分项和整体上限、恢复预留及数据库引擎限制保持。生产文件系统物理配额/WAL硬上限仍需单独验收。

95项工程测试及原隔离混合资料HTTP实测见[迭代022](../dev/iterations/022-search-performance.md)。完整场景小资料查询最高1633毫秒，查询期间数据读取最高23毫秒；一次返回50份8 MiB正文仍为2757毫秒，保持2秒门槛未通过。没有缩减页数或省略哈希来换取通过。SQL instr候选实际更慢，记录后未采用。
