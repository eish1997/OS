## 1 部署与入口

电脑浏览器、手机浏览器和后续 Electron 客户端访问同一 HTTPS 主服务。主服务管理登录、项目、任务、资产与记忆，并调度远程 worker 或电脑节点。

服务逻辑分层：

```text
电脑网页 / 手机网页 / 后续桌面客户端
                 |
             HTTPS 登录入口
                 |
       统一业务 API / 事件 / 文件访问
                 |
   状态数据库 + 共享资产库 + 唯一调度
                 |
        远程 Pi worker / 电脑节点
```

不把模型密钥或执行扩展放进浏览器。数据库、Pi 控制接口和任意命令执行接口不公开给客户端。首版一个主服务实例，维护成本控制在单用户可管理范围内。

开发可在本机复现相同边界；它不代表远程部署完成。实际服务器、域名、证书、供应商及费用需要部署任务决定。访问验收分本地模拟和真实电脑/手机跨网络验收。

## 2 远程与本地执行分工

| 位置 | 职责 |
| --- | --- |
| 主服务 | 权威业务状态、授权、预算、队列、资产登记和事件 |
| 远程 worker | 不依赖电脑的研究、资料处理、代码实验及内容生成 |
| 电脑节点 | 获准的本地目录、桌面软件、电脑特定硬件与环境操作 |
| 手机 | 对话、上传、查看进展、审批、阅读和轻量编辑 |
| 电脑界面 | 复杂编辑、对比、大型预览和本地工具配置 |

任务声明 requiredCapabilities、允许节点和数据范围，调度器在能力与授权均满足时分配。不能仅按“电脑在线”随意调度。

首版远程单执行 worker；电脑节点从固定可信样例接入。节点接入时全局仍限制最多一个实际执行任务，M1 才升为两个，电脑节点不会绕过预算与并发上限。

电脑节点主动建立认证连接，不要求家庭网络开放入站端口。配对凭据限定单节点、能力和项目范围，可撤销。手机操作通过服务端授权检查，不能要求节点执行任意未授权路径或命令。

## 3 数据归属

| 数据 | 权威位置 | 节点/客户端副本 |
| --- | --- | --- |
| 项目、任务、Run、事件、关系 | 服务端数据库 | 缓存与只读投影，不独立写权威状态 |
| 共享图片、视频、文档 | 服务端文件库或对象存储 | 下载缓存、编辑工作副本 |
| 代码项目 | 获准工作区与固定源码版本 | 工作目录不等于完整备份 |
| Pi 会话 | 所属执行环境的原生存储 | 主服务保存映射与可备份快照 |
| 工作台对话与素材索引 | 服务端 | 浏览器必要缓存 |
| 电脑专属敏感资料 | 电脑指定目录 | 只有授权范围内上传或发送模型 |
| 凭据 | 服务端秘密存储或节点系统凭据存储 | 浏览器不持有模型和发布密钥 |
| 临时构建、缩略图、索引 | 对应环境缓存 | 可重建，允许受控清理 |

任务登记“仅本地资产”时手机只能看到获准元信息，不能显示成已经可下载的共享成果。上传并登记完成后才成为两端可访问资产。

Pi session 与模型压缩状态按原生接口备份恢复。跨节点转移运行需单独验证，不通过复制几段聊天强行继续原会话；首版固定运行与节点绑定，节点不可用时等待或建立经对账的新尝试。

## 4 首版存储方案

默认采用主服务本地磁盘上的 SQLite，由服务端控制数据库写入；浏览器和节点通过 API 访问。不可通过网络共享目录让不同设备直接打开同一数据库文件。

资产首版保存于服务器持久文件卷，采用统一 StorageAdapter：

- 写入暂存资产、校验内容、提交不可变版本。
- 按 assetId/versionId 读取、授权下载、删除和检查存在。
- 文件路径或对象 key 是内部 locator，不直接作为客户端资产身份。
- 后续接对象存储时保持业务身份与引用不变。

对象存储不是数据库，Git 也不是大体积资产备份。首版不强制部署独立向量数据库；先实现标签、文件名与全文搜索，语义索引后续按实际需要引入。

数据库驱动、事务方式、索引和迁移通过 ADR 定义。若需要多个服务实例直接写状态、持续高写入负载或更复杂部署，再评估 PostgreSQL，不因有手机自动迁移。

建议服务器持久目录按职责区分 db、assets、sessions、workspaces、cache；真实安装路径由配置决定，数据不得放入临时目录或随应用版本覆盖。

## 5 文件上传、版本与同步

上传流程：授权与大小检查 → 建立 uploadId → 暂存传输 → 校验哈希/长度 → 提交版本 → 登记关系 → 发出资产事件。未完成上传显示 pending 或失败，不计为可用成果。

手机照片、电脑文件和节点产物走同一流程。设置上传配额、文件类型策略和超时，大文件按需支持分段续传。哈希只用于完整性和受授权的去重，不能以哈希绕过访问权限。

文件上传和数据库无法假定单一原子事务，使用操作日志与对账清理中间状态。节点断线保留可恢复暂存；重连查询 uploadId 和已有回执，不重复登记资产。

共享资产采用不可变版本。编辑携带 expectedRevision；电脑和手机同时修改时检测冲突，保留分支或提示合并，不采用最后写入者无声覆盖。草稿自动保存显示保存中、已保存、离线未同步或冲突。

首版以在线使用为主。离线可保留当前草稿或只读缓存，但不承诺离线执行、全量同步或编辑自动合并。客户端重连后按事件游标更新，不能把缓存重新写回覆盖服务端。

## 6 节点离线与恢复

Node 保存标识、平台、能力版本、在线状态、最后心跳与资源上限。租约分配保存 runId、nodeId、leaseId 和过期信息。

尚未开始的电脑任务在节点不可用时显示 waiting_node；已开始任务失联进入 interrupted/reconciling。主服务停止新增派发并保留已有成果，不能立即在另一个节点重复执行。

节点重连核对租约、任务、进程身份和产物。过期执行结果可保存为待核实成果，但不能覆盖新尝试状态。外部写入结果未知时先查询或人工核实。

关闭手机和电脑界面不终止远程任务。电脑睡眠只影响电脑节点。服务器故障会影响远程执行，需要持久队列、进程监督、对账与恢复，不能承诺无条件持续运行。

## 7 登录、授权与预览

首版单用户账户，电脑和手机各自有可撤销登录会话，限制暴力登录并记录关键安全事件。具体身份组件、cookie/令牌策略通过 ADR 与实际测试决定。

服务端验证每个项目、资产、命令、事件订阅和文件请求的权限。HTTP 与事件连接均校验身份；注销或撤销会话后不能继续操作。

文件通过授权代理或短期有效访问方式读取。所有预览按类型处理：生成 HTML、开源应用和文档内容不在拥有工作台凭据的主页面任意执行，使用受限预览或独立隔离源。嵌入截图不能当作可运行项目验收。

节点按许可目录和工具操作，防止路径穿越与越项目访问。下载、网页内容和文件说明是非可信资料，不改变策略。限额、凭据与授权由宿主强制，不能只通过提示词约束。

## 8 增长、清理和搜索

记录项目、资产版本、会话和缓存占用。配额覆盖磁盘、上传、日志保留和临时工作目录；达到上限时先阻止新增写入并给出操作建议，不私自删除成果。

2026-10-06工程落实：已接入整体与分项写入检查、磁盘/恢复预留、SQLite主文件页上限、Pi原生会话保存检查、有界运行日志、电脑节点独立容量及同机整体限制。设置页展示实际上限与用量，设备会话可撤销。默认值、恢复锁和未验证的生产物理边界见[ADR-004](adr/004-storage-admission.md)。应用准入不能替代部署文件系统配额；生产容量、WAL实际增长、日志/备份保留与独立恢复仍需配置和实测。

长期保留原始输入、关键成果、决策和必要验证；缓存、缩略图和失败构建可以按规则清理。重复内容去重与逻辑资产身份分开。

归档不删除；删除检查跨项目引用，进入可恢复期后再清理无引用内容。索引同步失效，不能继续检索已删除记忆。保留期与删除对备份的影响必须告知用户。

## 9 备份、恢复与数据迁移

备份包含业务数据库的一致性快照、被引用资产、工作台记录、可恢复 Pi 会话、版本与配置清单。密钥采用独立保护和恢复配置，不默认写入普通项目导出。

服务器同盘副本只用于快速恢复；独立备份位于另一个存储故障域。首版建议每天自动备份、保留多个恢复点，具体容量、保留期、允许丢失时间和恢复时长在部署前确认并实测。

2026-10-06本机落实：E/C盘独立物理磁盘联合恢复已通过；内置每天到期后空闲维护、默认最近7个有效恢复点、新副本逐次实际恢复检查、仅清理自有旧副本，当前产品首备份有实际记录。[ADR-008](adr/008-automatic-independent-backup.md)。进程未运行或一直未空闲时会延后，不承诺24小时数据丢失上限；大规模维护时延、系统守护和异地恢复仍需部署验收。

019把复制/恢复/保留轮转移到独立后台进程，源库只读一致快照，宿主持有并续租调度租约。界面继续读写，新执行排队；捕获后的编辑进入后续恢复点。384MiB三次实际维护共1180次数据接口读取、最慢约49.6ms，保留2点轮转和原生会话恢复通过。[ADR-010](adr/010-background-backup.md)。完整混合容量、启动扫描、生产物理配额/权限、守护和异地恢复仍待验收。

备份传输和静态内容按敏感级别保护；恢复在干净目录或新环境执行，核对哈希、关系、会话与未完成任务。没有实际恢复演练不能标记备份能力通过。

039已准备[基于rclone的加密转存](adr/024-encrypted-offsite-backup.md)，在本机合成目录通过完整读回、原生会话重开及错密钥/损坏/缺提交记录拒绝。独立恢复密钥另存，普通备份继续排除模型授权；未配置云桶、未接自动转存，不能当作异地恢复通过。

导出项目包含共享引用的必要资产和来源清单。仅本地资产需要节点在线或明确列出缺失项，不生成虚假的完整导出。

应用升级区分程序回退、数据库迁移恢复与资产保留。复制旧数据库覆盖新版状态可能删除后续成果，不能作为默认恢复方式。同步与备份分别设计，误删同步不等于历史恢复。

## 10 首版验收与后续范围

M0 必须证明：

- 同一账户的电脑和手机看到同一项目、任务和资产版本。
- 手机发送指令，远程任务执行，关闭界面后可再次查看结果。
- 手机上传文件，电脑读取；电脑编辑草稿，手机看到一致版本。
- 重复提交、事件断线、上传中断和编辑冲突不会伪报完成或静默覆盖。
- 电脑节点离线时专属任务等待，远程任务在允许并发内正常调度。
- 节点重连先对账，成果只登记一次，越权请求被拒绝。
- 未登录/会话撤销后，接口、事件和文件不可访问。
- 真实跨网络访问和独立备份恢复有证据；未部署只能标记本地验证。

M1 验证全局两 worker 并发、父子预算、节点能力版本与升级恢复。后续再加入移动安装体验、通知、离线编辑、多用户和自动节点迁移。

本次文档更新不执行服务器购买、上线部署或真实云端数据上传。


## 11 候选记忆服务的数据边界

首个选型实验为[TencentDB Agent Memory](首个验证项目-TencentDB-Agent-Memory.md)，尚未决定采用。若接入，工作台保存记忆身份、来源、范围、状态、修订和服务映射，组件的实际原始数据与派生数据职责在固定版本 ADR 中明确，避免两套互相冲突的权威。

候选服务使用何种数据库、索引和模型外发路径需实际核对；不把工作台 SQLite 的默认方案当作外部组件也能使用 SQLite 的承诺。实验只用非敏感构造数据，真实资料进入组件和模型均受现有授权范围限制。

停用/删除必须传播到检索、派生索引与缓存。联合备份纳入无法从现有资产重建的记忆数据、版本和映射；移除组件前验证导出、恢复与替代路径。代理接入不能绕过模型预算、项目权限或数据外发策略。
