## 实际验证

[探针](../../../scripts/probe-node-reconnect.ts)启动独立真实后端、只监听回环的故障代理和实际local-node CLI。使用独立数据/许可目录及合成登录，模型密钥、调用与费用均为空或零，不连接主工作台、不运行未知代码。通过实际HTTP503、丢弃回复和真实时钟租约到期制造断线，没有用修改数据库状态模拟恢复。

[结果](../../../output/dev-evidence/node-reconnect.json)通过三项：

- 节点尚未连通时任务保持waiting_node，实际CLI观察两次503，不生成资产；连接恢复后同一节点进程开始原任务。
- 后端已提交成果但回复丢失时，节点本机回执保持未发送。重连补交同一回执，后端去重，只有一份资产；本机文件字节及最终换行保持，没有重新执行。
- 本机文件已落盘、提交前断线时，原任务随实际15秒租约到期进入interrupted。从交付失败开始观察到中断约12.75秒，租约早于交付失败建立，不能把此计时误写为租约总时长。新任务保持queued且没有本机文件。恢复后原回执自动对账，原任务仍为interrupted并标记已对账；随后排队任务完成。三项任务均attempt=1，共3份资产，各自字节与本机文件一致。

实际节点PID2504在三阶段保持同一进程，没有重启。最终只通过保留的ChildProcess句柄停止，实际SIGTERM退出已等待；代理请求/响应关闭、独立后端关闭。没有根据历史PID强停。
