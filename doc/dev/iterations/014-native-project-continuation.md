## 实现

项目后续对话默认接续同项目/模型连接/策略版本的已完成会话；每次Run通过固定Pi forkFrom/open创建独立原生分支，保留原件和旧工具回执。可选「新话题」不要求配置参数。排队追问固定直接前序Run，等其结束并确认进程退出后固定会话哈希；前序缺会话或有未知操作则停止，不能接回更早话题。

源文件项目目录、链接、身份、JSONL版本/链、2MiB上限、绑定、容量和提交后哈希变化均受检查。未知副作用或未对账中断不能接续。历史宿主记忆/摘要注入和记忆工具结果在新分支中移除，当前确认状态重新注入；原件不修改。失败尝试有可用原生会话时，新Run接续其历史，仍不自动重试未知操作。[ADR-007](../../adr/007-native-project-continuation.md)

## 发现的问题

旧SessionBinding使用Run ID作为主键，但实体表的ID全局唯一，绑定写入实际发生冲突。012探针的sessionBound字段只检查Run路径/ID，不能证明独立绑定已登记。已改用session:<Run ID>并等待宿主事务回执；诊断与新真实探针核对实际独立绑定。旧缺失绑定仅在持久Run与项目内完整v3文件身份匹配时重建，显式reconstructed，不补造旧验收结论。

受控供应商故障401/429/503经固定真实SDK验证：每次一次请求、没有自动重试、用量不完整；后续新prompt可以成功。原始供应商错误可能包含请求材料，现不写入原生errorMessage。这些是受控故障证据，不是假称真实账户被限流。

完整回归中随机回调端口曾被Fetch拒绝bad port；本机成功listen不代表浏览器可用。依据已安装固定Undici的Fetch端口表，授权监听有界避开禁止端口，指定禁止端口直接拒绝，8次分配仍不可用才报告失败。没有改Windows端口范围或增加用户设置。

UI脚本首次在390尺寸结束时尝试点击隐藏桌面退出按钮，清理超时；已改为撤销该浏览器自己的会话。失败报告保留在ui/history，最终脚本实际退出成功。
