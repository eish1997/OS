# ADR-023：本工作台专属ChatGPT会话的受控迁移

当前更新以[043](../dev/iterations/043-auth-lock-process-identity.md)为准：接口已于042加载，授权锁身份规则已于043应用；真实账户迁移尚未执行。原042的一次423根因仍未定位，不能用后续通过覆盖。下文“未重启”属于036当时历史。

2026-10-07。状态：本地合成凭据和HTTP实现已验证，实际账户/远程主机迁移待部署验收。

## 改变的依据

此前033/035方案将SSH回调桥接作为远程授权前置，并写了“不复制本机凭据”。核对[OpenAI自托管VM说明](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)后更新：官方明确支持同工具、同用户/工作区的受保护注册会话转移；VM保留自己的稳定host ID，并负责后续刷新。转移会话目前不提供完整的按主机区分用量归属和撤销能力，不能宣称各机器可分别撤销同一个授权。

因此允许迁移本工作台选中的专属会话；不是读取全局Codex缓存、导入其他工具凭据或把凭据包含在普通备份中。实际资源未准备好，不移动现有账户。首次或重新授权仍遵循[官方注册说明](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)的回环与PKCE约束；Codex自己的设备码流程不能直接视为本工具动态注册流程的可用接口。

## 协议与所有权

[实现](../../server/chatgpt-transfer.ts)使用X25519临时密钥交换、HKDF-SHA256和AES-256-GCM，包的认证上下文绑定来源/接收主机、目标密钥、连接ID和迁移ID。接收方用独立Ed25519密钥签收。加密与回执不替代来源确认；Agent必须经验证的HTTPS或SSH传递同一个已授权工作台的包，不接受网上下载的凭据包。

1. 目标准备稳定host ID与私有接收/回执密钥，只返回公钥描述。
2. 来源核对目标与选中连接，和刷新/授权共用锁。没有排队、运行、等待或未对账模型任务后，保存加密包并持久冻结，再返回包。
3. 目标核对预期来源与自身密钥，拒绝覆盖已有连接。先写installing，再保存选中注册和原模型设置，最后提交active；提交前读取和刷新均拒绝。
4. 来源核对签名和包摘要，先写retiring，再删除自己的凭据及包，最后写retired。来源继续保持停止使用状态，不远端撤销同一个grant，不自动回退API。

丢失响应可按相同输入重试：来源返回原冻结包，目标返回已提交回执，来源完成未完成的退役步骤。目标保留自己的host ID；原client ID、账户身份、connection ID、模型、自动设置和首次告知状态保留。来源冻结后没有自动解冻或撤销迁移接口；网络结果不明确时由Agent继续对账，不擅自恢复第二个刷新者。

这要求两个服务都运行本版本代码、同一主机只有一个权威数据目录。保护记录不可由另一个管理员删除来启动旧副本；未知代码和复制整台VM的隔离仍属部署边界。普通HTTP测试不证明真实HTTPS来源、Linux权限或不同机器的访问拒绝。

## 用户体验与操作范围

日常仍是一次连接、自动模型、直接对话。迁移由开发/部署Agent在资源与数据迁移阶段执行，四个POST接口均需工作台登录与现有来源保护；没有用户参数表，没有公开的原始令牌导出接口。新接口不会自行发现云主机或把当前账户发送出去。

源码改动已在新建独立服务中验证。当前主产品未重启，仍运行此前实例；部署或受控重启后新接口才可用。这一轮没有为真实账户创建接收密钥、冻结、导入或退役记录，也没有对OpenAI发起新授权、刷新、撤销或模型请求。

## 验证与保留门槛

[四项测试](../../tests/chatgpt-transfer.test.ts)使用本地签名OAuth身份与受控提供商响应，实际HTTP和持久文件；涵盖鉴权、加密输出、篡改/目标/来源拒绝、签名回执、幂等、实例关闭重建后目标单独刷新、普通备份排除、两个提交中断和模型排队/刷新锁竞争。两个应用在同一测试进程中，提交中断由定点写入异常注入；尚不是实际杀进程或两台机器故障证据。目标默认模型就绪仅是合成协议证明，不是实际账户在云端推理通过。

037新增[实际进程崩溃探针](../../scripts/probe-chatgpt-transfer-crash.ts)和[回归测试](../../tests/chatgpt-transfer-crash.test.ts)：在来源冻结落盘、目标提交active前、来源提交retired前实际SIGKILL自有Node进程，创建新进程恢复并核对只有目标能刷新。5个自有进程均终态，3次强制退出。它补齐036未证明的杀进程边界；仍是同机Windows合成身份，不是Linux、跨机器或断电/fsync证据。详见[037](../dev/iterations/037-chatgpt-transfer-process-crash.md)。

真实账户的同工具/工作区核对、SSH/HTTPS来源、云端实际刷新与工具调用、目标磁盘故障、授权撤销与数据主库迁移仍待验证。凭据交接不能替代停止旧业务主库写入、完整恢复/回退及原M0门槛。
