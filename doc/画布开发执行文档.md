# 全能画布开发执行文档

更新：2026-10-15。用途：单个 AI agent 长时间循环开发、恢复上下文与交付。

本文规定任务及执行方法；[开发现场](dev/current.md)是唯一进度台账。本次文档整理不代表已启动全部实施。开发时在用户授权阶段内持续推进，不为每个可逆步骤重复确认。

## 1 启动与恢复

1. 阅读[需求与验收](全能画布需求文档.md)、[架构与数据约定](全能画布架构与数据约定.md)、本文和[开发现场](dev/current.md)。恢复时优先看现场及任务相关章节。涉及界面时同时阅读 [design.md](design.md)，视觉风格继续生效。
2. 核对目录、分支、HEAD、工作区差异和适用的 AGENTS.md。保留未提交工作，核实归属，不当作残留删除。
3. 核对任务依赖、最近证据、运行进程和失败次数。文档与实际冲突先查事实，不盲目重跑。
4. 优先恢复现场已有的 doing 或尚未结束的 verifying 任务；只有它完成、明确阻塞或记录拆分/切换原因后，才选择下一个已授权且就绪的最小任务。就绪要求前置任务的验收证据对当前版本仍有效，不能只看 done 标签；仅一个 doing。大任务按父 ID 拆为 C04.1 等可独立验证的子任务，不每轮重写计划。

## 2 固定循环

读取现场 → 选择任务 → 明确验收 → 实现 → 实际验证 → 检查差异 → 更新现场 → 继续。

### 明确验收

记录任务 ID、用户可观察结果、输入样例、涉及模块、验证方式和停止条件。先查代码与证据。可逆细节采用架构默认，影响产品取舍的问题集中询问，继续不依赖回答的工作。

### 实现

先复用再补缺口，每轮交付可运行的完整路径，例如“加目录后保存并重开同一画布”。不能长期只写空接口。包括必要的错误反馈与恢复；静态数据不冒充已接通功能。

### 验证

- 运行相关类型检查、构建和有意义的测试。持久化必须验证真实磁盘与重启；交互必须实际运行界面。
- 正常流程之外，对数据写入、外部调用、版本更新补充失败与恢复用例。
- 截图证明可见状态，日志和断言证明数据与执行。编译成功不代表功能完成。
- 模型、网页与桌面穿透必须在真实承载上验证。替身测试单独标明，不代替真实验收。
- 阶段整合后执行相关回归；无新改动、失败或疑点时，不反复运行同一检查来延长循环。

### 自检与保存检查点

审查 diff：无凭据、真实数据、缓存、无关修改或上游大面积格式化。确认仍以资产管理为主体、统一编辑且能独立运行。

立即更新现场的状态、改动、证据路径、版本、输入、命令与退出结果、限制和下一动作。提交遵循用户及仓库规则；未提交也必须描述工作区。暂停、切换任务或上下文不足前先保存检查点。

### 继续或停止

验收通过才为 done，尚待验证为 verifying，外部条件缺失为 blocked。完成后自动选择下一项已授权且就绪任务，直到该范围交付、无法继续或用户要求停止。不用“接下来可以做”代替未完成的已授权工作。

### C05 首版必须补齐的验收

- 按 C02 确定的作品格式导出整张画布，并导入全新应用管理区；不能用原管理区的缓存证明恢复成功。核对节点身份、布局、未落盘工作内容本体、文件关联和版本清单。
- 明确导出包是否包含外部原件；未包含且源目录不可用时显示缺失并可重新关联。缺失节点依赖保留数据并提示，普通导出包不得包含凭据。C04 的单项成果落盘不能替代作品导入导出。
- 在 C02 约定的设备、目录/对象数量、素材规格和活跃预览数下，验证扫描/加载、交互响应及资源占用预算并保存测量结果。未达标不得将 C05 标为 done；不能测试后静默降低预算。
- C06—C11 引入的新媒体、节点和窗口能力在对应阶段扩展基准；C12 做整体回归，不替代首版恢复和性能验收。

### C08 隔离必须补齐的验收

在实际选定的节点运行时及宿主桥接路径上，用独立样例目录和测试用哨兵值验证：范围外文件访问、未声明网络/进程能力、宿主凭据读取均被拒绝；既无返回数据，也无相应磁盘/网络/进程副作用。不使用真实凭据作测试材料。

同时验证已声明且允许的能力可正常执行、死循环可终止、拒绝或崩溃后其他画布内容仍可操作。仅通过 worker 终止测试不足以完成 C08。上述证据是 C09 运行真实生成节点的前置条件；运行时或桥接权限实现变更后必须重验。

## 4 失败与阻塞处理

同一失败三次尝试无新证据时停止原样重试，记录复现、假设、每次改动和结果，换更小复现或诊断方法。缺依赖、外部服务或必须由用户决定时，记 blocked、解除条件和可继续任务；不能伪造结果、降低验收或无限重试。

验证失败且需要修改实现时，原任务从 verifying 回到 doing；仅缺验证条件时保留 verifying 并记录原因，外部阻塞则转 blocked。失败记录沿用任务 ID 和同一失败标识，尝试次数跨会话累计，不能因恢复上下文而清零。阶段整体验收失败时定位并重开责任任务；尚未定位时建立该阶段下的诊断子任务，阶段保持未通过，不因子任务曾全部 done 而跳过失败。

不擅自更换 OpenPencil、删真实数据、覆盖凭据、开通付费资源或公开发布。已有明确授权无需重复询问；等待无回复不算授权。测试使用独立样例目录。

中断后检查进程、文件和日志再重试；操作 ID 防止文件和外部任务重复执行。后续改动影响旧证据时，记录失效原因和对应版本，并沿依赖关系检查任务、阶段与交付状态。依赖该证据且受到影响的已完成项退回 verifying，写明所需回归；新任务在所需证据恢复有效前不能视为就绪。未受影响的依赖项保留原状态并记录判断依据，不机械重跑全部测试。修复后只有必要回归通过才恢复 done，不能只重标状态。

## 5 最新检查点模板

现场保留最新检查点，长日志放证据目录并链接：

```text
任务 / 状态 / 授权阶段：
分支 / 基线提交 / 工作区改动：
本轮结果 / 决策依据：
验证：环境、命令、输入、结果、证据路径、适用版本
证据失效影响：受影响任务/阶段、必要回归、未受影响项的依据
失败：复现、尝试次数、已排除假设
运行资源：进程、端口、临时目录及用途（没有则写无）
剩余工作 / 阻塞与解除条件：
下一动作：具体文件、操作或验证命令
```

证据沿用 output/dev-evidence/；私人材料进入其被忽略的 private 目录，台账仅脱敏结论。关联证据产生时的提交或明确的未提交状态，不写令牌与会话秘密。

## 6 完成与交付条件

done 同时满足：需求可追溯、真实实现、相关验收与必要回归通过、数据/错误边界验证、现场和启动说明准确。代码完成与用户体验验收分开记录，不编造认可。

阶段交付包含可运行版本或产物、环境与准确启动命令、完成行为、验证证据、已知限制、数据恢复方法和剩余任务。所有已授权任务完成后结束循环，不靠持续新增任务延长工作。
