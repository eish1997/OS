# OS 全能画布需求文档

版本：0.10  
日期：2026 年 10 月 15 日  
状态：重构需求与验收基线（未完成项不代表已实现）  
适用对象：产品设计、交互设计、开发与测试

## 1 产品定位与确认范围

产品主体是画布式本地资产管理器：将本地文件夹加入管理根后，自动为其建立全能画布，以画布作为浏览和组织内容的主要方式。画布同时承载真实本地文件和工作过程中产生的内容，结合无限画布、在线白板、设计编辑、多媒体、工具和内置 agent。

文件夹提供资产入口，画布保存工作过程。用户可以选择工作成果，通过命令或快捷键保存到本地文件夹；与本地文件关联的节点具有明确标识。不能把产品仅做成与本地目录脱离的设计文档编辑器，也不能把它仅做成文件缩略图的自由排列视图。

OS 是产品主体。GitHub 仓库 `eish1997/assetcutter-ai-pro` 是能力迁移来源，其素材处理、生成、预览等能力按需融入 OS；不以嵌入整套旧工作台作为目标。

开发顺序明确为画布先行：先建设可独立运行和使用的画布模块，后续将其作为重构后的 OS 的核心功能。画布开发不等待整个 OS 重构完成，也不依赖当前工作台的页面布局。

## 2 核心使用体验

用户加入并打开本地文件夹，在对应画布中浏览文件，同时粘贴内容、记录想法、生成成果或使用工具。正式文件与工作过程共存，满意的成果可保存到本地目录。手动操作与 agent 操作使用同一套内容身份和保存规则。

独立阶段提供简洁的本地资产入口，用户无需启动完整 OS 工作台即可加入目录、打开对应画布、编辑和保存工作内容。项目管理、对话和任务系统在后续通过接口接入；不要求先创建 OS 项目才能浏览文件夹。尚未接入的能力不使用模拟结果冒充可用。

核心体验包括：

1. 在同一画布上组合图文、视频、模型、网页、便签和工具。
2. 对素材直接编辑，也能选中素材后用自然语言提出要求。
3. 工具执行时可以继续浏览和编辑其他内容。
4. 通过对话开发新节点，直接在当前画布中试用和修改。
5. 发布后的节点可以在其他画布中复用，已有作品能够长期打开和恢复。

### 2.1 对话开发节点示例

用户提出：“做一个图片对比节点，接收两张图片，用滑杆对比，支持横向和纵向切换。”

预期过程为：

需求对话 → 创建开发草稿 → 在画布渲染真实实例 → 拖入图片直接测试 → 对话提出修改 → 更新预览并保留测试素材 → 验证 → 发布 → 在另一张画布添加使用。

节点必须是实际可交互的运行实例。占位图、效果截图和模拟输出不能作为功能完成的证明。尚未接通的功能显示真实状态。

### 2.2 素材创作示例

用户将参考图放到画布，标注需要保留的部分，选中图片让 agent 生成变体，比较结果并继续加工。每个结果能够找到来源素材、对应任务和使用的参数。

### 2.3 网页研究示例

用户添加网页节点并浏览参考网站，把选中的文字、图片或截图保存为项目素材，再交给 agent 分析或作为创作参考。保存网页网址、截取内容与 agent 操作网页是不同动作。

### 2.4 文件与工作成果示例

加入一个含参考图的本地目录，系统自动建立画布并展示文件节点。用户生成四张图片，先保存在画布的工作数据中，选中满意的两张保存到当前目录。写入成功后，原节点获得本地文件标识，不产生重复展示。切换“本地图片”筛选时只显示符合条件的内容；清除筛选后，其余工作内容仍在原位。

### 2.5 工作台布局与画布层级

设计风格继续沿用 [design.md](design.md) 的 Factory + ASCII。用户提供的[默认布局截图](design/workspace-default-layout.png)是工作台基础空间布局依据，具体区域业务用途和精确尺寸后续细化。

全能画布位于最底层，平铺整个应用内容窗口；所有工作台面板在其上方。上层页面可横纵分割、嵌套和调整尺寸。业务窗口可停靠在分割区、自由浮动、收为可拖动悬浮图标、展开和置顶。置顶暂按应用内层级解释，是否跨应用置顶待确认。

可保存、命名、切换窗口配置并恢复默认，默认空间关系对应截图。布局变化不改变作品坐标，不丢失面板输入或取消任务；底层画布不随面板重排为中央一块内容区域。面板上的操作不误触画布，露出区域仍可操作。

开发顺序仍为画布先行：首版预留层级、坐标、输入与保存边界，完整窗口系统放在后续 OS 外壳阶段。画布节点是作品内容，工作台窗口是工具界面，两者身份、位置及保存规则分开。

## 3 基本对象与关系

| 对象 | 含义 |
| --- | --- |
| 管理根 | 资产管理器添加和管理本地文件夹的入口，不等于操作系统磁盘根目录 |
| 关联文件夹 | 管理器中登记的本地目录；作为文件入口并自动拥有对应画布 |
| 本地文件 | 位于关联目录或其它明确位置的真实文件，关联状态与路径可核对 |
| 画布工作内容 | 由画布持久保存的粘贴内容、生成结果等，尚未导出为用户目录中的普通文件 |
| 项目 | OS 对相关任务和背景的组织方式；不是打开目录画布的前置条件，与目录的映射待设计 |
| 画布 | 文件夹对应的工作空间，包含文件展示、工作内容、布局与工具；子文件夹和额外画布规则待确认 |
| 素材 | 图片、模型、文档等实际内容，具有身份、来源和版本 |
| 节点实例 | 放置在画布上的一个对象，保存位置、尺寸、配置及对素材的引用 |
| 节点定义 | 决定一类节点的界面、交互、输入输出和执行行为 |
| 节点扩展包 | 用于安装和发布节点定义及必要资源的版本化包 |
| 任务 | 一次生成、处理或其他执行活动，记录输入、状态和结果 |
| 画框或区域 | 组织画布内容、限定操作范围及支持展示的容器 |

同一素材可以被不同节点和画布引用。需要明确区分移除画布实例、删除素材、替换素材和创建素材新版本。

素材列表、搜索和专用编辑视图继续存在；无限画布不要求所有操作都只能通过拖动卡片完成。

### 3.1 文件夹关联与外部变化

加入文件夹后自动建立或恢复其画布，反复打开不应重复创建同一目录的内容。建议默认关联原位置，不搬动或批量复制原文件；该默认行为和目录去重规则仍待确认。

系统需要发现外部软件新增、修改、重命名或删除文件的变化，刷新对应节点状态，不静默重置用户布局。关联无法确定时提示重新关联，不仅凭同名文件推断为同一资产。目录暂时离线或无权限时保留画布和工作内容。

子文件夹建议以文件夹节点呈现，双击进入对应画布；是否递归平铺以及子文件夹是否全部自动建画布尚未确认。根目录自动建画布不默认等于递归展开全部文件。

### 3.2 本地文件与画布工作内容

“画布工作内容”只是尚未保存为用户目录中的普通文件，不等于未持久保存。自动保存必须覆盖其实际内容或可恢复副本，不能只存临时链接或易失的预览地址。

区分文件关联、内容类型和工作状态：生成结果可以后来关联本地文件；已关联文件仍可能有未写回修改。节点需明确显示已关联、未关联、关联失效及有未写回修改等适用状态，并支持查看路径、定位文件或重新关联。

画布上的位置调整不移动磁盘文件。重命名文件、移动文件、移除画布展示和删除真实文件是不同操作。建议普通删除移除展示，真实文件删除采用明确的回收站动作；刷新目录时如何恢复被移除的展示需定义，避免刷新立即撤销用户意图。

### 3.3 将选中成果保存到本地

提供命令及可配置快捷键，支持将单个或多个工作成果保存到本地文件夹。建议默认目标为当前关联目录，可选择名称、格式与位置。

- 按内容提供有效的输出格式；工具、分组、网页或复杂设计对象不能一律当作图片导出，需明确保存内容、快照或专用格式的行为。
- 成功写入后更新原节点的文件关联，保留位置、连线、参数和来源；目录变化通知不得重复生成节点。
- 同名冲突需明确处理，不静默覆盖；批量保存提供逐项结果，失败项继续作为画布工作内容保留。
- 已关联文件的再次保存区分写回、另存和导出。外部文件已变化时，不无提示覆盖外部修改。
- 文件关联标识仅在写入成功后更新，失败或中断不能显示为已保存。

### 3.4 画布筛选与搜索

筛选改变显示范围，不改变真实文件、工作内容、节点坐标和执行状态。建议维度如下，具体界面与默认组合待设计：

| 维度 | 可选条件示例 |
| --- | --- |
| 文件关联 | 已关联本地文件、仅画布内容、关联失效 |
| 内容类型 | 图片、视频、音频、3D、文本、文档、网页、文件夹 |
| 工作对象 | 工具、便签、图形、连线 |
| 工作状态 | 运行中、完成、失败、有未写回修改 |
| 来源与标签 | 导入、粘贴、AI 生成、自定义标签 |

支持组合筛选与名称、文件名、标签搜索。建议同维度多选为“或”、不同维度为“且”，并显示当前条件、匹配数量及清除入口。全文与视觉语义搜索作为后续扩展。

建议保存“全部内容”“本地文件”“工作过程”“未保存到目录的成果”等常用视图；这里的“未保存到目录”不能显示成工作数据尚未自动保存。

筛选隐藏节点不删除文件、不取消任务，清除后恢复原布局。“查看全部匹配内容”只调整视口，不自动重排。连线跟随端点的显示状态处理；分组、画框及其子对象的筛选关系需一致。隐藏节点不应留在可误操作的当前选区中，批量命令清晰限定作用对象。

## 4 无限画布与在线白板

### 4.1 画布基础

- 平移、缩放、适配选区、查看全部内容和返回上次视角。
- 框选、多选、拖动、复制粘贴、重复创建和快捷键操作。
- 撤销重做、对齐、吸附、等距分布、组合、锁定、隐藏及层级调整。
- 画框、分区、对象命名、搜索定位和大画布导航。
- 自动保存，关闭后重新打开可恢复内容及合理的视图状态。
- 导入文件、从剪贴板粘贴内容、跨画布复用内容。

无限画布是空间浏览体验，不等于无资源上限。需要定义内容规模、加载行为和性能验收场景。

### 4.2 白板能力范围

| 类别 | 目标能力 |
| --- | --- |
| 文字与便签 | 富文本、便签、列表、颜色与样式 |
| 图形与绘制 | 常用形状、自由画笔、线条、箭头 |
| 关系连线 | 吸附对象、标签、折线或曲线，跟随对象移动 |
| 结构化表达 | 流程图、思维导图和表格；具体编辑深度待确认 |
| 内容组织 | 分组、画框、区域和模板 |
| 展示与导出 | 按画框浏览或演示、局部与整图导出、图片与 PDF 输出 |

多人实时编辑、评论协作和组织权限不作为个人优先阶段的默认交付项。后续是否增加，独立确认。

### 4.3 透明桌面覆盖模式

用户可将画布背景设为透明，全屏覆盖所在显示器的桌面，透过画布看到桌面和其它软件窗口。节点仍保持自身内容与样式。使用同一个全局快捷键，在画布工作和操作其它软件之间切换。

| 状态 | 视觉表现 | 操作行为 |
| --- | --- | --- |
| 画布展开 | 背景透明，节点覆盖在桌面之上，可编辑和交互 | 接收画布操作；展开时空白区域是否穿透作为独立交互选项待定 |
| 节点退场 | 当前视口内的节点向屏幕外退出，连线及工具面板协调退场 | 过渡结束后让出输入，不保留不可见的点击阻挡层 |
| 桌面可操作 | 节点及画布工具界面不遮挡桌面 | 可正常点击、输入、滚动和拖动其它软件；画布不抢回焦点 |
| 节点恢复 | 再次触发快捷键，节点从屏幕外飞入原显示位置 | 恢复画布操作及原视口、选区和节点状态 |

“全屏覆盖”是桌面叠加展示目标，不要求使用独占全屏。透明背景和鼠标穿透分别控制：看得到下面的软件，不代表鼠标事件已能传递给它。

退场属于临时展示动画，不修改节点真实坐标、不改变素材关系、不加入作品的撤销历史，也不通过将对象实际移动到远处来实现。原先在视口外的对象无需飞入；连线跟随所属内容退场，避免留下悬空线条。

建议动画按对象相对屏幕中心的位置向外展开，并沿相应路径返回；具体方向、时长和缓动待交互设计确认。支持减少或关闭动画。连续快速按键需要正确取消或反转过渡，不出现重复实例、错位或输入状态卡住。

隐藏期间不卸载节点，不默认取消正在执行的任务；网页、视频和 3D 的显示与播放资源按明确策略暂停或降载，恢复时保留合理状态。未保存文字及节点开发草稿不能因切换丢失，任务完成不能强制唤回画布。

快捷键必须在其它普通应用获得焦点时仍能唤回画布，允许配置并提示注册冲突；提供独立恢复入口，避免快捷键失效后无法展开。具体组合键尚未确定。

这是新增的桌面承载需求，不视为 OpenPencil 现成功能。Windows 下的透明合成、层级、焦点、全局快捷键和输入穿透需在早期原型中联合验证，尤其要检查网页节点等独立承载内容是否同步退场。多显示器、DPI 缩放、显示器拔插及系统特殊窗口的行为需明确支持范围并实测。

## 5 设计编辑能力

Figma 作为精确设计、图层结构和复用能力的参考。以下为候选需求范围，具体深度与首期范围待确认。

| 类别 | 候选能力 |
| --- | --- |
| 图层与容器 | 图层树、画框嵌套、层级、裁切 |
| 精确布局 | 坐标、尺寸、间距、对齐、约束、自动布局 |
| 视觉样式 | 填充、描边、圆角、透明度、阴影和文字样式 |
| 矢量编辑 | 钢笔、路径、锚点、布尔运算 |
| 设计复用 | 组件、实例、变体、共享样式和变量 |
| 交互原型 | 页面跳转、交互状态、演示与动画 |
| 设计交付 | 尺寸查看、素材导出，后续按需增加代码关联 |

设计组件负责复用结构和样式；工具节点负责扩展交互或执行能力。两者可以结合，但不能混为同一个版本和运行概念。

不以完整复制 Figma 或兼容其插件生态作为当前承诺。现有 OS 的视觉规范如何适配画布，在后续交互与视觉设计阶段确定。

## 6 多媒体素材与节点类型

### 6.1 内置内容范围

| 内容 | 基本操作与目标 |
| --- | --- |
| 文本 | 阅读、编辑、格式调整和来源记录 |
| 图片 | 缩略图、原图预览、裁剪、标注、变体与对比 |
| 视频与音频 | 播放、基本信息、处理入口；剪辑深度待确认 |
| 3D | 交互预览、材质查看，逐步接入模型及材质相关能力 |
| 文档 | 文件卡片、支持格式的预览、来源与导出 |
| 网页 | 节点内浏览、导航、专注模式及内容采集 |

素材格式支持清单需要单独定义。不能把“支持 3D”解释为支持所有模型格式，也不能把预览等同于完整编辑器。

### 6.2 三类可扩展节点

| 类型 | 例子 | 测试方式 |
| --- | --- | --- |
| 内容节点 | 图片卡片、便签、模型、文档 | 编辑、样式、缩放、保存恢复 |
| 工具节点 | 抠图、图片生成、格式转换 | 输入素材、参数设置、运行、输出与异常处理 |
| 交互节点 | 图片对比器、调色器、专用编辑器 | 点击、拖动、绘制、预览及状态保持 |

三类是能力分类，不是互斥限制。一个图片裁剪节点可以同时展示内容、提供交互并输出处理结果。

### 6.3 连线与执行

- 白板关系连线表达说明和关联，不触发处理。
- 执行连线传递数据或建立任务依赖，具有明确的输入输出类型。
- 普通素材节点按需显示端口和参数，避免所有对象始终呈现复杂的工作流界面。
- 明确哪些动作启动任务，以及任务可能调用的外部服务。
- 支持输入校验、运行状态、取消、失败说明和重试。
- 多步执行、分支、循环、局部重跑和缓存策略需要后续细化，不能由“支持连线”默认推导为全部实现。

## 7 内置 agent 开发测试与发布节点

### 7.1 开发入口

用户用自然语言提出节点需求，也可选择画布中的草图、素材、示例节点或网页内容作为参考。agent 使用 OS 提供的开发工具生成代码和资源，并创建画布内的开发实例。

用户无需手动建立外部工程、复制代码或反复安装，即可完成通常的开发与试用。代码和日志仍应可查看，支持需要时深入调试。

### 7.2 开发预览

- 在当前画布中渲染真实节点，而非单独展示代码或截图。
- 修改后快速更新预览；耗时构建、安装和处理显示真实进度。
- 尽量保留测试素材、参数和交互状态；无法保留时说明原因。
- 节点内显示错误，agent 可读取日志并继续修复。
- 开发运行与画布主体隔离，节点失败不应使整个画布失效。
- 开发草稿与正式版本分开，避免试改影响其他画布中的稳定实例。

### 7.3 开发接口与验证

提供统一的节点模板、界面组件、素材访问、任务执行、结果保存和权限接口。开发者和 agent 使用同一套约定。

用户负责体验与效果反馈；agent 负责相应工程检查，包括输入输出、错误处理、保存恢复、实际交互和兼容性。编译通过不能替代功能验收。

建议先支持将已有节点组合成可复用工具；组合无法满足需求时再开发新代码。组合节点的参数暴露和内部执行规则需进一步设计。

### 7.4 安装与发布

节点扩展应具备名称、图标、说明、版本、输入输出、配置、依赖、兼容要求和权限声明。

支持安装、启用、停用、更新、卸载和回退。已有实例记录所用版本；更新涉及数据变化时提供兼容或迁移方案。

建议发布范围分为“我的节点库”“项目共享”“公开发布”，默认优先实现本机个人节点库。公开市场不作为首期必需能力，发布触发方式及是否自动发布仍待确认。

节点缺失、停用或版本不兼容时，应保留实例内容、参数及素材引用，并提供恢复入口。卸载扩展不能静默删除作品数据。

## 8 agent 操作画布

- 可选中对象、画框或区域作为任务范围，整张画布操作需有明确范围表达。
- 能创建、整理、连接和修改对象，并调用可用的工具节点。
- 任务固定所使用的输入与版本，结果保留来源和参数记录。
- 执行期间用户可以继续编辑；结果不能无提示覆盖用户的新修改。
- 大范围改动建议提供变更预览、整体应用与整体撤销。
- 进度、取消、失败和重试与 OS 的任务管理相衔接。

画布中的网页、文档和节点输出是任务数据，不能自动视为用户授权或系统指令。

## 9 网页节点

### 9.1 浏览体验

- 输入网址后在画布节点中浏览，支持点击、滚动和输入。
- 地址栏、前进、后退、刷新及外部浏览器打开。
- 可以放大到专注浏览，再返回原画布位置。
- 明确网页交互与画布拖动、缩放的切换方式，避免滚轮和快捷键冲突。
- 保存网址、尺寸和视角；网页内部状态恢复取决于网站和承载方式。
- 页面不可用时显示原因和可采取的操作。

### 9.2 浏览器承载与权限

目标是浏览器式网页节点，而不只是链接卡片。普通网页嵌入无法保证兼容所有网站；桌面浏览器承载方式需要技术验证后确定。

登录、验证码、下载、多媒体与弹窗需有明确处理规则并实际验证，不承诺所有网站均可正常运行。

登录状态按需要共享或隔离；敏感凭据不进入画布文件与导出包。下载文件不会无提示自动成为项目素材。

网页浏览和 agent 浏览器操作是两项能力。agent 读取当前页面、提取素材和执行操作，需要独立工具接口与用户任务范围；网页内容不能获得本机任意文件或命令权限。

用户自行开发的网页工具也可承载为交互节点，但与第三方网页采用不同的信任和权限规则。

## 10 保存恢复与项目携带

| 层次 | 要求 |
| --- | --- |
| 画布历史 | 编辑、布局和连接可撤销重做，支持保存与恢复 |
| 素材版本 | 原件、修改、变体和任务结果之间有可追溯关系 |
| 节点版本 | 草稿、正式版本、升级和回退各自清晰 |

撤销画布修改不等于撤销已经发生的模型调用、下载或外部操作。相关任务记录应继续可查。

支持项目导出、导入与恢复，包含画布结构、所需素材和节点版本清单。需要外部服务、特殊依赖或凭据的能力，在恢复时明确提示；项目包不包含敏感凭据。

本地内容应在网络不可用时仍可浏览和编辑；依赖网络的功能显示不可用状态并保留用户输入。

独立阶段同时保存文件夹关联、画布结构、工作内容本体及必要的视图状态，提供重新打开、导入导出和可验证的恢复能力。画布保存格式应具备版本信息，素材引用、节点身份与节点版本从基础阶段建立。

工作数据存放于目录旁还是应用管理区，留待技术设计；不能用临时缓存代替持久存储。备份和导出需区分外部关联文件与应用管理内容，明确是否携带原文件；不能把仅含路径的画布记录声称为完整文件备份。

嵌入 OS 后，通过保存接口对接 OS 的存储与备份机制。独立阶段创建的作品应可迁移或直接打开，保持布局、素材引用和节点配置；需要格式迁移时提供明确的版本转换路径。现有 OS 项目数据、模型连接和成果迁移仍需独立验证。

## 11 性能与可靠性

- 按视野加载内容，使用缩略图或低成本预览，避免全量加载原件。
- 不可见的网页、视频和 3D 按策略暂停或降低资源占用；恢复行为明确。
- 节点运行具备必要的资源约束和错误隔离，本机执行不意味着无限权限。
- 保存状态可辨识，失败时保留可恢复内容。
- 键盘焦点、快捷键、文本输入和画布操作之间有一致规则。
- 建立混合内容基准：白板对象、图片、网页、3D 和运行任务共存时验证加载、交互、内存及恢复。

性能验收需要明确参考电脑、素材规模、活跃预览数和响应指标。目前尚未确定数值，不将“流畅”当作可直接验收的标准。

## 12 OS 与 AssetCutter 的融合边界

### 12.1 独立画布与运行入口

画布核心与承载它的应用分开。独立入口负责打开画布、提供本地存储及必要的运行能力；重构后的 OS 通过同一组接口承载画布。独立入口用于持续使用和验收，不只是临时效果演示。

- 画布核心负责对象、布局、选区、缩放、连线、编辑、历史记录及节点交互。
- 本地资产适配层负责目录登记、文件变化、关联身份、落盘写入和缩略图；与画布编辑层通过接口协作。
- 节点系统负责节点定义、加载、渲染、运行边界和版本识别。
- 项目、素材访问、持久化、任务执行、agent 和权限通过明确接口连接。
- 核心模块不直接依赖当前 OS 的页面组件、全局界面状态或数据库表结构。
- 不为独立入口重复建设完整账号系统、聊天系统和项目管理系统。

建议先在 OS 仓库内建立独立模块与运行入口，具体目录、构建方式及是否拆仓库留待技术设计确定。独立模块不等于必须创建新 GitHub 仓库。

### 12.2 后续接入职责

| 部分 | 目标职责 |
| --- | --- |
| OS | 项目、agent 执行、任务记录、上下文、资产记录、保存与恢复 |
| 新画布 | 内容展示、空间组织、白板编辑、设计交互与节点操作 |
| 本地资产管理 | 文件夹入口、文件变化同步、文件节点关联、工作成果落盘与筛选数据 |
| AssetCutter 可复用模块 | 素材处理、生成、预览、模型供应商适配等 |
| 节点扩展系统 | 开发、安装、运行、测试、版本和发布 |

上表描述最终融合职责。基础阶段以本地实现满足画布使用与保存，后续逐步替换或连接承载接口；不以 OS 整体重构完成作为前置条件。agent 开发闭环阶段只接入所需执行能力，AssetCutter 再按独立能力接入。

迁移按能力逐项进行。GitHub 来源需要固定到明确的分支或提交；本地已有改动与远程版本不能混同。正式迁移前，核对模块依赖、许可、数据格式和测试范围。

账号商业化、支付积分、管理后台和旧工作台界面不因存在于 AssetCutter 就自动进入个人 OS。需要的部分另行确认。

现有 OS 的项目与任务结构、现有 AssetCutter 的工作流和素材结构，都不能未经验证就直接作为新画布的数据模型。

### 12.3 开源能力复用范围

画布独立开发不意味着从零编写全部能力。先验证现成实现，优先复用公开接口；确需修改内部行为时，再维护小范围源码移植或 fork。候选项目不能反过来缩减已确认的产品目标。

OpenPencil 已确定为主底座。优先保留其现有编辑交互、图层、布局、组件、历史和保存体系，再扩展白板、自定义节点与 OS 接口。其他项目作为局部能力来源，不并行建设另一套主编辑器。资料和源码依据见[开源项目调研](全能画布开源项目调研.md)。

OpenPencil 是编辑底座，产品入口仍是本地资产管理器。须补充目录关联、工作内容与普通文件的双重存储关系、文件标识、落盘与筛选；不能直接将其设计文档管理模式当作最终资产管理架构。

| 需求领域 | 优先验证来源 | 拟复用部分 | 必须补齐或验证 |
| --- | --- | --- | --- |
| 主编辑器与精确设计 | OpenPencil | 优先保留完整编辑器、场景对象、布局、组件、历史、保存与自动化接口 | Windows 本机运行基线、白板及自定义节点扩展、OS 接入 |
| 白板补充 | 按缺口考察 Drawnix／Plait 等 | 可独立复用的图形、画笔或思维导图能力 | 必须融入 OpenPencil 的编辑与保存体系，不引入第二主画布 |
| 自定义节点与创作 | AssetCutter 已引入的 basketikun/infinite-canvas 快照 | 节点定义、注册、插件加载、宿主接口与 agent 操作协议 | 执行隔离、版本锁定、权限和作品恢复 |
| 节点与执行连线参考 | React Flow | 按需参考节点、端口与连线交互 | 不默认引入完整框架；避免与主编辑器争夺视口、选区及历史 |
| 其他能力备选 | Excalidraw、LeaferJS、Penpot、BlockSuite、DGM.js | 按白板、图形、设计或文档能力选择模块 | 模块依赖、维护状态、许可与集成成本 |

已有 infinite-canvas 快照记录的上游提交为 `e856c878e0a34651bb828e28f0af20d71016a7d4`。正式移植前核对 AssetCutter 的后续修改，不将本地版本视为未经改动的上游源码。已检查的加载器直接在主页面执行插件，应重构执行边界后再用于任意生成节点。

### 12.4 OpenPencil 底座与统一体验

底座选择以产品完整性、实际交互质量和后续改造成本为重点，不只依据框架扩展接口。用户反馈 Plait 相关体验简陋且存在使用问题，并确定采用 OpenPencil。该反馈用于记录选型依据，不等同于已完成对 Plait 的缺陷复现，也不表示 OpenPencil 已通过运行验收。

实施时先固定 OpenPencil 来源提交，运行原版并记录功能基线，再验证文字、图形、图片、真实交互节点、嵌套画框、编辑撤销、保存恢复及 agent 指令。网页承载另外验证，并检查坐标、遮挡和焦点协调。验证用于明确扩展方案和缺口，不再以两条主底座路线并行比较作为默认工作。

不为迁就当前 OS 的 React 页面而先重写 OpenPencil 的 Vue 编辑器。先独立运行，后续通过明确接口接入 OS；具体嵌入方式和桌面承载仍待技术验证。节点协议可以复用，但已有 React 节点 UI 需验证适配，不能假设可直接插入。

无论采用多少底层组件，用户必须获得同一套对象身份、坐标、选区、快捷键、编辑历史和保存体验。不得以互不连通的多个编辑器或多个画布替代这一要求。复用上游内部模型时，通过明确映射保留素材来源、节点版本和作品兼容性。

保留原版回归场景，新增能力不能破坏已有编辑与保存行为。记录实际运行结果、功能缺口、改造范围和维护成本；仓库说明、演示截图或编译成功不能代替验收。若发现影响核心需求的阻碍，应说明证据和替代方案，再讨论调整，不自行更换已确定底座。

### 12.5 复用来源与维护

- 直接依赖固定版本；移植代码记录仓库、提交、原文件、许可证及修改范围。
- 保留所需版权与许可声明，分别核对代码、子包、字体、图标和其他资源。
- MIT、MPL、GPL 与自定义许可分别评估，不能因仓库公开就视为可任意复制。tldraw SDK 当前不纳入默认可直接复制的底座，使用时需满足其授权条件。
- 上游升级先验证作品格式、节点接口与行为兼容；保留必要的迁移和回退路径。
- 将我们的改动集中在适配与扩展边界，减少大范围改写上游带来的维护负担。

上述规则用于管理实际引入的模块，不要求为所有候选安装依赖或启动服务。

## 13 分阶段交付建议

画布先独立开发、后续嵌入 OS 的顺序已确认。以下是具体阶段划分建议，不是已批准的开发排期。

| 阶段 | 目标 | 代表性成果 |
| --- | --- | --- |
| OpenPencil 基线与扩展验证 | 固定版本、跑通原版，确定改造边界 | 本机运行与保存恢复基线、自定义节点及网页承载验证、缺口与复用清单 |
| 独立画布基础 | 基于选定底座，形成可用的画布式资产管理入口 | 加入目录自动建画布、文件关联标识、工作内容持久化、选中成果落盘、基础筛选，以及画布编辑、撤销、保存恢复与导入导出 |
| 节点扩展基础 | 移植可用节点能力，补齐统一接口与隔离 | 图片与交互工具节点的加载、输入输出、运行、错误处理和状态恢复 |
| agent 开发闭环 | 接入必要的 OS 执行能力 | 对话开发节点、原位试用、迭代、验证、发布到节点库及跨画布复用 |
| 专业创作与 OS 融合 | 扩充能力，并接入重构后的工作台 | 设计编辑、多媒体、网页与 AssetCutter 工具逐步可用，项目、素材库、对话与任务接入 |
| 扩展生态 | 完善开发工具、模板、组合与分发 | 可维护的个人节点库，后续按需共享 |

稳定对象身份、素材引用、保存格式版本、节点版本和扩展边界从基础阶段建立。先让画布可用，再完成 agent 开发闭环；不将整个能力生态作为首次可用的前提。

网页承载、精确设计布局、运行隔离及透明桌面覆盖模式需要早期验证，但不要求在基础阶段完成其全部产品功能。桌面覆盖验证必须包含全局快捷键、退场恢复、输入穿透与焦点，不能只展示透明截图。独立画布的交互和数据基础用于最终产品，避免接入 OS 时重新实现整套画布。

实时多人协作、公共市场、移动端、云端执行和完整设计工具兼容不作为首期默认范围。网页节点属于目标范围，但具体上线阶段取决于本机承载验证。

## 14 代表性验收场景

| 场景 | 验收结果 |
| --- | --- |
| 窗口布局 | 分割/调整尺寸、停靠/浮动/图标化/置顶切换后状态保留；保存重开或切换配置可恢复，重置回截图布局 |
| 全窗口底层画布 | 面板变动不缩小画布为中央区域、不改作品坐标；输入不误穿透，画布平移缩放不带动窗口 |
| 独立运行 | 不启动完整 OS 工作台，可新建、打开、编辑、保存和重新打开画布 |
| 目录入口 | 加入本地目录自动建画布，重开不重复创建；原文件位置及布局行为符合约定 |
| 工作内容恢复 | 未导出为普通文件的生成或粘贴内容，关闭重开后仍完整可用 |
| 成果落盘 | 选中保存成功后原节点获得本地标识，无重复节点；冲突、部分失败和中断有准确结果 |
| 外部文件变化 | 外部新增或修改文件可反映到画布；缺失或离线时保留工作数据，未写回修改不被静默覆盖 |
| 筛选与恢复 | 组合条件准确，清除后恢复原布局，隐藏内容不被误删、任务不中断 |
| 桌面覆盖切换 | 透明背景下正常编辑；按键后节点退出、其它软件可正常操作，再按键原位恢复 |
| 覆盖模式状态保持 | 连续切换无错位或输入阻挡，未保存输入保留，真实坐标与撤销历史不变，任务不因隐藏取消 |
| 承载切换 | 后续嵌入 OS 时复用画布核心，独立阶段作品经明确兼容或迁移流程保留内容、布局与引用 |
| 复用集成一致性 | 来自不同模块的图形、素材和交互节点共用选区、坐标、编辑历史与保存机制 |
| 依赖版本升级 | 固定样例作品在候选升级后可正常打开，或经明确迁移后保留内容；失败时可回退 |
| 混合内容画布 | 可摆放和编辑不同对象，选择、缩放和专注编辑不互相干扰 |
| 对话开发节点 | agent 创建真实可交互实例，用户直接试用并通过对话迭代 |
| 开发失败 | 节点显示错误且可修复，其他画布内容仍可操作，测试素材保留 |
| 发布复用 | 正式节点能在另一画布添加，配置和输入输出符合定义 |
| 版本维护 | 新开发草稿不影响旧实例，更新与回退有明确结果 |
| 保存恢复 | 重启后布局、素材引用、节点配置及版本可恢复 |
| 执行与编辑并行 | 任务运行期间能编辑，返回结果不覆盖用户新修改 |
| 网页浏览 | 在明确的网站测试清单内完成浏览、输入、导航和返回画布 |
| 导出与导入 | 新环境可恢复项目；缺失依赖有说明，凭据不被导出 |
| 失效扩展 | 停用或缺失扩展时保留作品数据，可恢复或替换 |

真实素材、实际交互和保存恢复是验收的一部分。静态演示、截图、编译成功和模拟服务不能独立代表场景通过。

## 15 尚需确认的产品问题

| 问题 | 当前状态 |
| --- | --- |
| 窗口细节 | 默认布局以截图为准；区域用途、精确比例、初始浮窗数量、跨应用置顶与布局作用域待细化 |
| 目录组织 | 根目录加入自动建画布已确认；默认关联而不搬动、子目录画布、递归展示及重复目录处理待确认 |
| 工作数据存储 | 应用管理区或目录旁文件、关联身份与迁移方式待技术设计 |
| 文件操作细节 | 快捷键、格式、默认落盘位置、覆盖与另存、删除及重新扫描行为待细化 |
| 筛选规则 | 筛选能力已确认；默认视图、组合语义、分组与连线处理待交互设计 |
| 第一种做深的内容 | 图片、3D 或文档与信息整理，尚未选择；图片对比仅为建议验证场景 |
| 白板与工作流的默认体验 | 建议白板优先、执行能力按需展开，待确认 |
| Figma 能力深度 | 精确布局、矢量、组件、原型各自的优先级待确认 |
| 节点发布规则 | 个人节点库为建议默认；手动发布、agent 按指令发布及共享范围待细化 |
| 网页承载方式 | 需要技术验证，尚未确定桌面框架或浏览器方案 |
| 桌面覆盖细节 | 快捷键、动画参数、展开时空白区域穿透、播放策略及多显示器范围待确认；核心切换体验已确定 |
| 本地模型范围 | 本机运行已确认，是否要求本地推理及哪些离线能力待确认 |
| 执行流程复杂度 | 顺序、分支、循环、局部重跑与缓存的交付范围待确认 |
| 兼容和导入格式 | 素材格式、第三方画板与设计文件格式清单待确认 |
| 大画布验收指标 | 参考设备、对象规模、媒体尺寸和性能数值待制定 |
| AssetCutter 迁移基线 | 正式选取 GitHub 分支和提交，并列出首批可复用模块 |
| 独立工程组织 | 建议 OS 仓库内独立模块；实际目录、构建与启动方式待技术设计 |
| OS 接入接口 | 明确项目、素材、保存、任务、agent 与权限接口及独立运行实现 |
| OpenPencil 实施基线 | 底座已确定；来源提交、独立运行方式、节点扩展与 OS 嵌入接口待验证 |
