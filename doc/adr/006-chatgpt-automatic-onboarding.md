# ADR-006：登录后直接使用 ChatGPT

2026-10-06。用户明确希望像Codex一样直接对话，不承担模型、调用次数、超时和重复确认的设置成本。该偏好覆盖此前“必须填写10次/120秒才能验证”的开发建议。

首次OAuth授权已经包含ChatGPT订阅用量权限。首次连接完成后自动读取实际账户目录，与固定Pi目录取交集，按已固定偏好顺序选择可用默认模型；当前真实账户选中GPT-5.6-Sol。没有兼容模型时保留成功登录、提供重试准备，不能自动改用付费API。

默认automatic模式只限制每个任务20次请求、300秒；不设置连接终身10次的门槛。实际订阅额度仍由供应商判定，20不是账户剩余额度。每次实际请求仍经过宿主预占、模型/连接绑定、取消和工具范围检查；没有自动重试供应商请求。原API模式的累计次数及美元限制不改变。

高级设置默认折叠，可自定义模型、连接累计上限和超时，也可恢复自动模式。原有自定义配置在重新授权后保留。累计用量历史不被重置。首次显示一次“正在使用你的ChatGPT额度”的告知，关闭状态存于受保护凭据，重新登录不再重复；这是告知而非启用前的参数表单。[官方界面指引](https://developers.openai.com/siwc/ui-ux-guidelines)

真实探针还发现主服务持有存储锁时，原生会话写入立即423失败。仅执行进程的原生写入最多等待1秒；只等待尚未进入写入回调的锁获取，不重复回调，不删除活进程的锁，不等待未知/损坏锁。宿主仍默认立即报告冲突。两个实际进程测试证明提示只落盘一次及限时冲突后锁不变。

证据：67项工程测试/类型检查/构建/Pi离线探针、实际Chrome自动登录流程、真实账户自动配置界面，以及真实GPT-5.6-Sol两请求保存文件往返。后续原生继续、真实取消/超时、远程手机、独立备份及腾讯实验仍按原门槛完成。
