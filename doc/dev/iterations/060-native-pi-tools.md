# 060 恢复Pi原生能力

日期：2026-10-11。用户明确要求“不要限制Pi自带能力，基础带什么就用什么”，并授权代码修复和文档更新。

## 改动

核对固定SDK1.0.3源码后，新Pi任务策略8提供read/write/edit/ls/find/grep/bash/powershell八项原生工具，叠加工作台工具。研究任务保留原生能力，不再替换为三个资料工具。业务工具继续通过宿主校验；原生工具由SDK直接执行。旧任务重试继续原工具快照；策略升级不会接续不兼容旧会话。需要新能力时提交新目标。

使用SDK DefaultResourceLoader保留原生系统提示，工作台规则追加；恢复技能、提示模板和项目上下文发现。可执行扩展自动发现仍关闭，不把第三方扩展当作Pi内建工具，也不声称Ponytail已安装。默认模型重试/压缩/预热继续关闭以兼容现有预算结算。

worker保留独立项目cwd，PATH优先宿主Node版本并提供Windows查找shell所需环境字段。原生工具开始/结束/失败记录为native.tool事件，只记录名称、调用ID和状态，不复制命令或输出到事件表；近期记录显示在任务页，详细原生工具结果留在原生会话。

## 证据与边界

新增测试创建真实Pi会话，确认原生工具与业务工具共存、原生提示未替换、项目技能发现、可执行扩展未加载；真实临时文件写入/编辑/读取/目录检查及编辑失败原件保持；真实PowerShell执行及AbortSignal取消。订阅受控协议测试扩展为原生write和业务write_asset连续往返，零真实模型请求。初次测试使用旧版edit参数，核对本地类型后改为edits数组，不改变SDK工具实现。

原生能力使用宿主用户权限，工作目录不是OS隔离。GitHub域名许可只适用于capture_source；资产容量准入只覆盖宿主管理的写入，不能限制任意shell。普通文件不会自动入资产库、自动版本回滚或纳入联合备份。原生工具没有业务Operation的事务去重保障；取消/中断后的外部副作用须核对。重要删除、系统配置和发布依据用户授权执行。

真实Ponytail安装、启用和同模型对比未在本轮执行。验证结果与实际应用见后续记录。

## 最终验证与应用

171项全套测试通过（0失败，约245秒），类型检查、生产构建、SDK离线探针通过。八项原生工具均有真实本机执行检查，grep/find/Bash额外用临时文件与固定命令核对。受控订阅协议实际完成原生write与业务write_asset往返；零真实供应商请求。见[最终报告](../../../output/dev-evidence/native-pi-060/report.json)和[测试日志](../../../output/dev-evidence/native-pi-060/tests.log)。

应用前无在途任务。先正常停止服务；首次紧接着启动时旧守护尚在处理停止请求，入口返回未就绪。未强杀或清理锁，核对服务与旧守护均已停止后，再次原入口启动成功。当前服务PID50404、实例ad18dc9d-c1f4-498d-a42f-8896b8e52c03；守护ready、restartCount0，HTTP健康与页面200。以后仍须用运行记录与健康接口核对，不能盲用历史PID。

重启前后20项目、56资产、16草稿、6记忆、32任务、33执行记录和2摘要的完整实体摘要一致，业务数据保持。见[应用前](../../../output/dev-evidence/native-pi-060/before.json)、[应用后](../../../output/dev-evidence/native-pi-060/after.json)。未创建生产模型测试任务，没有安装Ponytail或更改模型登录。用户刷新页面后提交新目标即可获得原生工具；旧任务的“新建尝试”继续原权限。
