# 迭代037：会话交接的实际进程崩溃恢复

2026-10-07。继续用户“没有现成资源，准备部署方案”的要求，补齐036留下的实际杀进程证据；不购买资源，不迁移真实账户。完整M0/M1范围保持。

## 实际验证

[独立探针](../../../scripts/probe-chatgpt-transfer-crash.ts)在私有测试目录内创建两个独立Node服务，共创建5个自有子进程。测试父进程保留ChildProcess句柄，实际核对健康接口的PID/实例后操作；只终止自己创建的句柄，不按保存的PID操作其他服务。

[子进程夹具](../../../tests/helpers/chatgpt-transfer-process.ts)使用合成签名身份和受控提供商响应，未经允许的外部/推理请求直接拒绝。通过同步检查点通知父进程后阻塞，父进程用SIGKILL实际终止服务，在同一私有数据目录启动新的Node进程恢复。

| 故障位置 | 磁盘状态与恢复结果 |
| --- | --- |
| 来源冻结落盘、HTTP返回前 | frozen与加密包保留；新进程拒绝读取/刷新，重试返回同一包 |
| 目标凭据保存、active提交前 | installing与凭据已在磁盘；来源和目标均拒绝刷新，新目标进程重试提交并返回同一签收 |
| 来源凭据/包删除、retired提交前 | retiring保留且来源凭据已删除；新来源进程重试完成退役，持续拒绝使用 |

最终目标独自完成一次合成刷新，来源刷新计数为零，无API回退或远端撤销。三个故障点均没有返回成功HTTP响应。5个进程全部取得实际退出结果，3次SIGKILL、2次正常退出；[独立运行报告](../../../output/dev-evidence/chatgpt-transfer-crash.json)保留具体检查点和终态。

[回归测试](../../../tests/chatgpt-transfer-crash.test.ts)将上述整条流程纳入完整工程检查，最终结果以[收尾审计](../../../output/dev-evidence/chatgpt-transfer-crash-final-audit.json)为准。036的113项报告单独保存在历史目录，不覆盖原验证含义。
