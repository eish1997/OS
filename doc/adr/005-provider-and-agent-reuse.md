# ADR-005：模型连接与本地Agent接入复用

2026-10-06。状态：候选核查与建议，未安装新网关或改变M0/M1门槛。用户提出统一连接模型供应商、统一连接本地Agent，减少重复开发。

## 区分两种接入

模型接入统一请求、流式响应、工具格式和用量，不执行项目文件任务；Agent接入统一会话、执行事件、权限请求和取消。把CLI账户转换成模型API并不等于操控该CLI Agent的完整任务/文件/会话。

| 组件 | 官方项目说明与适用位置 | 当前决策 |
| --- | --- | --- |
| [Pi pi-ai](https://github.com/earendil-works/pi/blob/main/packages/ai/README.md) | 多供应商统一模型接口、工具/流式/用量；当前已固定采用1.0.3，不能把main能力当安装版本能力 | 继续复用，不逐家重写模型SDK；现有宿主授权/预算适配不等于另造统一模型API |
| [LiteLLM](https://github.com/BerriAI/litellm) | 统一多供应商API；网关提供虚拟密钥、费用管理、路由/负载均衡和管理界面 | 多账户/API与独立网关有明确需要时优先评估；当前不增加运行服务，也不能假定API网关自动授权订阅 |
| [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) | 将多种CLI账户渠道包装成兼容模型API，含OAuth路径 | 作为订阅渠道候选；采用前固定版本、核对供应商许可/路由/日志/工具兼容，关闭隐藏重试、跨账户及付费后备；不是完整本地Agent统一执行器 |
| [ACP](https://agentclientprotocol.com/get-started/introduction) | 标准化客户端与编码Agent通信；本地stdio JSON-RPC，远程支持仍在发展 | 后续多Agent接入优先使用协议SDK/成熟适配器，逐个能力验证；不是任意Agent自动兼容或调度集群 |

建议形态：工作台管理项目、资产、授权和任务状态；Pi继续承担主要Agent运行及模型适配；模型网关是可替换可选后端；本地Agent扩展经统一适配接口接入ACP或自身稳定SDK。既有唯一调度、权限交集、调用预算、工具操作去重与审计仍由宿主权威管理，不随外部组件默认行为放宽。

用户此轮未指定采用某一网关，不克隆运行未知项目、不安装依赖或迁移账户。当前登录失败已确定为服务直连出口被拒，接入网关也需正确网络/账户授权；先修复现有连接，再依据真正缺口采用组件。保存候选不表示已完成M1、多Agent或所有供应商的实际接入。
