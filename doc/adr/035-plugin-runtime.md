# ADR-035：Pi 插件管理与运行边界

日期：2026-10-15。状态：实现中，最终验收尚未完成。

## 决策

保留 Pi 1.0.3，不另建插件格式。独立 `plugin-worker.ts` 使用 `DefaultPackageManager` 安装、更新和卸载；工作台 SQLite 的 plugin_config 是唯一权威，SDK settings 只使用内存投影。

运行入口使用空 packages 的内存 settings，`noExtensions: true` 保持目录扩展自动发现关闭，通过 additionalExtensionPaths 传入校验过的绝对本地文件。Skills 与提示词自动发现保持。探针已验证额外资源、动态工具、非交互命令、resources_discover、模板参数与退出事件。运行入口不接收 npm/Git spec 或目录，避免 SDK 缺包自动安装。

所有托管包共用环境写锁。管理器与调度器共享持久 scheduler 租约；运行期间持读引用，等待写操作阻止新执行启动。文件操作后重新检查所有包与共享依赖目录的内容摘要。manifest 在真正启动执行时固定；重试或接续与原 manifest 不兼容时拒绝静默替换。

有扩展时不向 SDK 提供固定 tools allowlist，因为它会过滤 session_start 动态注册的工具；改为保留原生 excludeTools、明确工具注册来源并在初始/动态注册时阻止同名覆盖。扩展工具由 Pi 执行，工作台业务工具继续原有 RPC。扩展不是沙箱，其直接系统调用不受普通工具许可限制。

托管资源启用时把固定项目上下文放入 appendSystemPrompt，保持 slash 命令和模板的原始用户参数。命令-only 执行成功后记录真实用户请求，触发原生会话持久化，不伪造模型回应。退出事件在成功终态前执行。

## 数据与恢复

安装先登记操作意图，再执行文件变更，最后校验并提交。进程中断或结果未知进入 reconcile_required，阻止新 Pi 执行；不承诺跨 SQLite/文件系统原子回滚。第二实例须等待持久租约释放或过期后才对账，不能仅因构造协调器就判定原实例崩溃。待核对进程仍存活时不允许修复覆盖。

Windows 安装前由独立 PowerShell 守护进程建立带 KILL_ON_JOB_CLOSE 的 Job Object，将管理 worker 纳入其中，之后创建的 npm/Git 后代继承该组。守护进程在 worker 退出时关闭 Job；守护进程自身退出也关闭句柄并回收组内进程。初始化失败不执行安装。此保护只管理进程生命周期，不是文件、网络或权限沙箱。Unix 使用独立进程组。仅依赖 JavaScript disconnect 回调的原方案已被真实宿主强制退出测试证伪；该失败证据保留。

npm 生命周期脚本在未启用前也可能执行；页面在安装动作前要求确认可信来源。环境不继承无关凭据。npm/Git 样例测试通过真实 CLI 和本地 HTTP 来源，不下载未审查第三方代码。

备份只保存配置/操作/运行记录；恢复后所有包标为缺失并禁用，不沿用原目录自动加载，不重放未完成安装。插件目录与缓存单独计入 plugins 容量组；操作前后只清理经路径归属校验的托管 cache。

## 验证结果与边界

安装准备/提交前/提交后及更新/卸载提交前的真实宿主中断、Windows Job后代回收、动态注册来源、真实模型工具往返与浏览器交互均通过。最终全套211项通过，增量应用前后业务摘要一致。逐项证据见071-plugin-acceptance.md；ADR记录决策，不替代测试与实际运行回执。
