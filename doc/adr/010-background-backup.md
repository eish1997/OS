# ADR-010：后台备份保持界面可用

2026-10-06。替代ADR-008中“在主线程和整段存储写入锁下执行文件维护”的部分；独立故障域、自有目录/保留规则和逐次恢复检查保持。

018发现384MiB资产维护使HTTP健康请求等待约3.4秒。仅等待Agent空闲不能保证浏览器可用。019把复制、哈希、恢复检查和保留轮转放入宿主创建的固定backup-worker进程。IPC只接收一个内部BackupJob，不提供HTTP启动入口或任意程序参数；不继承模型、密码、NODE_OPTIONS等环境配置，不调用模型。不声称这是未知代码的OS隔离环境。

宿主先检查无在途/等待任务或未知操作，持有120秒调度租约，每20秒续租；维护期间暂停新执行，允许浏览器读取、编辑和提交排队任务。租约丢失会停止所属子进程；子进程提交和清理旧点前再次核对租约与目录归属。委托备份只核验调用方租约，不续租或释放它，释放权属于宿主。

备份进程以SQLite只读连接执行VACUUM INTO形成一致数据库快照，再复制快照登记的不可变资产版本及稳定原生会话。新Agent执行暂停，已有原生源件不追加；物理回收受同一调度租约排斥，界面删除只是进入保留期。恢复的实体数量与捕获数据库比较，不与用户仍在编辑的实时库比较。快照之后的编辑属于之后的恢复点。

验证成功后原子提交，之后只清理自有、完整、已恢复检查的旧副本。后台进程最长180秒；关服务时停止新调度并等待当前维护，管理脚本最多等待190秒，不强杀无关PID。常规异常清理当次自有暂存；进程强制终止或系统崩溃留下的未知暂存保留，不能宣称已自动回收。旧副本及用户登录不因维护失败而删除。

384MiB、三次恢复检查与2点保留轮转的实际数据请求，以及编辑/任务排队/失租约/关闭/原生会话回归见[迭代019](../dev/iterations/019-background-backup.md)。启动时仍同步检查备份位置和历史有效点；更大混合数据、完整容量、启动耗时、生产物理配额、系统守护及异地恢复保持未验收。
