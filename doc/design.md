# 个人 AI 工作台设计规范

版本：2.3
日期：2026 年 10 月 15 日
设计方向：以 Render 控制台的结构、层级和操作密度为主要参考，保留暖灰纸面与少量语义化 ASCII。
适用范围：电脑与手机共享的个人 AI 工作台，包含项目、资产、内容编辑、执行进度与能力管理。

本规范服务于[主开发文档](主开发文档.md)定义的个人工作台。参考对象是 Render 的产品控制台，不是它的营销首页；学习信息组织、比例和操作规则，不复制品牌、产品功能或账户数据。开发循环依照[开发执行文档](开发执行文档.md)执行。

v2.0 根据用户提供的 Render 控制台截图、Render 官方控制台说明和官方产品截图修订。截图中的几何尺寸仅支持比例观察，不能当作已提取的官方 CSS；下文数值是本项目的实施目标。本文是新设计标准，不代表当前 UI 已实现。自由分割、页面内全局浮窗、配置保存和 Pi 能力保持原要求。

## 1 设计意图

像一个安静、有秩序的个人工作室：成果清晰，操作直接，助手随时可用。深色外壳承载项目与执行；浅色纸面用于文章和需要专注阅读的内容；ASCII 用于编号、路径、进度和关系。

页面首先回答：当前是什么项目、主要成果是什么、下一步能做什么。系统信息按需展开，不能抢占成果空间。

**先建立信息秩序，再调整表面风格。** 判断好坏的依据是用户能否看清内容、识别作用域、完成操作；黑底、细线、小圆角本身不是质量保证。克制不是所有文字都小、所有元素都灰，留白也不是把空容器撑满屏幕。

### 1.1 Render 值得借鉴的部分

| 截图观察 | 产生的作用 | 本项目如何采用 |
| --- | --- | --- |
| 顶栏、左导航、内容区有稳定边界；导航保留完整名称 | 即使内容很多，也容易定位 | 空间名称与项目绑定分开表达；紧凑栏是可切换模式，不强迫用户只认一个汉字 |
| 页面标题、分组标题、条目名称、辅助字段明显分级 | 浏览顺序明确，重要信息不用挤在按钮里 | 页面级28–32px、内容组18–20px、正文14px、元信息12px；窗口标题仍保持紧凑 |
| 分区之间留白大，列表内部间距小且整齐 | 页面能呼吸，信息仍集中 | 大区块24–40px，行高40–48px，组内8–12px；禁止全页统一紧凑间距 |
| 大部分信息直接落在页面上，表格用横向线组织 | 不靠层层卡片也能读清结构 | 窗口内部优先列表、分组与对齐；浮窗边框只表达容器边界 |
| 紫色主要标识当前导航和选项，绿色标识明确状态 | 颜色承担语义，选中位置容易认 | 引入局部选中底色；执行、成功、失败另有状态语义，不把强调色铺满所有按钮 |
| New入口统一收纳创建动作，菜单中的图标与文字对齐 | 功能多但顶栏不拥挤 | 添加窗口集中入口；保存/导入/默认等配置动作归入布局菜单 |
| 空项目区域仍有标题、说明和明确下一步 | 空状态也是可使用的页面 | 新工作空间给有意义的起步方式，空分区只作轻量插入点 |

这些是基于截图的设计判断。官方文档另确认了全局搜索、顶部面包屑、左栏折叠及独立显示主题等导航能力；它们说明结构与操作相互配合，但不自动成为本项目已实现的功能。

### 1.2 当前实现为何还差一截

审查基线：062版 `src/workbench/app.tsx`、`workbench.css` 与运行截图。下表是当前缺口，不是通过改本文就已修复。

| 当前问题 | 代码/页面证据 | 视觉后果 | 修正方向 |
| --- | --- | --- | --- |
| 字号整体偏小，层级被压平 | 工具栏12px、空间名13px、状态10–11px；空空间缺少独立内容标题 | 高分辨率下像微缩工具条，用户找不到阅读起点 | 按职责建立字号梯度；主要操作与导航至少13–14px，不靠放大浏览器补救 |
| 留白缺乏内容锚点 | 多个空区域各自居中一个“添加窗口”，其余几乎空白 | 大面积空和边缘拥挤同时出现，像布局调试器 | 一个空间级起步引导，提供有主次的默认配置；用户主动拆出的空区域才显示插入入口 |
| 导航识别不足 | 52px栏使用 `s.name.slice(0,1)`，附9px编号 | 名称被丢弃，相似空间难以辨认 | 可展开的名称导航；折叠态用统一图标和可见tooltip；编号只辅助 |
| 业务操作与布局操作同层 | 保存、添加、窗口列表、布局、收拢并排；分割按钮每个区域常驻 | 用户先看到“管理窗口”，后看到自己的内容 | 主动作、布局管理、状态分组；区域工具进入标题菜单或布局编辑态 |
| 图标缺少统一造型 | `⌖`、`↗`、`◫`、`⊟`、`◢`等字符混用 | 线宽、重心、含义不一致，像临时拼接 | 操作图标统一SVG尺寸/线宽，文字负责表达动作；ASCII只用于真实结构 |
| 空间容器和内容层缺少区分 | 外壳变平后，普通内容也常只剩一条标题和大块背景 | 页面虽然更黑更简洁，但信息组织没有改善 | 容器安静，内容具有标题、工具区、列表/阅读区的明确结构 |
| 实现规则容易漂移 | 同一CSS文件多次定义 `.wb-toolbar`、`.wb-caption`、`.wb-region` 等选择器 | 最后追加的样式决定效果，token存在但组件尺度仍分散 | 整理成token→基础组件→窗口内容→响应式，删除被覆盖旧规则，禁止无限追加补丁 |

不能简单把Render有真实服务列表、而我们是空布局的内容差异归结为视觉质量。后续必须同时比较空状态、真实资料、长标题、多浮窗等同等复杂度场景。

## 2 视觉原则

### 窗口布局与项目内容分离

分区边缘的入口随占用状态变化：空分区为“添加窗口”加号，已有窗口为“切换窗口”双向箭头。切换在当前分区原位替换，保持分区结构；选择“留空”仅移除内容。未发送输入按关闭窗口规则确认。

“添加窗口”只选择窗口类型，不要求选择项目。顶部“当前项目”决定资产和Pi窗口显示哪个项目的内容，包括全局浮窗；切换项目不改变空间、窗口实例、位置或尺寸。未选项目时仍可添加资产/Pi窗口，在窗口内显示选择顶部项目的提示。便签、时钟等无项目依赖的窗口不随项目切换。

Pi窗口在内部新建或选择已有对话。各窗口按项目保存内容状态：会话、草稿、资料附件、筛选及滚动位置相互隔离，切回项目恢复。异步提交结果必须写回发起操作时的项目，不能污染切换后的项目。项目选择随布局配置保存，旧配置无项目字段时仍可读取。

### 三层工作区与透明穿透（v2.3）

空分区不显示居中的添加按钮或占位卡片。添加入口保留在顶部和分区边缘工具栏；关闭窗口即可露出底层画板，清空当前布局可让整个中层留空。

浮窗拖动默认只调整顶层位置，不参与中层分区吸附，也不显示停靠预览。需要回到中层时，使用标题栏“停靠到当前空间”按钮。中层窗口之间的拖动重排、Shift拖出为浮窗和Esc取消继续保留。

工作区由底层画板、中层停靠布局、顶层浮窗组成。画板入口是 `src/workbench/canvas-layer.tsx`，真实画板仍待接入；不得把验证用网格或事件探针当成已交付画板功能。

透明不等于整窗禁用：布局容器、窗口外壳、窗口内部留白都穿透；按钮、编辑器、正文、消息、标题栏和缩放手柄接收输入。浮窗与置顶浮窗使用不透明主题背景，整个窗口阻止向画板穿透。半透明内容块仍属于实际内容。点击、拖拽和滚轮通过浏览器原生命中交给下层，不通过复制事件模拟画板操作。若透明处下面仍有真实控件，则由那个控件接收；所有覆盖层都留空的地方才能直达画板。

窗口开发约定：外壳继承 `pointer-events:none`，原生按钮/输入框/链接由公共样式恢复交互；自定义有背景的内容块标记 `data-workbench-interactive`。不得在占满窗口的透明外壳上恢复 `pointer-events:auto`。不透明的内容区保留自己的滚动和文字选择。分隔条仍保留6px拖拽感应区，可见线宽遵循设置。模态弹窗与遮罩阻止底层操作，避免确认过程中误操作画板。

透明分区不能再依赖 `elementsFromPoint` 命中：窗口停靠按分区矩形和工作区裁剪范围计算。分区工具以紧凑可见按钮展示，不使用遮盖整片画板的透明悬停区域。窗口布局与已有业务状态继续沿用原保存逻辑。

### 统一控件契约（v2.2）

- 新工作台按钮使用同一字号、2px圆角及焦点描边；主动作使用行动色，普通动作使用中性边界，标题栏图标按钮保持紧凑。不能把所有按钮都做成主按钮。
- 添加窗口、外观设置、新建/重命名、删除确认使用相同表面色、线宽和4px弹窗圆角。业务操作不得直接调用浏览器 `prompt` / `confirm`。
- 布局菜单、窗口列表与选择列表共用表面色、2px圆角、36px最小行高和轻阴影；全部继承全局配色与线宽。
- 项目、已有对话、目标聊天使用 `src/workbench/controls.tsx` 的 `Select`。选中项采用主题选中色，键盘支持方向键、Home/End、Enter、Escape及文字前缀定位；长列表滚动，弹层不得超出视口。
- 工具栏弹层互斥；打开弹窗时关闭菜单；执行菜单动作或点击外部时关闭菜单。Escape先关闭选择列表，再关闭所属弹窗；关闭弹窗恢复入口焦点。
- 回归必须覆盖深色/浅色、1px/3px线宽、长列表、800×600视口，以及弹层叠加与取消操作。组件变化不能重置布局或对话状态。

- 黑白与暖灰构成主要界面，少量橙色表示正在执行或需要注意的动作。
- 用少量深紫底色表达当前选中位置；浅色按钮表达本区域主动作。选中、行动和运行状态必须分开。
- 层次由明暗、留白、文字等级和分隔线建立。
- 页面以一个主要工作区域为中心；辅助信息允许折叠。
- 控件偏平面、小圆角；不用霓虹、玻璃、渐变按钮或装饰光晕。
- 中文正文使用清晰的无衬线字体；等宽字体承担结构与技术元信息。
- ASCII 必须表达实际结构，不作为随机代码装饰。
- 文章观点、资产和任务状态必须来自真实数据；效果图里的文案不可直接作为运行状态。

## 3 颜色

以下是项目自定 token，源于参考风格后按应用需要调整，不宣称是 Render 官方色值。

| Token | 值 | 用途 |
| --- | --- | --- |
| --bg-canvas | #101010 | 全局画布 |
| --bg-sidebar | #141414 | 导航区域 |
| --bg-surface | #191919 | 编辑、输入、辅助面板 |
| --bg-hover | #242321 | 普通悬停、次级数据行选择 |
| --bg-selected | #240046 | 当前导航/选项底色，小面积使用 |
| --text-selected | #F3E8FF | 选中项文字，配合背景和标记表达状态 |
| --bg-paper | #EEEEEA | 阅读与稿件纸面 |
| --text-primary | #EEEEEE | 深色背景主文字 |
| --text-secondary | #B8B3B0 | 次级正文 |
| --text-muted | #918A85 | 辅助信息，需按背景实测对比度 |
| --text-ink | #24231F | 浅色纸面正文 |
| --border-subtle | #30302E | 轻分隔线 |
| --border-strong | #77716B | 需要可辨识的控件边界，深色底上保持至少 3:1 |
| --accent-running | #EE6018 | 运行中小标记、关键进度 |
| --status-success | #A0CA92 | 小型成功标记 |
| --status-danger | #E88782 | 错误图标与提示 |
| --focus-ring | #EEEEEE | 键盘焦点 |

主要按钮采用浅色底与深色字，次要按钮为透明或深灰。普通悬停用 `--bg-hover`；持久的导航/选项选中用 `--bg-selected`，数据行选择可用暖灰底加侧标记。紫色不用于正文、全页边框和每个浮窗；橙色不铺满按钮或大卡片。成功不用大面积绿色，所有状态同时附文字或符号。焦点环独立于选中状态，不因已有紫底就省略。

边界分三层：背景差异分开画布与侧栏；subtle线分开内容组；strong线用于输入、菜单和必要浮窗边界。同一层不要同时使用明暗底色、强边框、阴影三种强调。白色边框不是“高级感”装饰。

### 3.1 用户外观设置

工作台左下角“设置 → 外观”提供墨黑/紫色选中、暖灰、石墨、浅色四套整体配色，以及0.5–3 CSS px、步进0.5的线宽选择。默认墨黑、1px。颜色统一映射语义token，窗口/菜单/控件边界使用 `--line-width`，分隔线视觉粗细跟随设置但拖动命中区保持6px；键盘焦点环保持独立可见。不同屏幕像素密度可能使半像素边框取整。

实时预览并沿用服务端修订号自动保存，所有布局空间共用；切换主题不改变业务绑定和窗口布局。旧配置缺少appearance时读取默认值，无破坏性迁移。导航展开/折叠同样保存。恢复默认外观只恢复主题、线宽与导航模式，不重置工作空间。正文纸面仍可通过阅读窗口自己的深色选项切换。

导出完整配置包含appearance；“导入为新空间”和冲突“另存本地配置”合并空间时保留当前服务端全局外观，避免导入布局意外换主题。已有旧版入口维持其原视觉，不把新版外观设置写入旧版样式。

## 4 字体与文字等级

Latin 推荐 Geist 或 Inter；中文使用系统可用的 PingFang SC、Microsoft YaHei、Noto Sans SC；等宽区域使用 Geist Mono、JetBrains Mono 或系统等宽字体。字体许可、分发与加载在实现时核实，不依赖未取得许可的专有字体。

| 用途 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| 页面标题/空间起步页标题 | 28–32px | 500 | 1.25 |
| 内容分组标题 | 18–20px | 500–600 | 1.4 |
| 窗口标题 | 13–14px | 500 | 1.4 |
| 常规正文 | 14px | 400 | 1.5 |
| 控件与导航 | 13–14px | 400–500 | 1.4 |
| 元信息 | 12px | 400 | 1.5 |
| 文章正文 | 16px | 400 | 1.75 |

标题不使用营销页的超大字和整屏粗体。英文可轻微收紧字距；中文保持正常字距，不能直接套用英文负字距。文章宽度约 60–75 个字符，采用独立阅读排版。

28–32px标题只用于空间首页/全页内容，不给每个浮窗增加大标题。正文、文件名、菜单项和常用按钮不低于13px；12px用于辅助字段，10–11px只允许非关键快捷键或诊断信息。禁止用缩小整个UI掩盖拥挤，先减少常驻操作。阅读列以统一容器限制宽度，不能分别给不同字号的h1与p设置相同ch数，造成左边缘错位。

## 5 间距与形状

间距基于 4px：4、8、12、16、24、32、40、48。常规窗口内容内距16–24px，关联元素8–12px，独立区域24–40px，空间起步页内容边距32–48px。紧凑的表格行不意味着分组标题也应紧贴表格。

按钮和输入圆角 3–4px，普通面板 4–8px；浮层可用 8px。药丸只用于确有需要的紧凑标签，不能让所有控件都变成胶囊。

列表/菜单/分段选项优先0–2px圆角，常规窗口外壳2–4px，主要对话框最多6px。图标16px，复杂工具可用18px；选定同一SVG图标体系，统一约1.5px描边、20px对齐槽。不要用不同Unicode字形替代菜单、停靠、收起等核心操作图标。图标按钮视觉28–32px，指针目标至少32px；触控仍至少44px。

边框通常 1px。阴影只用于需要覆盖层级的浮层，保持轻微。没有阴影也应能理解页面结构。

## 6 布局

### 6.1 稳定外壳

自由布局工作台保留空间配置切换器。提供200–240px的名称导航和48–52px折叠栏；浏览配置默认显示名称，专注工作配置可折叠，并保存用户选择，不擅自改写现有配置。标题、全名tooltip和可访问名称必须能识别空间；不能用首字和极小编号承担全部导航。

全局顶栏48–56px，窗口标题32–36px，二者不能做成同一种工具条。顶部左侧只交代工作台/当前空间；窗口内部明确项目或资源绑定。旧项目标签页可保留40–44px。关闭任何视图不等于停止任务。

顶栏右侧保留“添加窗口”与必要的窗口切换入口，其他配置操作归入“布局”菜单。自动保存成功用安静状态文字；保存失败/冲突才提升提示。整体收拢在存在展开浮窗时才出现或可用，不为不存在的对象占据常驻强调位。全局搜索可后续设计，但没有实现时不显示假的搜索框或快捷键。

分割区域直接组成工作面，不再每层套卡片。默认不显示满屏分割/关闭按钮：放入标题菜单、布局编辑态或hover/focus显现，键盘始终有可达入口；标题只保留高频动作。分隔线视觉1px，拖动命中区至少6px，命中区不得覆盖正文控件。

自由布局不意味着没有默认构图。配置应有一个主工作区域和辅助区域，常规桌面主区域占约55–70%的可用工作面；这是默认配置原则，不限制用户自行调节。主区实际宽度不足640px时，默认配置先折叠辅助区，保留用户手动布局及找回入口。

空白配置仍可选。首次没有内容时展示一个空间级起步区：空间名称、一句用途、一个主动作和少量真实可用配置；不要默认打开演示窗口作为业务首页，也不要把三块等价空容器当成完成设计。用户手动分割产生的空叶用轻量“添加窗口”插入点，无需重复整套引导。

默认不放 CPU、内存等系统监控，它们属于诊断视图。不要照搬效果图中的装饰指标、随机时间或虚构任务数量。

### 6.2 项目主页

项目预览优先，可使用规则网格或一个重点项目配合项目列表。编号 [01] 帮助识别，不替代项目名称。预览必须来自该项目成果或明确的空状态占位。

每个项目只显示名称、状态、预览和必要元信息。详细进度移入项目页。新建项目使用一个清楚的主要动作，主页不堆叠运营看板。

### 6.3 项目工作页

主要成果占据可用空间的大部分。资产导航位于左侧，检查器和任务记录按需打开。避免始终展示资产、聊天、日志、验证、代理和升级六个面板。

图片页突出画布和比较；研究页突出证据和结论；文章页使用浅色纸面编辑区域。共享外壳保持稳定，各页使用合适视图。

### 6.4 小窗口

空间不足时先折叠检查器，再收起侧栏；主成果不硬压成狭窄列。必要时单列显示，标签栏可横向滚动。预览、编辑和对话切换时保留状态。

### 6.5 手机访问

手机以项目列表、项目切换器和单列成果为主，保留同一作用域对话。桌面标签页可以转为项目切换入口，不照搬横向多面板。手机支持需求输入、上传、查看、审批、阅读和轻量稿件编辑；复杂图片画布与代码编辑留给电脑专用视图。

主要触控目标至少 44px，ASCII 元信息可简化但保持语义；目录树与表格可折叠，避免缩小文字塞满屏幕。输入区域适配软键盘与安全区，不遮挡提交和保存状态。

显示保存中、已同步、离线未同步和冲突。手机关闭页面不取消服务端任务；电脑节点离线时显示“等待电脑上线”，而不是笼统的运行中。通知渠道尚未实现时使用应用内进展，不画出虚假的推送能力。

## 7 ASCII 表达

推荐字符：

```text
[01] 图片实验室
[+] 新建项目
>_ 输入指令
资料 -> 试验 -> 结论
[====......] 4 / 10
assets/
├─ references/
├─ outputs/
└─ notes/
```

ASCII 是可选的轻量视觉语言。已知可计量总量才能展示百分比或进度条；未知进度显示“运行中”与最近真实事件，不虚构推进数值。

ASCII从“风格主角”降为结构辅助：编号、路径、命令提示、真实关系可以使用；窗口操作和业务类别采用统一图标或文字。不给普通标题强加英文大写副标题，不用 `>_`、星号或代码碎片装饰每个组件。

目录树来自真实数据，可点击节点使用正规的控件语义。流程线只表达真实依赖，节点位置不代表执行先后。屏幕阅读器使用简短可访问描述，装饰字符隐藏。全局背景不使用随机字符雨。

## 8 组件

| 组件 | 规则 |
| --- | --- |
| 主要按钮 | 浅色底、深色字，每个上下文清楚指向主要动作 |
| 次要按钮 | 中性边框或文字，不与主要动作争夺强调 |
| 输入框 | 深色底、明确边界，焦点可见，错误信息靠近字段 |
| 对话入口 | >_ 提示、作用域、输入和发送；历史按需展开 |
| 项目条目 | 名称、真实预览、简洁状态；整块点击与菜单动作不冲突 |
| 状态标签 | 小标记与文本，颜色仅辅助 |
| 文件列表 | 文件名、类型、必要版本和操作，不仅依赖扩展名 |
| 阅读纸面 | 浅底深字，充分行距；可切换深色阅读 |
| 执行日志 | 时间、任务、动作、结果；技术细节展开查看 |
| 对话/界面操作 | 共享业务接口，成功状态以真实结果为准 |

任何列表和任务视图都需要 loading、empty、error、partial、ready 等相关状态。示例按钮不是默认功能承诺；是否显示取决于能力与授权。

### 8.1 内容组织的具体尺度

- 列表行40–48px，双行资料项56–64px；主名称14px，元信息12px。表格使用稳定列宽和横向分隔，数值右对齐、时间格式统一，禁止每个单元格都嵌一张卡片。
- 常规输入高36–40px，按钮32–36px；一组动作统一高度和基线，不能把12px文字按钮夹在大输入框之间。窄窗优先折行或收进菜单，而非继续缩字。
- 菜单宽200–240px，条目32–36px；图标槽20px、文字列共用起点，危险操作另组。最多两级常用分组，不把所有按钮平铺在标题栏。
- 浮窗正文同样需要标题/作用域、局部操作、内容三层；布局外壳不承担业务说明。只有当前操作窗口提升边框，置顶标记只说明层级，不自动等于激活或运行。
- 内容阅读保持纸面模式，但工具栏和资料列表不跟着变白；同一时刻只让主阅读区域形成大面积明暗对比。
- 空状态要告诉用户缺什么、能做什么；失败状态保留已加载内容和恢复动作。没有内容不能用演示任务、随机数字或假日志填版。

## 9 执行与错误呈现

排队显示“排队中”，运行显示当前动作，等待用户显示待决问题。取消请求与实际停止区分；中断显示恢复或对账入口；未知外部结果显示“结果待核实”，不给假成功图标。

任务成功与验证通过分别呈现，验证详情在需要时展开。提供成果入口和继续操作，不将底层模型事件直接转为业务完成。

插件启用、恢复等高影响动作显示实际版本和结果。恢复按钮只在系统具备对应能力时可用，不能作为视觉装饰。

## 10 动态页面与可访问性

动态页面复用本规范的组件和 token，不能按每次生成临时改变主题。优先通过可信组件配置布局，新代码遵守候选构建与验证流程。

保存视图、选中资产与版本，生成失败可以恢复默认页面。新视图的颜色、密度、状态和作用域不得破坏稳定外壳。

常规文字对比度目标至少 4.5:1，大字号文字及必要图形按适用标准验证；控件焦点明显。键盘可完成导航、切换项目、发送指令和打开成果。尊重减少动画设置，不使用持续闪烁光标或状态动画。状态变化提供适度的可访问通知。

## 11 实现与验收

通过 CSS 变量统一 token，通过共享组件统一状态和交互。ASCII 内容采用合适的等宽排版；逻辑与数据不写死在视觉模板。

样式按token、基础控件、外壳、业务窗口、响应式顺序组织。同一组件只有一套权威尺寸定义，媒体/容器查询的例外紧邻组件或集中说明；不继续在文件尾覆盖已有同名选择器来修补观感。设计变更同时改组件规则和使用位置，不能只改根颜色。

### 11.1 下一轮实施顺序

1. 整理重复CSS与图标体系，统一文字和控件尺寸；保持现有布局协议与业务数据。
2. 调整全局顶栏、可展开空间导航与操作分组，保留自由拖拽/停靠/全局常驻。
3. 设计空间起步区和有主次的默认配置；只使用现有真实窗口，不替用户绑定项目、不覆盖已保存布局。预设尚不可实现的业务窗口明确后置。
4. 用同一组真实测试内容校准资产列表、纸面、聊天、菜单与浮窗；再检查空/加载/失败/窄窗状态。
5. 实际截图复核后做交互回归，确认保存、焦点、拖拽、滚动与Pi生命周期未退化。不得把前端功能测试通过当成视觉认可。

### 11.2 视觉验收尺度

- 在浏览器100%缩放的1440×900视口，能直接读出当前空间、主内容与主动作；不需要放大页面才能读常用操作。
- 同时验证空空间、真实资产+阅读、长对话、至少三个浮窗、打开菜单、保存失败等场景，不只展示最整齐的一张截图。
- 主标题、分组、正文、元信息能一眼分级；主内容比布局管理按钮更醒目。尺寸以本规范为基准，任何偏离注明场景原因。
- 对齐检查覆盖标题/正文左边缘、图标与文字中心线、菜单文字列、表格列和输入按钮基线，不能只检查色值。
- 每个独立任务上下文只有一个主要动作；其他操作按频率和作用域分组。已经打开的弹窗或浮窗可有自己的主动作。
- 灰度观察仍能辨认层级，移除阴影仍能辨认容器边界；颜色不成为唯一识别依据。
- 在800×600及150%浏览器缩放下可操作；按窗口实际宽度响应，而不是只按浏览器宽度判断。切换布局不丢失输入、选择和滚动。

以下通用检查继续适用：

视觉验收检查：

- 当前项目、主要成果和下一步是否一眼可辨。
- 主操作与对话是否清楚且不遮挡内容。
- 字体、间距、边框和状态是否统一。
- 是否存在不必要嵌套卡片、大标题、光晕或过多强调色。
- 图像预览、稿件、表格是否适合实际阅读。
- 空、失败、取消、中断和未知结果是否有真实状态。
- 小窗口与键盘操作是否可用。
- 运行截图是否来自真实数据，示意与模拟是否明确标识。

验收使用真实运行页面和交互，概念图只用于方向参考。已授权的自由工作台继续开发；本规范不扩大到完整绘图引擎、代理图或手机功能实施。用户对观感的认可单独记录。
