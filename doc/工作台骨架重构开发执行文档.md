# 工作台骨架重构：Agent 开发与交付执行文档

版本：1.1
日期：2026-10-15
状态：开发与交付执行规范；实际实现进度以 `dev/current.md`、`dev/backlog.md` 和对应证据为准。本文不代表功能已完成。
目标：先交付可自由布置、保存和恢复的工作台骨架，再逐个接入功能窗口；保留 Pi 执行底座。

## 1. 使用方式与优先级

本文是本次重构的范围、执行循环和验收依据。收到用户“按本文实施/继续开发”等执行指令后，Agent 应持续推进依赖就绪的工作，完成验证和交付；不能每完成一个小任务就等待下一条指令。本次编写文档不等于已经启动产品实现。

用户最新指令、适用的 AGENTS.md 和运行环境约束优先。本文覆盖旧文档中与本次重构冲突的固定页面和分区组织要求（视觉继续遵循 `design.md` 的 Factory + ASCII 规范），以及“必须先完成全部旧 M0 才能推进新界面”的顺序；不把历史未验收事项标成通过。旧文档中数据保护、Pi 能力保留、真实证据和恢复原则继续适用。

阅读顺序：本文 → `dev/current.md` → `dev/backlog.md` 中 WB 任务 → 最近关联迭代与 ADR → 实际代码。旧计划只按依赖查阅，不要求每轮重新读完历史。

文档描述的是**开发 Agent 的工作循环**，不是产品内部 Pi 的任务循环。没有新增用户授权时，不自动扩大到发布、付费服务、远程部署或删除历史数据；也不为已授权的普通实现、修复、验证重复征求许可。

- 新旧界面先并存，默认入口切换放在最终本地交付阶段；入口路径由 WB-01 确定并记录。

## 3. 范围与完成边界

本次必做：空间导航、嵌套分割、停靠和浮窗互转、全局浮窗、置顶、图标收起、整体收拢、窗口找回、配置持久化及恢复、默认布局、共享前端连接与窗口注册接口、一个真实资产浏览窗口、支持独立会话的 Pi 聊天窗口。

本次不做：画板绘图引擎、完整资产库改造、便签/Todo/日历/时间线/预设的完整业务、第三方插件市场、OS 桌面窗口、多任务并发调度、手机/云部署。可以出现明确标注的演示窗口，但不能用它们代替真实接入验收。

不删除旧业务模块及历史数据来缩短交付。旧 UI 的最终删除另列清理任务，待替代路径和回退方案证据齐全后按授权范围执行。历史 M0/M1 未完成项单独记录，不冒充本次交付阻塞，除非确实影响本次功能。

工程交付、在线模型验收、用户体验认可分别记录。不能用编译成功代替交互验收，也不能因等待用户体验反馈而停止其他已授权、可执行的工作。

## 5. 对象、状态与不变量

### 5.1 对象关系

- Workspace：布局空间，具有稳定 ID、名称、顺序和停靠布局树。
- WindowInstance：具体窗口，具有稳定 instanceId、窗口类型、业务绑定和视图状态版本。
- DockTree：由水平/垂直分割节点和叶节点组成；记录比例及叶节点中的实例引用。
- GlobalFloatingLayer：全局浮窗、图标、置顶顺序和整体收拢恢复信息。
- Project：现有业务数据归属，与 Workspace 独立。
- Conversation：独立对话标识，绑定项目及其 Task/Run/消息链；不是 Pi 每次运行生成的原生 sessionId。
- WorkbenchConfiguration：工作空间集合、全局浮窗层、实例索引、配置版本和并发修订号。

结构为概念契约，不强制具体 TypeScript 字段名。WB-01 必须形成类型与存储 ADR，避免组件库内部结构直接成为永久业务协议。

### 5.2 三类状态

| 状态 | 示例 | 生命周期 |
| --- | --- | --- |
| 布局状态 | 分区比例、坐标、尺寸、置顶、收起 | 保存配置，支持版本迁移 |
| 视图状态 | 未发送输入、选中项、筛选、滚动、未提交编辑 | 按实例隔离；拖动/收起/切换不能丢失 |
| 业务数据 | 文件、草稿、对话、任务、执行记录 | 独立保存，不随窗口关闭而删除 |

暂存编辑内容不可只依赖可能卸载的 React 组件；为同内容多视图明确同步/冲突策略。拖动过程只更新临时预览，提交落点后一次更新权威布局，持久化合并写入，不能每个 pointermove 都写数据库。

### 5.3 必须始终成立

1. 一个实例只能处于一个位置：某空间的停靠叶节点、全局浮窗或全局图标；不能重复出现或成为不可找回的孤儿。
2. 拖出/拖回是移动；无效落点、Escape 或指针取消恢复原位。关闭窗口与删除业务内容是不同命令。
3. 悬浮转停靠后属于目标空间；转为悬浮后全局常驻。图标化保存原尺寸、位置和置顶属性。
4. 切换空间不改变全局窗口的项目、资源或会话绑定。发送请求使用窗口绑定，不能隐式读取当前空间的全局 selected。
5. 关闭/收起/切空间不取消 Pi；布局恢复不创建新的业务会话、不重发消息、不重复启动任务。
6. 多实例按 instanceId 隔离；注册类型声明单例、多实例或同内容多视图策略，不假定所有窗口均可无限复制。
7. 置顶只影响内容浮窗；菜单、对话框、拖动提示仍可正常显示和操作，焦点不会被置顶窗永久抢占。
8. 视口变化后标题栏与收纳入口仍可触达；窗口列表可定位、展开或找回窗口。
9. 删除空间保留数据和全局浮窗；最后一个空间删除后仍提供可用空白入口。未保存内容先持久保存或明确拦截关闭，不静默丢弃。
10. 配置中的未知窗口类型或失效资源显示可关闭的说明占位，不使整个工作台白屏。

## 6. 窗口接入与 Pi 会话边界

窗口注册最少声明：类型 ID、名称/图标、默认/最小尺寸、实例策略、创建与恢复方法、状态版本、内容组件、资源绑定、关闭前处理。注册入口由应用代码控制，本次不建设第三方动态代码加载框架。

外壳统一提供标题、移动、停靠、浮动、收起、置顶、关闭。正文可选择和编辑；仅标题栏/指定手柄发起窗口拖动。提供菜单操作作为拖动的基础替代，支持 Escape 取消和关闭后合理焦点恢复。

共享层负责认证、SSE、重连、数据缓存；每个窗口有独立加载、错误与提交状态。窗口数量增加不能等量增加全量事件连接。切换空间可卸载不可见内容，但其视图状态和后台业务不丢失。

跨窗联动首版只验证一个用例：选定资产送入明确指定的聊天，携带资产 ID 和必要版本引用；不能使用“全局最后选中的文件”作为所有聊天上下文。

真实聊天接入必须完成：

1. 建立逻辑 conversationId 与项目归属，约束历史、任务和执行链查询。
2. 提交、排队、重试和续聊均沿当前会话链，拒绝跨项目/跨会话错误绑定。可复用现有显式 continueFromRunId，但不回退到项目全局最近会话。
3. 同项目两个会话互不混入历史或上下文；同会话快速排队遵循确定顺序，不能任意接到其他会话刚完成的 Run。
4. 旧项目历史使用兼容聚合视图或明确标注的历史会话；不能声称自动还原出过去不存在的独立对话边界。迁移可重跑且不重写原始 Pi 会话文件。
5. 保留原生工具、技能/资源发现、模型连接、预算、取消、恢复和原生会话校验；UI 重构不升级 Pi 或重写其执行循环，确有需要另记 ADR。

## 7. 配置保存、恢复和兼容

WB-01 决定服务端保存实体和接口细节，至少含 schemaVersion 与 revision；读写沿用已有认证。布局引用不能绕过现有项目/资源访问校验。

- 首版服务端作为已保存配置的权威来源；缓存记录基准 revision 和待保存状态。成功响应后才能显示“已保存”。
- 两个标签页或浏览器并发修改使用修订号校验，冲突保留本地副本并允许重新加载或另存为空间；禁止静默最后写入覆盖。
- 页面恢复时校验版本、实例引用唯一性、布局树深度/数量及尺寸等合理限制。限制应在 ADR 给出具体值，避免损坏数据导致无限递归。
- 保存失败保留本地未保存状态并明确提示；恢复配置损坏时使用上次有效配置或默认布局，不覆盖损坏原件以便排查。
- 自动保存现场与应用默认布局分开；后者不触碰全局浮窗和业务内容。整体布局回退保留上一有效版本，首版不要求任意步撤销系统。
- 新旧 localStorage 键和样式作用域独立，保留 `wb-project-tabs`、`wb-project-views-v1`、`wb-project-inputs`。
- 服务端持久化的布局和会话新增对象必须被现有备份覆盖；检查恢复到干净目录后可读，而不只验证当前进程内状态。
- 一次性迁移先在副本验证，应用前备份；版本/迁移失败能退回旧入口读取原数据。若旧版不能读取新结构，明确只能使用配套备份回退，不能宣称直接换旧代码即可回滚。

## 9. Agent 长时间开发循环

### 9.1 每次启动/上下文恢复

1. 阅读最新用户指令和上述恢复入口；检查 Git 状态、当前分支和未提交改动，保留既有工作。
2. 对照 current 核实 doing/verifying 的真实产物、进程与测试，不盲目重放启动、迁移或模型请求。
3. 核对工具可用性、Node 版本、验证环境和运行服务。历史 PID 不可直接用于停止进程。
4. 确定唯一主任务、验收项、上次失败和下一条可执行动作，更新 current 后继续。

### 9.2 每轮循环

```text
while 本次交付条件未满足:
    吸收用户最新反馈，检查当前代码和证据
    优先修复当前主任务，否则选择依赖就绪的 WB 任务
    写清本轮可观察结果、影响范围和验证方式
    实现一个最小但贯通的改动
    运行相关验证，检查实际 diff 与需求覆盖
    if 验证失败:
        保存复现、原因假设和证据，修复后重验受影响路径
        同根因三次无进展则改变诊断方法，不机械重复
    else:
        更新任务证据和状态，保存接续现场
    if 确有外部阻塞:
        标明受阻子任务、恢复条件，继续独立可做任务
    if 所有工程任务满足:
        执行最终交互、回归、恢复和本地交付检查
        失败则建立关联修复项继续循环
    只有达到交付条件、用户明确暂停或无法继续时才结束
```

普通小任务完成后直接继续，不反复询问“是否继续”。等待某项外部信息不阻塞无依赖工作；不因任务困难、一次超时或缺少可选反馈而宣布整体 blocked。

同一失败记录稳定 failureId、累计次数、假设、复现和修复依据。三次无进展后缩小复现、检查假设或换实现路径；仅当剩余路径确实依赖不可得条件时才记阻塞。禁止通过改名清零失败次数、删测试、降低验收标准或把未知改为通过。

### 9.3 记录与接续

- `dev/backlog.md`：任务 ID、依赖、状态、验收、证据、缺陷和阻塞。状态沿用 todo/ready/doing/verifying/done/blocked/cancelled。
- `dev/current.md`：本次目标、主任务、完成事实、最新代码基线、运行进程、最后验证、失败、下一条具体动作、待答问题。
- `dev/iterations/`：本轮实现、测试、失败和决策；使用不与已有编号冲突的文件名。
- `doc/adr/`：对象模型、布局库、持久化、独立会话及迁移等重要选择。
- `output/dev-evidence/workbench/<轮次>/`：命令输出、结构化结果、截图/交互证据。记录 commit 或相关文件摘要，使证据能对应当前代码；不保存凭据。

每完成一个可验证单元或准备中断时更新现场，不能只在最后写大总结。更新进展应说明新事实、下一步及阻塞，避免长时间无反馈。工作需跨会话时提供可直接继续的任务与命令，不要求后续 Agent 重新分析全部历史。

需要子 agent 时遵循当时用户授权与工具约束；本文不要求持续并行，也不把此前一次计划审查授权扩展成无限委派。审查发现必须落为处理结果，不能只收集报告。

### 9.4 可直接复制的单轮记录

每轮围绕一个可验收结果填写下列字段；可以更新同一轮记录，不要求每次工具调用都新建文档。耗时较长的测试记录启动命令、日志位置和进程身份，接续时先查结果，再决定是否重跑。

```markdown
### LOOP-<编号>：<可观察结果>
- 主任务：WB-xx；关联需求：Rxx；验收：Vxx
- 开始现场：分支/commit、相关未提交文件、已有失败
- 本轮结果目标：用户操作什么，将看到什么
- 实现范围：将修改的模块；依赖是否就绪
- 验证计划：命令、真实交互步骤、预期结果
- 实际改动：文件与行为；重要决策对应 ADR
- 验证结果：通过/失败/未运行；退出码；证据路径；代码摘要
- 缺陷：failureId、累计尝试、复现、已排除原因、下一诊断动作
- 任务状态：doing/verifying/done/blocked；变更依据
- 下一条动作：具体文件/命令/操作，以及预期观察
```

状态流转规则：依赖齐备才进入 ready；开始实现进入 doing；产物可验收进入 verifying；该任务全部通过条件有当前有效证据才进入 done。后续发现回归时重新打开对应任务，保留原证据与失败历史。blocked 必须记录外部依赖及解除条件，不能只写“需要用户确认”。

### 9.5 接续与防止空转

开发文档本身不能让已退出的 Agent 自动唤醒。当前执行会话内持续循环；上下文压缩后读取现场继续；进程退出、额度或工具限制中断后，需要运行环境或用户重新启动。不得把“文档支持接续”写成已经建立后台自动调度。

中断前至少保存：未提交改动位置、当前任务及验收缺口、最后一条命令和结果、仍运行的测试/服务、失败复现、下一条动作。记录密钥的引用位置，不记录密钥值。新 Agent 核实现场后从断点继续，不从 WB-00 重做全部工作。

两轮连续只重复计划、阅读或运行相同命令，且没有新增代码、证据或排除的假设时，下一轮必须缩小问题并提出可证伪的诊断；不能用不断润色文档代替实现。每轮完成后优先处理仍未通过的验收，再选下一个依赖就绪任务。

交付证据按下列格式归档，V01–V17 每项一行；一个测试可覆盖多个场景，但必须说明覆盖的行为。修改影响到某项证据时标为待重验，仅重跑受影响范围，最终再按第 11 节完成回归。

| 验收 ID | 当前代码基线/文件摘要 | 操作或命令 | 结果 | 证据路径 | 缺口/关联缺陷 |
| --- | --- | --- | --- | --- | --- |
| Vxx | 待填写 | 待填写 | 未运行 | 无 | 待填写 |

## 10. 验证矩阵

测试用独立数据目录和端口；现有用户资料不作破坏性夹具。根据变化选择有价值的测试，不为纯样式变更编写镜像实现的测试。交互必须在真实浏览器里操作，不以 HTTP 200、SSR 或纯 reducer 测试替代。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| V01 | 至少三层嵌套分割、拖动尺寸、关闭分区 | 最小尺寸有效，树无孤儿，最后区域可继续添加 |
| V02 | 停靠→浮窗→另一分区；无效落点/Escape | 实例唯一，取消回原位，内容不丢 |
| V03 | 浮窗置顶、单窗图标化、整体收拢/展开 | 恢复位置/大小/置顶；原先收起窗口不误展开 |
| V04 | A 空间聊天输入未发→切 B→发送 | 输入不丢，仍提交原会话/项目 |
| V05 | 保存分区及浮窗→刷新/重启服务/换浏览器 | 布局和内容绑定恢复，缓存不会覆盖服务端新版本 |
| V06 | 应用默认、复制/删除空间 | 全局浮窗保留，业务内容不删除，不复制任务或会话 |
| V07 | 缩小窗口、浏览器缩放、遮挡 | 标题栏/图标可找回，菜单/弹窗可操作，正文正常选择 |
| V08 | 损坏配置、未知类型、资源已删除、存储失败 | 无白屏；有说明、保留本地状态或回退；不假报已保存 |
| V09 | 两标签或浏览器并发改布局 | 冲突可见，可恢复本地修改，无静默覆盖 |
| V10 | 同项目两个独立聊天分别提交、继续、排队 | 历史和续聊链隔离，不借用其他会话执行 |
| V11 | Pi 执行中关闭聊天、切空间、刷新再打开 | 后台执行继续，可恢复输出，不重复模型请求 |
| V12 | 不同资产窗口送资料到指定聊天 | 只有目标聊天收到正确资源引用 |
| V13 | 拖动含输入/编辑/滚动的真实窗口 | 视图状态保留，无重复订阅或重复发送 |
| V14 | 原生 Pi 能力与取消、预算、恢复回归 | 原有保护和工具能力不因 UI 重构退化 |
| V15 | 旧入口与新入口往返、旧数据迁移重跑 | 旧状态保留，样式不污染，迁移幂等、原始会话不变 |
| V16 | 备份恢复到干净测试目录 | 新布局/会话和既有内容可读，凭据处理沿原规则 |
| V17 | 4 空间、12 停靠窗、6 浮窗，100次混合操作 | 无窗口丢失、重复或控制台未处理错误；共享连接不随窗口数增长 |

性能记录浏览器、机器、视口和操作延迟，检查拖动不卡住输入。WB-02 记录实测基线与可接受门槛；不能宣称所有设备达到同一帧率。V17 验证对象及资源泄漏趋势，不要求无依据的大规模压力工程。

真实在线模型验收采用最小输入、可识别标记和明确请求数/超时上限，先核对已有授权及连接状态。不得把工程样例、mock 或离线协议测试写成真实模型通过。缺外部条件时保留该项待验收，先完成其余工作；不反复消耗额度尝试同一失败。

先确认脚本当前内容及 Node 24+ 环境。Windows 可复用：

```powershell

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 test
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run.ps1 probe
```

`scripts/verify.mjs` 可用已确认的 Node 24+ 绝对路径执行，包含完整测试、类型、构建和 Pi 离线探针。不要默认系统 `node` 版本符合要求，也不要重复运行等价的完整检查来凑证据。

每轮：相关测试＋必要类型/构建＋对应实际交互。里程碑：扩大到相关回归。最终：当前代码基线完整检查＋V01–V17证据核对。新增浏览器测试的运行入口、依赖和命令应写入 package scripts 或 README，不能只保存在临时终端历史。

若基线已有失败，先记录并判断与本次改动关系；不能把已有失败掩盖，也不能无边界修复所有历史问题。验证工具不可用时明确缺的是哪项证据，继续可以验证的部分，不把截图或代码阅读冒充交互操作。

## 12. 本地交付与停止条件

最终交付前必须核对：

- R01–R09 均映射到已实现任务和有效证据；没有隐藏删除的需求。
- 当前基线的类型、构建、相关与完整测试通过；V01–V17逐项有结果，失败和未知不能计为通过。
- 占位窗口和真实窗口清楚区分；真实资产与独立 Pi 聊天接入完成。
- 旧数据、凭据及 Pi 原生能力保留；迁移和恢复证据齐全。
- 新入口可访问，用户知道如何添加窗口、保存/恢复、找回浮窗、切回旧界面。
- 本地应用前核查服务身份与在途任务，优先等待空闲，不为换 UI 直接强杀正在执行的 Pi；应用后检查健康、页面与关键交互。
- 更新 current、backlog、运行说明和交付记录；新增配置在 `.env.example` 等适当位置说明，不泄露密钥。

交付状态只能按事实报告：

| 状态 | 含义 |
| --- | --- |
| 开发中 | 仍有可执行必做任务，继续循环 |
| 工程完成，在线/交互验收受阻 | 明确剩余项、外部条件和恢复动作，不宣布全部完成 |
| 已本地交付，待用户体验反馈 | 必做工程及真实验收已通过，提供入口和操作说明；用户认可单独等待 |
| 已按反馈完成 | 用户提出的本轮具体修改已实现并验证 |

可以结束当前执行的情形：目标完成；用户明确暂停/变更目标；系统资源或权限限制使继续不可能；所有剩余必做项均有真实外部阻塞。结束前保存现场。禁止因为“已写计划”“原型看起来像”“测试跑过一部分”就停止并宣称交付。

最终回复应简洁列出：可用入口、已完成能力、验证范围、未完成或受阻项、回退方式。完成文档本身时只报告文档完成，不报告工作台已重构。
