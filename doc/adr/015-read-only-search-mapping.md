# ADR-015：只读搜索映射与索引字节校验

2026-10-06。继[ADR-014](014-search-and-capacity-performance.md)后台搜索后，完整容量场景50份8 MiB正文页仍超过2秒。逐项诊断显示数据库读取/字符串转换占主要成本，保留原件哈希、真实片段和完整分页。

只在每个所属只读搜索进程设置SQLite mmap_size上限1 GiB，最多两个进程。它是有上限的虚拟文件映射，不代表立即分配1 GiB堆内存、额外磁盘配额或OS隔离。SQLite继续处理事务/WAL一致性；运行时设置不持久化，没有用户设置表单或新索引。构建不支持映射时使用原普通读取；失败仍通过所属进程终态报告，超时、取消、关闭与权限复核保持。

UTF-8数据库将当前页索引TEXT按BLOB读取，与已经完整SHA256和fatal UTF-8校验的原件字节比较。TextDecoder去掉文件开头一个UTF-8 BOM，所以比较时对应去掉该BOM；原件本身及其哈希保持。二进制和无效UTF-8保留原空正文语义。非UTF-8数据库仍使用原字符串比较。不以资产元数据hash字段替代派生索引内容检查；相同字节长度的伪造正文也会被排除并修复。

普通LIKE字面量、大小写、Unicode、排序、总数、分页和实际原文片段算法保持。尝试正则/锚点匹配和ASCII片段查找后未采用，没有为达标增加未证明收益的算法。

实际原两批隔离资料HTTP测量中，完整正文页最高2057毫秒，仍超过2000毫秒；期间数据读取最高19毫秒。只说明本轮本地改善，不宣称全部查询或生产条件已验收。新增BOM/Unicode/SQL字面量/等长度篡改/无效UTF-8及UTF-16数据库回归，完整工程和产品应用见[023](../dev/iterations/023-search-mapping.md)。
