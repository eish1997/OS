# ADR-007：项目对话的原生会话接续

2026-10-06。已实现；真实服务重启接续通过，异常中断及排队追问的完整真实验收继续推进。

普通项目对话默认使用同项目、同模型连接和策略版本的已完成Pi会话。用户可选择「新话题」只对本次创建空白会话；无需模型或会话参数。前序任务尚在运行时，后续对话固定前序Run依赖，等待其终态与实际进程退出，再校验、固定会话身份和哈希；没有可恢复会话或未知操作未对账则停止后续任务，不偷偷使用旧话题。

采用固定Pi1.0.3的SessionManager.forkFrom / open接口。每个新Run拥有新会话ID和文件，原始会话不改写；历史工具回执是上下文，不能作为重放指令。重试仍为新Run与attempt，存在可用会话时接续失败尝试，未知操作先对账。

Run固定源Run ID、session ID和SHA256。宿主及worker校验项目目录、路径链接、2MiB首版文件上限、JSONL版本3及条目链；核对独立SessionBinding中的项目、任务、会话、cwd、模型、认证类型和策略版本。读取者和本次凭据仍由宿主固定，不从会话加载扩展、包、全局密钥或任意工具。

复制前预留容量，持有同一有界写入锁核对原件；原生后续写入继续受容量保护。SDK复制到自己的新文件后，移除过去由宿主附加的固定记忆/摘要上下文，以及search_memory/read_project_summary/propose_memory历史工具结果；本次重新注入当前确认状态，避免被删除的记忆从旧注入文本返回。用户自己说过的历史文字仍是对话，不宣称能够从所有历史和备份物理抹除相关字词。

独立绑定使用session:<Run ID>主键。旧代码全局实体主键冲突导致部分绑定缺失，可从持久Run与项目内身份匹配的完整v3文件重建，标记reconstructed；记录1.0.3读取兼容性，不据此证明旧文件的全部来源或恢复验收。绑定与Run字段在同一事务中保存，worker等待确认后才执行prompt。

提供商流终态先等待用量结算，再交付给Pi。失败回执永远不冒充完整用量；原始供应商错误不写入原生errorMessage，宿主保留安全步骤码。401/429/503和恢复通过真实固定SDK受控协议测试，不声称耗尽实际账户额度。

证据见[迭代014](../dev/iterations/014-native-project-continuation.md)。实际服务重启接续证明正常历史恢复；干净目录联合恢复为离线SDK证据，尚不能替代独立存储灾难恢复、真实模型异常中断继续及跨网络手机验收。
