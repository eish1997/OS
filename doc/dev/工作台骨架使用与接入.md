# 工作台骨架使用与窗口接入

## 使用

- 默认入口：`http://127.0.0.1:4310/`；`/workbench` 同样进入新版。旧界面保留在 `/legacy`，模型连接与旧草稿等入口仍可使用。
- 左下角“设置 → 外观”可选择墨黑、暖灰、石墨、浅色配色，调整0.5–3px线条粗细；实时生效并自动保存，所有空间共用。导航可展开显示完整名称或折叠。恢复默认外观不会重置布局；旧版入口样式独立。
- 左侧按钮切换布局空间。`＋`新建；点击顶部空间名称重命名；“布局”菜单可另存、上移、删除或恢复默认。
- 空区域“添加窗口”或顶部“＋窗口”添加内容。布局演示窗口仅用于验证骨架，不是完整便签业务。
- 分区页脚按钮上下/左右拆分；拖动分隔线调整大小。空间不足时布局区域可滚动。
- 分区工具在鼠标悬停或键盘聚焦时显现。空工作台可选择“添加窗口”或“直接编辑布局”；已有窗口时直接恢复原配置。
- 拖动标题到目标区域边缘可停靠；按住 Shift 拖动可悬浮，也可点标题“↗”。浮窗在区域中央可自由移动；拖到边缘会出现停靠预览。Esc取消未提交的拖动。
- 浮窗右下角调整大小；“⌖”置顶，“−”收成图标；双击图标或从窗口列表展开。全局浮窗不随空间切换而隐藏。
- “收拢浮窗”把当前展开浮窗收为一个可拖动入口，点击“展开浮窗”或双击收纳入口恢复位置；原先单独收起的图标不被展开。
- “窗口列表”找回被覆盖、收起或位于其他空间的窗口。
- 布局自动保存到本机服务；“已保存”表示服务端确认。冲突时本地内容保留，可下载副本、另存本地配置或重新加载。下载的JSON可通过“导入为新空间”恢复，不覆盖当前空间。
- “恢复默认布局”只替换当前空间；全局浮窗和业务数据保留。“恢复上一步布局”保留一次布局回退，不是完整编辑历史。

资产窗口绑定项目，可按名称/标签筛选、预览和下载文件，并选择同项目的目标聊天添加资料。新建或重新打开Pi对话时选择项目；每段对话有独立历史与续聊链。同对话多个窗口是多个视图，不是多个业务会话。多个任务仍按现有单worker调度排队。

关闭聊天窗口不删除对话，也不取消任务。重新打开时从“＋窗口”的已有对话列表选择。未发送文字保存在窗口状态和本浏览器草稿缓存；关闭有输入的聊天时会提示。现有旧项目历史仍在旧版聚合视图，不伪造历史对话分组。

## 接入新窗口

1. 实现 `WindowContentProps` 内容组件；在 `registry.ts` 添加定义：类型、名称/图标、组件、实例策略、尺寸、状态版本、create/restore、canClose。
2. 在添加窗口入口增加适合业务的创建流程（简单窗口调用注册定义的create；聊天等先创建/选择业务对象）。不要在React挂载时创建业务记录。
3. `binding`保存稳定业务ID；`view`保存选择、滚动和输入等可序列化状态，通过`patch`更新。异步返回若依赖最新状态，使用函数式patch，避免覆盖用户在请求期间继续输入的内容。
4. 服务端业务数据独立保存；窗口不得自行停止全局Pi任务、打开自己的SSE连接或篡改其他窗口的上下文。共享snapshot/refresh由外壳传入。
5. 窗口内只实现内容，停靠、拖动、缩放、置顶、收起交给外壳。当前registry为静态应用注册，不是第三方动态插件执行环境。
6. 验证停靠↔浮窗、收起/切空间、刷新后状态保留；未知类型/失效资源应可关闭且不阻断工作台。

主要文件：`shared/workbench-layout.ts`（模型与不变量）、`server/workbench-config.ts`（保存协议）、`src/workbench/client.ts`（共享连接/缓存）、`app.tsx`（外壳与交互）、`registry.ts`（注册）、`panes.tsx`（首批窗口）。

## 开发验证

Node.js24+，依赖已固定在锁文件。安装使用`npm ci --ignore-scripts`。`playwright-core`不下载浏览器；指定本机Chrome路径：

```powershell
$env:CHROME_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:workbench-ui
```

命令运行隔离构建、临时数据服务和两组真实浏览器验证，不修改生产布局或发起模型请求。可用`PLAYWRIGHT_PACKAGE`覆盖工具包路径，通常不需要。

运行全套工程回归可用Node24执行`--import tsx --test --test-concurrency=4 tests/*.test.ts`，避免同时启动大量Windows进程造成桌面启动测试超时。类型检查和Pi离线探针沿用原脚本。

在线验收脚本`workbench-live-qa.ts`只在明确授权的验证中使用，需要`WORKBENCH_LIVE_QA=1`；使用本机已有认证，创建专用项目，最多3任务/4次模型请求，结束归档并关闭临时登录。其布局通过浏览器私有夹具隔离，不覆盖用户保存的布局。不得将其加入默认离线测试。

## 回退与数据

普通界面回退直接访问`/legacy`，不删除新版配置或对话。旧界面项目历史是聚合视图，独立对话请回新版继续。

首次应用前的业务备份、旧dist和基线源码包保存在被Git忽略的`output/dev-evidence/private/workbench-061/`。数据库备份不含凭据；不要把它移到可提交目录。需要完整版本回退时，先保存当前数据、核对在途任务与服务身份，再由维护流程使用配套源码/静态文件及必要的独立恢复目录；不能覆盖当前数据目录或盲目还原整个工作区。生产历史数据未做破坏性迁移。
