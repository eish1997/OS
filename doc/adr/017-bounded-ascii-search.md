# ADR-017：有界 ASCII 搜索候选与原匹配回退

2026-10-06。023保留完整原件哈希、索引字节校验、真实片段和50份结果页，完整资料库端到端最高2057ms，仍未达到2秒。026在相同隔离库上定位候选匹配成本，采用有界字节定位，不引入新索引、配置或配额。

只在UTF-8数据库、无NUL的ASCII查询且SQLite当前LIKE允许ASCII大小写折叠时启用。正文列必须实际为TEXT，转换为BLOB后先用Node isUtf8核验；其他编码、BLOB/异常TEXT、非ASCII查询和修改过的大小写语义继续交给原SQLite LIKE。

ASCII字节不会成为合法UTF-8多字节字符的组成部分。用Buffer.indexOf查找首字节及其ASCII大小写对应字节，再逐字节核对查询。遇NUL按原SQLite文本终点处理；最多检查64个候选，密集匹配返回“交给原LIKE”。元数据LIKE、SQL转义、范围/状态/版本、排序/总数/分页保持。SQL参数不直接拼接用户查询。

这只是筛选候选的优化。每页原件仍重新完整读取/SHA256、fatal UTF-8解码、派生索引完整字节比对，损坏索引仍修复，片段仍来自原件和原Unicode算法。宿主仍检查权限、取消、资料状态和版本，最多两自有只读搜索进程及实际退出回执的契约保持。

预编译worker及数据库内比较两个候选未显示稳定收益，未采用。更早的ASCII片段候选同样保持未采用；本次优化发生在候选匹配阶段。映射下定位候选的直接诊断不是端到端证据，是否通过以最终HTTP测量和当前工程基线为准，见[026](../dev/iterations/026-bounded-ascii-search.md)。
