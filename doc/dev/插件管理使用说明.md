# 插件管理使用说明

插件管理面向当前工作台实例，统一管理 Pi 插件包。项目切换不会切换插件配置。2026-10-15 已应用到本机工作台 `http://127.0.0.1:4310/`，工程与实际入口验收见 [交付审计](iterations/071-plugin-acceptance.md)。

## 打开管理窗口

从“添加窗口”选择“插件管理”，也可以使用设置中的插件管理入口。已有窗口时定位该窗口；窗口支持工作台的停靠和浮窗操作。窄窗口通过列表与详情切换查看内容。

## MCP外部工具配置（开发工作区，尚未部署）

MCP与插件包分别管理。在插件管理窗口展开“MCP 外部工具配置”，选择全局或具体项目。可以导入mcp.json文件、粘贴JSON，或展开“用表单添加服务”，填写服务名称、HTTP地址或本地启动程序，并选择工具使用方式。本地启动参数每行一个，含空格的参数无需额外引号。表单只加入待预览内容，不覆盖已有同名服务，也不会立即连接；认证、环境变量和高级项目覆盖仍在JSON中配置。

先点击“预览MCP配置”，核对服务名称、来源、项目覆盖及暴露方式。可以只保存而不启用；要启用则打开本范围开关、重新预览并勾选信任确认，然后保存。预览和保存不启动服务；之后执行是否连接成功，要查看执行结果。项目配置未启用时，已有全局配置仍可生效。明确启用的空配置也可能允许可信插件注册MCP服务，不代表禁用所有MCP能力。

命令和路径属于工作台服务所在电脑；导入文件不会自动转换相对路径。展开“MCP 凭据”，使用 `MCP_` 开头的大写变量名保存凭据，然后在配置中引用，例如HTTP头中的 `Bearer ${MCP_TOKEN}`。也可以使用服务端已有环境变量。项目私有凭据优先于全局私有凭据，全局优先于同名环境变量；移除项目凭据后可能重新使用全局值。不要把密钥明文填入JSON。凭据存放在仅宿主用户可访问的私有目录，不是加密保险库；普通备份不包含凭据，恢复或换机器后需要重新配置。页面不回显值，运行时仅传递所引用的凭据；更换凭据可能阻止旧会话接续。OAuth浏览器授权入口仍未完成。配置文件导入不等同于安装服务，所引用的程序需在服务端已存在。

未保存修改会锁定范围切换；可保存或点击“放弃修改并重新读取”。版本冲突或保存响应丢失时，输入会保留，先重新读取核对服务端状态。若全局定义移除导致项目覆盖失效，页面仍保留可编辑文档；恢复全局定义或移除无效覆盖，再预览保存即可。旧会话因配置改变无法接续时，恢复原配置或另开话题，原会话与成果保留。

## 安装与启用

1. 点击“安装插件”，输入 npm 来源、Git 仓库地址或服务端本地绝对路径。示例格式为 `npm:包名@版本`、`git:仓库地址@提交`，以及本机实际存在的绝对路径。也支持粘贴 `npm install @scope/plugin` 或 `npm i @scope/plugin@版本`，系统会提取单个包来源；不接受多个包、额外参数或拼接的其他命令。
2. 阅读来源信任说明。安装可能执行 npm 安装脚本，未启用不代表代码从未运行。扩展拥有宿主用户权限，工作台没有为扩展提供系统沙箱。
3. 提交后查看操作记录。安装、更新和卸载会等待现有执行结束；等待期间新执行排队。关闭插件窗口不会取消安装。
4. 安装完成默认不启用。在详情中打开包级开关，并选择需要的包内资源。
5. 开始新的 Pi 执行，检查本次插件清单和最近加载结果。启用与加载成功是不同状态；没有实际执行过的包会显示待首次验证。

本地路径指运行服务所在电脑的路径，不是另一台浏览器设备的上传路径。本地源文件可由外部程序修改；工作台会检测执行时的内容变化，但不能将其视为不可变版本快照。

## 生效、更新与卸载

开关配置影响后续开始的执行，已运行的任务保留其环境。排队任务在实际启动时固定插件清单。更新或更换版本会等待环境可写；安装目录重叠的不同来源会被拒绝，避免覆盖另一插件。

已有执行的重试或旧会话接续需要环境兼容。出现环境变化提示时，按当前配置开始新话题，历史会话仍保留。不要通过反复重试来绕过兼容检查。

卸载会移除托管安装与工作台登记。服务端本地源只移除登记，不删除原目录。要将本地包迁移至新路径，可以先卸载旧登记，再从新绝对路径安装并启用；原源文件仍由用户管理。

## 资源支持与来源

| 类型 | 页面与运行行为 |
| --- | --- |
| 工具与事件扩展 | 支持已验证的非终端运行能力；具体包仍需实际验证 |
| Skills 与提示词模板 | 支持包内资源开关；保留既有自动发现行为 |
| 扩展命令 | 支持非交互命令；依赖终端交互的命令不能直接当作网页功能使用 |
| Pi 终端主题 | 展示资源但禁止网页启用；不会转换为工作台主题 |

“最近执行发现的 Skills 与提示词来源”展示最近10次执行的记录，每次最多500项资源和100条诊断。用户或项目自动发现的资源不受托管包开关控制；记录不是常驻加载状态。工具和资源的具体运行验证以执行记录为准。

## 失败与恢复

插件的基本确认、单行输入和选择问题会出现在对应对话的运行记录中。可同意、拒绝、提交或取消当前问题；刷新页面会重新读取仍待答的问题，关闭页面不会自动同意。重复提交返回原答复回执，不能覆盖另一页面已提交的答复。输入值不写入普通交互记录，页面提交后清空；插件收到值后的使用行为仍由插件决定。进程退出或等待到期后旧答复不转发到新任务。

运行设置中的“用户答复等待上限”控制新任务的每个问题，默认300秒，可设1秒至24小时。插件可提前结束等待，但不能超过该任务保存的上限；任务总时限仍继续计时，先到的期限生效。到期不会自动同意。修改设置不改变已有任务和重试；旧任务没有此字段时保留先前行为。独立等待状态及完整恢复体验仍在补齐。终端自定义组件和多行编辑器明确不支持，fork/newSession/reload等命令上下文还在适配，不能据此认为任意交互插件已完全兼容。

插件的普通提示、警告和错误显示在“插件通知”，带来源与时间，刷新后保留。每次运行最多保存100条，超过时另存一条说明；过长内容会明确缩短或替换，不冒称完整日志。工作台会遮盖通知中已知的交互输入值、模型凭据和传入MCP的环境凭据原文；这不等于插件沙箱，也不能保证遮盖插件自行读取或编码后的所有秘密。不要让插件通过通知输出敏感资料。

插件命令请求newSession、fork、navigateTree、switchSession或reload时，当前会明确报“不支持此会话/环境操作”，并留下错误通知，原会话不变；不会使用SDK的空实现报告成功。这些限制不代表工作台已经提供历史节点分支或会话导入入口。waitForIdle已使用原生等待实现。

多个问题同时出现时，可按任意顺序逐项答复。页面分别显示“待答问题”和“等待送达回执”的数量，未结束的问题排在历史与通知之前。局部工具等待不等于其他工具也停止了；取消整个任务请使用运行的停止按钮。

对话的运行记录可能显示“MCP连接提醒”，按服务列出本次启动收到的连接失败、需要登录等提醒。它保留当时的情况，不代表服务当前在线；到插件管理检查该服务的配置和凭据。原版只提供简略失败信息时显示通用连接失败，不猜测具体原因，也不展示可能含凭据的原始错误。当前尚未提供OAuth登录向导和实时连接面板。

| 现象 | 处理方式 |
| --- | --- |
| 等待现有执行结束 | 查看仍运行的任务；可等待或按原任务入口主动取消 |
| 请求失败但结果未知 | 保留输入并重试，页面会复用原请求；先查看操作记录，避免另建同一安装 |
| 配置已更新 | 页面重新读取配置后，确认当前设置再提交 |
| 环境需要修复 | 核对操作记录中的来源，使用修复入口；未知文件状态下新执行不会使用该环境 |
| 插件文件缺失 | 对托管来源执行修复；本地源确认原路径或按新路径重新登记 |
| 旧安装进程仍存在 | 由维护者核实进程身份及日志；不要仅凭历史 PID 终止进程 |
| 容量不足 | 根据容量记录清理确认归属的文件，保留错误记录后再修复 |
| 目录冲突 | 改用独立来源目录，或确认原包已不需要后卸载原登记 |

备份保存包声明和相关记录，不默认打包整个依赖目录。恢复后的插件禁用并标记待重新安装；恢复和会话启动不会自动联网补装。修复重新安装可能再次执行安装脚本，也不能撤销此前脚本在系统其他位置产生的副作用。
