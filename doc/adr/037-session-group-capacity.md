# ADR-037：会话组容量与单文件上限对齐

日期：2026-10-19。状态：工作区已改默认值，待部署与旧数据目录迁移说明随交付执行。来源：PIF-03、计划中“支持容量内可备份历史不得被更小门槛拒绝接续”。

## 问题

单会话文件上限为 128MiB，会话组默认上限也曾是 128MiB。近上限的有效历史可以保存和备份，但接续必须再写一份整理后的副本时，原件加副本会超过组上限，在复制前被拒绝。这不是临时测试夹具问题，而是保存、备份、恢复、接续边界不一致。

## 决定

1. 单会话文件上限保持 128MiB（`nativeSessionMaximum`），不通过降低文件上限绕过接续。
2. 默认会话组上限改为 `2 × 128MiB + 16MiB`（285,212,672 字节）：容纳一份最大原件、一份 fork 副本，以及 `nativeForkGrowth` 中的条目余量。
3. 环境变量仍为 `SESSION_MAX_BYTES`；新安装与未覆盖该变量的进程使用新默认值。已显式配置旧值的部署保持原配置，直到运维按迁移说明调整。
4. 容量不足时的 507 文案继续说明所需空间，并写明本次请求不会自动提高上限。

## 后果

- 近 127MiB 的导入在默认配额下可以 fork，并进入备份与恢复。
- 会话组占用上限提高，总数据目录默认仍为 2GiB；若目录中已有大量其他会话，仍可能在复制前被拒绝。
- 旧 ADR-004 中的“原生代理会话 128MiB”按组容量理解时应读作本 ADR；单文件 128MiB 不变。
- 自动备份会复制更多会话字节；备份盘与恢复检查仍按现有归档路径，不另开交互接续后门。

## 迁移（配置，不改写历史文件）

1. 确认单文件上限仍是 134,217,728；不要降低它来“腾出”接续空间。
2. 查看运行目录 `.env` 是否写死 `SESSION_MAX_BYTES=134217728`（或更小）。未写该变量的进程已使用新默认 285,212,672。
3. 若写死了旧值，且运维同意提高组容量：在无在途任务时改为 `SESSION_MAX_BYTES=285212672`（或删除该行以继承代码默认），再重启服务。
4. 重启后用健康/容量读数核对 `sessions` 上限为 285,212,672；已有会话文件字节与 hash 不变，无需数据库迁移脚本。
5. 若磁盘或总目录额度不足以同时容纳更多会话副本，保持旧组上限并清理/导出多余会话，而不是在请求路径自动抬高上限。
6. 本仓库 `.env.example` 已示例新值；实际部署到用户数据目录需另一次明确授权，本 ADR 不代替部署。
