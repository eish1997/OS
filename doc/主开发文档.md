当前范围已确定，不再以选择服务器或准备手机连接作为下一步。使用方式是打开这台电脑的工作台，通过对话推进项目、查看和修改成果；数据保存在本机，已有模型连接继续使用。具体接续任务与剩余验收见第 14、20 节及执行计划第 6 节。

本版明确当前交付边界：M0 是日常可用的本地工作台，M1 是在此基础上的受控并行和插件自我扩展。两阶段均在这台电脑完成；手机和云端按用户后续需要再启动。既有代码、资料、登录和模型连接继续保留，计划调整不重新建设已验证功能。

## 1 产品定义

构建一个以个人 AI 助手为统一协作入口的可扩展工作台。用户通过自然对话表达想法和需求，助手将意图转化为项目，组织工具和子代理推进工作，验证并呈现成果，将经验沉淀为可复用能力，并帮助用户制作和发布内容。

系统既承担日常工作，也帮助用户探索新方向、验证想法、发现机会。核心能力是可验证地修改和扩展自身：新增技能、接入工具、改进流程、开发界面和功能，经过验证后启用，并保留恢复路径。

长期目标是让有限的个人注意力支撑更多探索，形成持续积累的知识、工具、作品与对外影响。

## 2 用户背景与设计原则

用户不是专业开发者，主要借助 AI Agent 开发。兴趣方向多，经常从社媒发现开源项目，希望通过链接或自然描述让助手理解、试运行并接入自己的工作台。

产品应遵循以下原则：

- 用户表达目标即可，不要求提前理解专业术语或工具位置。
- 优先复用成熟组件，通过扩展集成能力，减少重复开发。
- 对话随时可用，项目成果与工作现场占据主要界面。
- 多个项目集中管理，各自拥有独立上下文和工作空间。
- Agent 操作与界面操作共享状态，完成声明必须关联真实成果。
- 文件和资产能备份、迁移、追溯，项目积累能够复用。
- 自主程度由权限、预算和验收标准约束。
- 内容输出从项目开始积累素材，并使用真实证据。
- 执行效率提升后，系统同时帮助用户管理注意力与项目优先级。

## 4 产品外在形态

### 4.1 主页与项目库

主页采用项目画廊或仓库列表，展示项目预览、简介、状态、最近活动与待决事项。支持搜索、分类、归档和创建项目。

主页包含收件入口，接收临时想法、链接、文件和日常需求。输入不完整时，助手先帮助梳理，避免立即创建大量无目标项目。

### 4.2 项目标签页

每个项目拥有独立标签页，保留当前工作现场和上下文。标签页包含目标、任务、资料、运行状态和成果，按项目类型提供合适视图。

| 类型 | 推荐视图 |
| --- | --- |
| 软件开发 | 产品预览、任务、变更、运行与测试结果 |
| 图片创作 | 素材库、画廊、编辑画布、版本对比 |
| 研究验证 | 来源、证据、实验、比较与结论 |
| 内容创作 | 素材、稿件、版本、渠道与发布状态 |

动态界面应读取统一项目数据，通过已注册操作执行动作。生成新布局时优先组合现有组件；新增可执行代码进入正常开发与验证流程。

### 4.3 随处可用的对话

对话入口可表现为底部浮动输入、快捷键、侧边浮层、对象操作入口，语音属于后续可扩展能力。

发送指令时传递当前项目、视图、选中资产或草稿及其版本。查看一篇草稿后说“修改这篇文章”，应修改当前草稿，保留来源和修改前的可追溯内容；要求新建文章时才另建。发送前处理尚未保存的本机编辑；冲突或保存失败时保留输入并说明原因。跨项目操作要明确目标对象，避免根据视觉位置猜测。当前原稿修改已通过工程和真实Pi验证，实际界面交互仍待完整验收，见[051](dev/iterations/051-selected-draft-editing.md)。

### 4.4 全局工作进展

集中展示运行中、等待用户、阻塞、失败和完成的任务。支持调整优先级、暂停、取消、恢复和查看日志。需要时展开子代理执行过程。

节点画布用于解释流程和依赖，时间线用于呈现历史；常规操作仍可通过对话完成，不要求用户手动搭建节点。

### 4.5 资产库与作品空间

资产库管理文件、来源、版本和跨项目引用。作品空间将项目证据转化为文章、短帖、图文、视频脚本等，并记录审核和发布结果。

## 5 工作闭环

### 5.1 从想法到成果

接收想法 → 明确目标与成功标准 → 搜集信息 → 制定有限投入的计划 → 执行 → 验证 → 交付 → 决定继续、调整或结束。

研究应针对相关来源开展，记录出处和时间，明确停止条件。“全网爬取”是用户愿景，实施时需要目标驱动的搜索、访问与证据筛选。

### 5.2 从成果到内容

项目启动时记录动机；执行时记录关键尝试、决策、截图和实验；结束时提炼结果、局限与用户观点。根据渠道生成内容版本，按照授权执行发布。

生成内容不得虚构用户经历、实验结果或个人观点。用户修改和外部反馈作为后续改进依据。

### 5.3 从项目到能力

已验证工具和有效方法沉淀为能力包。多个能力可以组合成新流程，例如生成图片 → 编辑图片 → 检查 → 输出。

项目合并需区分资料与历史合并、能力组合。默认保留来源关系，避免无记录地移动或覆盖资产。

### 5.4 主动发现机会

在用户指定的领域、来源和周期内收集变化，形成带依据的机会建议。主动研究、投入执行资源、对外发布分别设置授权范围。未请求持续监控时不默认启动长期后台采集。

## 6 推荐系统架构

### 6.1 产品层

负责项目主页、标签页、资产视图、动态页面、对话入口与进度展示。

### 6.2 工作管理层

负责项目、任务、优先级、依赖、预算、权限、暂停恢复和代理调度。保存系统业务状态，不依赖单次模型会话。

### 6.3 Agent 适配层

封装 Pi 的会话、消息、工具事件、执行控制和恢复接口。将执行事件转换为统一工作台事件，避免界面直接依赖社区扩展内部格式。

首版只接一个执行引擎，不提前实现多引擎系统，但保持适配边界。

### 6.4 工具与能力层

由 Pi 扩展、Skills、脚本、MCP 服务和外部应用组成。每项能力登记用途、输入输出、权限、依赖、版本与验证状态。

### 6.5 数据层

当前本机主服务保存统一业务状态和资产，Pi worker 使用独立工作目录；后续远程服务与节点复用数据契约。会话记录作为过程证据，不承担全部业务状态。详细数据归属、存储接口、同步和备份见[存储与多设备架构](存储与多设备架构.md)。

### 6.6 自我改进层

负责提出改进、创建候选版本、开发、测试、比较、发布和恢复。工作助手、开发执行与发布控制承担不同职责，可使用相同模型，但权限需区分。

## 7 Pi 与生态复用

Pi 作为 Agent 执行引擎，承担模型交互、工具调用、会话和扩展加载。它不是已经完成的项目管理产品，也不自动具备可靠自我进化。

| 组件 | 计划用途 | 状态 |
| --- | --- | --- |
| Pi SDK 或 RPC | 将 Agent 接入工作台，获取流式事件和执行结果 | 已采用固定版本 Pi SDK 与独立 worker；证据见开发现场，RPC 为后续候选 |
| pi-subagents | 委派任务和多代理工作流 | 社区候选，未选定版本 |
| 官方 MCP 支持或 pi-mcp-adapter | 接入 MCP 工具 | 先按固定 Pi 版本验证官方支持，不足时再评估社区候选 |
| Pi Skills 与扩展包 | 封装方法、工具和新增能力 | 确定采用的扩展方向 |

社区包需记录原始仓库、作者、许可证、固定版本、依赖和兼容结果。优先选单一子代理实现，避免混装同名分支。安装功能不等于取得新增权限。

模型选择通过配置实现。目标是支持用户希望使用的不同供应商模型；具体接口、认证、费用和可用性需核实。消费端 ChatGPT 或 Claude 产品的功能与模型 API 接入不可直接等同。

## 8 最小数据模型建议

| 对象 | 必要信息 |
| --- | --- |
| Project | 标识、名称、目标、验收标准、路径、状态、预算、策略 |
| Task | 项目、输入、预期输出、依赖、状态、负责人、验收结果 |
| Run | 执行标识、任务、会话、模型、环境、时间、费用、事件 |
| Agent | 角色、工具范围、模型配置、并发与委派限制 |
| Asset | 路径或外部引用、类型、来源、版本、项目与引用关系 |
| Capability | 名称、接口、依赖、权限、版本、验证与启用状态 |
| Change | 改进动机、基线、改动、评价、发布和恢复记录 |
| Publication | 素材、稿件、渠道版本、审核、授权和发布结果 |

建议使用稳定标识关联对象。文件重命名或视图变化不应破坏引用。敏感凭据独立存储，不写入普通项目文件、日志或能力包。

## 9 状态同步与执行契约

业务修改通过可记录的操作入口执行。Pi 文件和 shell 工具造成的文件变化通过独立工作区、差异扫描和资产对账接入，不能假设所有代码工具都经过业务入口。操作至少包含项目、目标对象与版本、输入、执行标识、权限上下文和结果。

任务状态建议为：待安排、运行中、等待用户、阻塞、成功、失败、已取消。完成必须存在成果或可验证的操作结果。

界面通过事件流更新，重新打开后从持久化状态恢复。需要处理重复事件、断线重连、部分失败、重复提交和过期版本。

任务重试不应重复发布内容或重复产生外部写入。对外操作需要幂等或明确检测既有结果。

资产写入完成后才登记为可用。外部变化需检测并对账。用户手动修改和代理同时修改时应检测冲突，避免静默覆盖。

## 10 多项目与多代理

主助手掌握全局目标，调度器管理持久化任务。每个项目使用独立目录、会话和必要的运行环境。

子代理接收明确任务、限定输入、预期产物和验证标准。交接使用文件或结构化结果，不能只依赖自然语言“完成了”。

设置并发数、委派深度、预算和超时。存在依赖时顺序执行，独立任务才并行。同一文件或资源的并发写入通过隔离副本、锁定或合并控制。

暂停停止安排新任务；运行中操作能否中止取决于工具。取消、恢复与部分成果处理应有明确语义。首版优先实现受控委派，再扩展代理群组协作。

## 11 自我修改与持续改进

### 11.1 可修改范围

记忆、技能、提示词、工具适配器、任务流程、界面和产品功能可进入改进流程。Agent 运行机制的修改需要更严格的回归验证。

通过模型 API 改进系统，不意味着能够直接修改供应商模型权重。

### 11.2 改进流程

1. 根据用户需求、失败记录或重复工作提出改进。
2. 建立目标、基线、验收条件和投入上限。
3. 创建独立分支或副本，保存依赖与数据版本。
4. 开发候选版本，运行针对性测试。
5. 用保留任务比较旧版与新版，检查质量、成本与回归。
6. 在授权范围内启用，通过运行记录观察实际效果。
7. 失败时恢复，并保存改进结论。

运行中的主助手应继续可用。新插件或内核版本不得直接替换正在工作的环境。

### 11.3 稳定底座

启动、版本选择、权限上限、预算约束、备份恢复和发布控制保持稳定。Agent 可以提出修改，但普通工作任务不能自行绕过这些控制。

开发候选可以生成新测试，但不能在同一次改进中擅自改变用于判定通过的既定标准。验证模型的意见只是证据之一，关键行为优先使用客观测试。

### 11.4 评价方式

软件看运行行为与测试；研究看来源支持和不确定性；图片看规格、可用性与用户选择；文章看事实依据、表达偏好和审核反馈。

不存在能统一可靠判断所有任务的单一总分。评分需要展示维度、依据和未验证项。审美与观点保留用户最终判断。

## 12 开源项目接入流程

输入链接 → 检查用途、许可证、依赖与运行条件 → 建立隔离试验 → 最小运行 → 目标验证 → 封装适配 → 登记能力 → 接入视图 → 维护与升级。

记录版本、安装方法、环境、费用、凭据需求与失败情况。开源项目可能通过 CLI、SDK、HTTP 或 MCP 调用，不默认将所有源码合并进工作台。

## 13 视觉设计基线

## 15 首版边界

首版目标是一个完整可用的闭环，不承诺全能、全网无边界采集或无限递归自我进化。阶段细分以第 20 节的 M0、M1 为准，可靠执行是自我升级的前置条件。

M0 优先实现：项目库、标签页、上下文对话、Pi 单执行 worker、真实文件成果、状态同步、素材记录、文章草稿与导出。M1 增加有限子代理与一次受控插件自我升级。

后续实现：手机和远程连接、云部署、跨机迁移、异地恢复、独立桌面包装、全面动态页面、长期机会监控、多平台自动发布、复杂代理群组与运行内核自动优化。

## 19 产品成功标准

系统是否成功，主要看想法是否更快得到验证，项目是否能持续推进，成果是否可信，切换方向能否恢复，能力是否复用，作品是否值得用户署名，以及用户是否更容易决定下一步。

工具数量、代理数量和自我修改次数仅是运行指标，不能代替实际工作价值。

## 20 五项审查后的开发约束

本节整合产品、Pi、数据、自我升级和执行审查。如与前面原则性描述存在差异，以本节具体约束为准。以下为整合后的开发建议；不把代理提出的方案自动记为用户已确认决策。

### 20.1 首版价值与交付门槛

建议以“输入一个开源链接或资料 → 形成验证目标 → 运行有限实验 → 展示真实成果 → 形成可追溯结论与文章草稿”为产品黄金路径。隔离执行未就绪时，只进行资料分析，不自动执行未知代码。

工程验收使用固定本地样例，避免外部来源变化使结果不可比较；真实使用验收另选一个实际开源项目。两者分别保存证据，工程样例不能替代真实价值验证。

| 里程碑 | 必须交付 | 暂不纳入 |
| --- | --- | --- |
| M0 本地可靠单任务闭环 | 桌面启动入口、项目画廊/标签页、上下文对话、一个执行 worker、真实资产、持久事件、中断识别、记忆/摘要、素材记录、文章编辑导出、本地备份恢复 | 手机/远程部署、子代理群集、自动发布、任意动态代码页面、自我修改运行内核 |
| M1 本地受控扩展闭环 | 两个 worker 受控并行、结构化交接、一个可卸载图片对比插件、验证启用与恢复 | 多端资源前置、不可逆数据迁移、无限递归委派、自动内核优化 |
| R 后续多端 | 真实手机/不同网络、HTTPS、远程节点、跨机迁移和异地恢复 | 用户已延期，当前不实施或伪报通过 |
| 后续持续成长 | 动态视图、机会监控、渠道发布、失败驱动改进与复杂代理协作 | 每项能力另立验收与权限范围 |

本地 M0 必须通过本地工程闭环、实际使用反馈、中断识别、资产对账与干净目录恢复，才开始 M1；R 阶段不阻挡本地 M0/M1。内容素材和草稿属于 M0。腾讯组件的独立运行实验保留未验证状态，不以资料研究宣称组件效果。

### 20.2 日常任务、记忆与标签页行为

日常任务允许在个人空间直接完成，只有需要持续推进、保存运行环境或组织成果时转成项目。收件项记录原始输入、处理状态、产物和关联项目。

记忆分为个人明确偏好、项目背景、已验证方法、临时上下文和待确认推断。记录来源、时间、适用范围及修订关系，支持查看、纠正、删除与停用。一次性要求默认限于当前任务；外部网页是资料，不能变成权限或执行政策。技能提炼进入候选验证流程。

每条指令发送时冻结 ContextBinding，包括 projectId、选中对象、资产/草稿版本和视图。草稿修改先保存本机编辑，再由宿主核对版本并记录任务输入；Agent 只可修改此次绑定并获授权的对象。执行期间用户另行修改导致版本冲突时，保留双方内容，不静默覆盖。切换标签页不改变已启动任务的归属。全局、当前项目和跨项目指令显示明确作用域；后台成果回到原项目，通过轻量通知提示。

初期“合并项目”实现为新建组合项目、引用原资产和固定能力版本，保留原项目与历史；物理历史合并后续设计。动态视图需要版本、布局保存和默认视图恢复，更新页面不丢失当前选择。

### 20.3 Pi 执行宿主与接口

阶段一必须形成技术决策记录，确定 SDK 或 RPC、后台执行宿主、进程与 session 数量、崩溃影响和资源限制。前端不持有模型密钥、不加载执行扩展。

固定 Pi 发布版本、源码 commit、运行时、shell 和依赖锁。官方 main 文档仅供参考，不作为已安装版本的接口保证。当前官方 SDK 文档含 MCP 扩展接入说明，先验证固定版本接口，避免重复安装社区 adapter。

Project、Task、Run、Pi Session 与进程分别建模。SessionBinding 保存业务标识、Pi session 标识、会话路径、worker、cwd 和运行版本。会话恢复使用 Pi 会话管理接口；重新打开标签页不重跑任务。

消息接受、模型文本完成和底层 agent_end 都不能直接代表业务成功。适配层按固定版本识别最终停止状态，再运行验收。当前 SDK 文档描述 agent_settled；实际接入时以该版本声明和测试为准。

原生编码工具在开发目录运行，文件变化经扫描、Git 差异和登记后成为资产。结构化业务工具走操作网关。cwd、分支和 worktree 只提供逻辑隔离；OS 权限、网络和凭据边界另行实现。

候选技能、可执行扩展、工具适配器与页面组件分别声明类型。生产资源加载使用明确白名单，不能自动发现开发副本中的候选代码。每次 Run 固定能力快照，升级使用新 worker，在途任务继续旧版本。

### 20.4 数据权威与一致性

业务状态存储是任务和关系的权威；资产内容采用不可变版本；界面是两者的投影。聊天文字不能直接改变成功状态。

资产写入采用暂存、校验、原子提交和登记；文件与数据库之间使用持久操作日志和对账，不承诺跨文件系统的单一数据库事务。启动时恢复或隔离未完成写入。外部手工修改导入新版本，不覆盖旧版本。

在第 8 节对象基础上补充：

| 对象 | 用途 |
| --- | --- |
| AssetVersion / AssetReference | 内容哈希、父版本、来源 Run、引用范围；任务固定输入版本 |
| Operation | 一次动作的持久意图、输入摘要、状态、外部回执和幂等键 |
| ContextBinding / SessionBinding | 对话作用域与 Pi 执行会话映射 |
| Memory / InboxItem | 连续记忆与轻量输入生命周期 |
| Grant / Policy | 版本化授权、数据外发和预算限制 |
| EvaluationSuite / Release | 固定评价、构建摘要、激活和恢复依据 |
| BudgetEntry | 预算预占、实际消费、释放和估算来源 |

文件重命名不改变资产身份。删除项目先检查跨项目引用，不能误删其他项目仍使用的成果。整体备份与项目导出包含引用依赖、schema 和校验清单；凭据默认不导出。

### 20.5 状态、事件与副作用契约

Task 表示目标；Run 表示一次尝试；Operation 表示具体动作。验收状态独立记录为 pending、passed、failed 或 needs_review。Run 完成不意味着 Task 验收通过。

Run 使用 queued、running、waiting_user、completed、failed、cancelled、interrupted 等状态。取消请求与实际取消分别记录；暂停默认停止后续调度，不承诺撤销正在发生的副作用。状态转移表必须在实现前确定，迟到事件不能把终态改回运行中。

重试创建新 Run，记录 parentRunId 和 attempt。失联或崩溃先进入中断及对账流程，确认已有产物和外部结果，再决定恢复方式。

命令至少带 commandId、projectId、runId、目标 revision、输入版本、幂等键和策略版本。事件带 eventId、schemaVersion、runId、对象 revision、sequence、关联标识和时间。采用至少一次投递、去重、对象顺序校验；快照附游标，重连重放增量，过期时重新加载快照。

外部写入先保存意图，后保存回执。响应丢失时进入 unknown，查询或人工核实，不盲目重发。不能查询也不支持幂等的服务无法承诺绝不重复。事件重放只恢复状态，不再次执行外部动作。

### 20.6 调度、预算与后台生命周期

主助手提出计划，唯一调度服务取得执行租约后启动 worker，防止双击、双实例和重启重复执行。首版不需要分布式调度，但需要持久队列、所有者、心跳与租约失效。

建议 M0 一个 worker，M1 全局最多两个 worker、每项目最多一个写入 worker、子代理委派最多一层。具体参数是可调整配置。优先级先影响排队任务，不实现自动抢占正在运行的任务。

父子任务共享预算上限，调用前预占、调用后结算，重试与系统改进单独可追踪。费用不可得时使用 token、调用数和估算预留限制，不把未知费用记为零。

M0 的默认保护以 Task（同一目标）为范围，同一 Task 的所有 Run 共享累计调用上限和 API 费用上限；失败、取消、已对账中断后重试不重新发放额度。Run 保留单次尝试的用量明细；已预占、已消费和结果未知的请求不因新尝试消失。新建独立目标可取得默认任务额度，但仍受已启用的连接累计限制和 API 总预算约束，不把自动拆分目标用作绕过上限的方法。ChatGPT 订阅用量与 API 美元费用分别核算，不把订阅请求折算为已知 API 费用。

该范围是交付要求，056曾发现 L-03c 缺陷：限制2次的同一目标在重试后累计准入3次，见[宿主复现](../output/dev-evidence/task-budget-056-before.json)，没有真实供应商请求。057宿主修复及正常应用已完成，见[记录](dev/iterations/057-task-budget.md)；保留历史用量、原始任务输入与来源，无须用户补填配置或重新连接。M1 的父子共享额度在 M1 另行验证，不能以修复 M0 重试计数宣称已实现代理群集预算。

子代理交接包含任务、项目、输入版本、允许工具、工作目录、截止时间、预算、产物 schema 和验收标准。必需依赖失败阻塞后续，可选分支失败允许标明局限的部分交付。父任务取消向子任务传播，记录实际停止结果。

当前关闭项目标签页不停止本机后台任务；电脑关机、休眠或后台退出会影响执行，恢复时进入中断对账。后续远程服务在线时，关闭手机或电脑页面不停止远程任务；电脑节点不可用时专属任务等待节点或中断对账。节点恢复后先核实租约、产物和外部结果，不能仅凭持久记录显示“运行中”或自动重复动作。本地节点保活行为需明确设置。

每个 Run 登记进程树、端口、运行环境和资源所有权。结束或取消后清理资源。诊断入口展示认证、网络、worker、扩展、队列、磁盘和预览服务状态，并提供脱敏日志导出。

### 20.7 自我升级的发布协议

首次升级限定为只读图片对比插件：读取真实图片、形成可登记的比较结果或声明式视图，无业务 schema 迁移、无新增外部凭据。界面与 Agent 调用同一个 compare 操作，不能只生成截图。

授权绑定主体、项目范围、操作、能力版本或摘要、有效期、预算与委派许可。子代理获得父授权与自身权限的交集。符合既有授权的低风险更新可自动启用；权限增加不得继承旧版授权。

候选 manifest 保存来源、锁文件、安装脚本、构建摘要、API 版本、权限、运行环境与验证报告。下载、安装、试运行、注册和启用分别记录；安装脚本在候选环境执行。生产不自动追踪 latest。

Change 状态为 proposed → building → validating → validated → activating → active，另含 rejected、failed、rolled_back。发布控制使用唯一锁，核对当前基线，候选过期则合并后重验。

启用按“启动新环境 → 健康检查 → 切换运行版本指针 → 保留旧版”执行，中断后应能识别完整旧版或完整新版。候选不得访问生产密钥、发布控制或唯一备份。未验证权限隔离时只允许受限的展示型扩展实验，不运行未知高权限代码。

每次升级声明无迁移、向后兼容迁移或不可逆迁移。初期禁止自动不可逆迁移。代码恢复、数据恢复与外部补偿分别记录；恢复不能删除升级后的无关用户成果，也不能声称撤销已发生的外部发布。

EvaluationSuite 固定测试版本、不可退化项、比较规则和成本上限。开发样例与保留评价分离，候选不能改写判定标准。模型评价记录配置、证据与不确定性；不以一次自评分作为启用依据。

自动改进设置每日预算、最大候选次数、冷却和停止条件，合并重复问题。首版用户明确需求触发代码修改；重复失败先产生诊断与建议。上线观察实际成功、成本和用户修正，异常时停用或恢复。

### 20.8 数据与权限边界

跨项目读取、外发模型或工具的数据、凭据注入和发布权限由宿主执行层检查。全局助手能索引哪些内容也需要明确范围，不能因为“全局”就读取全部秘密。

密钥不进入提示词、日志和普通导出。外部资料中的指令不能改变授权。定义会话、截图、索引、记忆和备份的保留与删除行为，删除后停止检索并说明备份留存范围。

OS 权限隔离、路径校验和网络策略必须通过测试。普通工作目录不能充当该测试的替代品。实现复杂度按启用能力分阶段增加，不能为赶进度把权限检查降为提示词约束。

### 20.9 验收证据与测试剧本

验收包包括固定输入、真实输出、事件、环境版本、验证报告、失败注入结果和用户反馈，不能只有概念图或 Agent 自评。

下表单 worker、资产、权限和恢复场景用于当前 M0；子任务、真实并行竞争和插件激活/恢复属于 M1。实际发布渠道属于后续阶段，M0 仅用受控故障端点证明 unknown 与对账契约。手机/远程场景按第23节单独验收，不能混入本地通过数。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 固定资料生成图表与短文 | 程序计算的数据一致，文件真实存在，草稿有素材引用 |
| A 发令后切换 B | 任务继续属于 A，结果回到 A，B 上下文未混入 |
| 重复提交与断线重连 | 不重复业务动作，事件去重，恢复后状态一致 |
| 写文件或登记期间强制退出 | 未完成资产不伪报成功，启动对账可恢复 |
| worker 崩溃与重试 | 标记中断，保留部分结果，创建新 Run |
| 取消长任务与子任务 | 请求和实际停止可区分，残留进程和端口可定位 |
| 外部响应丢失 | unknown 并对账，不能盲目重复发布 |
| 并行写入与预算竞争 | 冲突被检测，预算预占不超父上限 |
| 未授权跨项目访问 | 执行层拒绝，凭据不出现在请求与诊断包 |
| 新插件启用与激活中断 | 基线与构建可追溯，完整版本切换，无半升级状态 |
| 插件恢复与备份恢复 | 旧项目、会话和新成果可读，干净环境可恢复 |

Windows 首轮固定一种运行环境，再测试中文及空格路径、CRLF、文件占用、进程树取消、端口释放和睡眠唤醒；原生与 WSL 的路径及凭据不能混用。社区子代理必须在非 TUI 的选定 SDK/RPC 模式下验证。

用户验收记录目标到首个可验证成果的时间、澄清次数、人工介入、恢复成功与是否愿意再次使用。先建立基线，再设改善目标。

## 22 开发语言与技术组合

本节记录推荐技术方向，作为原型开发默认方案。具体版本、库、打包方式和兼容性在阶段一验证并形成技术决策记录；本文更新不代表已完成工程验证。

### 22.1 主语言

核心系统使用 TypeScript，覆盖界面、业务接口、任务调度、Pi 集成和自研扩展。Python 作为按需调用的工具语言，用于数据分析、图片处理或接入相关开源项目。

选择依据：Pi SDK 提供直接 TypeScript 接口；前后端可共享接口类型；类型检查有助于在运行前发现部分接口错误，降低 Agent 修改系统时的衔接成本。类型检查不能替代运行测试、权限检查和数据恢复验证。

### 22.2 推荐组件

| 部分 | 推荐技术 | 职责与边界 |
| --- | --- | --- |
| 主语言 | TypeScript | 核心产品与扩展开发 |
| 界面 | React | 项目标签页、画廊、画布、编辑器与动态视图 |
| 执行后台 | Node.js + Pi SDK | 独立 worker 内管理 Agent 会话、工具与事件 |
| 状态存储 | 本机后台管理的 SQLite | 单服务写入保存统一业务状态；多实例写入需求出现时评估 PostgreSQL |
| 资产内容 | 本机文件库与统一存储接口 | 版本化资产；后续可接对象存储，节点本地产物经校验上传登记 |
| 当前界面/后续多端 | React Web | 当前打磨电脑界面，保留响应式能力；真实手机接入后续 |
| 桌面客户端 | Electron，后续 | 电脑端增强入口，业务状态仍来自主服务 |
| 外部能力 | Python 脚本、服务及其他语言组件 | 通过 CLI、HTTP、MCP 等接口接入，不要求重写源码 |

优先采用 Pi SDK，具体调用和事件接口按固定版本验证。SDK 运行在后台执行进程，不能直接加载在界面进程。RPC 作为跨语言或不同进程管理需求下的备选，不提前维护两套完整执行实现。

当前本机 Node.js 后台与 Pi worker 独立于页面生命周期，无须另配远程节点。Electron 是后续包装选择，保留后续远程入口的兼容性。独立进程不等于 OS 安全隔离，具体运行边界按第 20.6 节及存储架构文档实现。

### 22.3 开发顺序

以下是总体建设顺序，前几步已有实现。接续开发按第 14 节和执行计划第 6 节选择剩余任务，不从初始化重新开始。

1. 建立 TypeScript 项目、共享接口与类型检查。
2. 完成本机服务、登录保护、React 电脑页面和本机 SQLite/资产库，不引入手机或云资源前置。
3. 在本机独立 worker 接入 Pi SDK，完成 M0 真实执行、资产、事件同步、文件成果、文章草稿和本地恢复。
4. 验证中断、恢复与权限边界，再接入受控子代理和插件升级。
5. 核心稳定后评估 Electron 包装；多端、远程节点和云部署按后续 R 阶段独立验收。

本地开发环境默认仅绑定回环地址。当前通过业务 API 和存储接口保留后续迁移边界，不提前建设云服务、同步引擎或分布式调度。R 阶段启用远程访问时使用 HTTPS 和统一认证，数据库、Pi RPC、worker 和节点控制接口不得直接暴露给浏览器。实际购买资源、公开上线和部署仍需对应任务授权。动态页面优先组合可信组件。

### 22.4 跨语言能力接入

工作台不强制所有能力使用 TypeScript。Python、Rust 等项目保留自己的依赖和运行环境，通过明确输入输出接口调用。

每项外部能力记录版本、环境、超时、取消、错误和产物契约；命令执行使用结构化参数，避免把用户或模型文本直接拼成 shell 命令。外部组件复用同一任务、资产与权限管理规则。
