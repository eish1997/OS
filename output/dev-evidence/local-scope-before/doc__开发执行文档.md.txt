# Agent 开发执行文档

版本：0.5 首个验证项目版  
日期：2026 年 10 月 5 日  
状态：开发流程规范；2026-10-06 已获用户授权并启动工程，M0 尚未验收。当前进展见[开发现场](dev/current.md)与[台账](dev/backlog.md)。

本文规定开发 Agent 如何持续推进个人 AI 工作台，从恢复现场、选择任务到实现、验证、记录和进入下一轮。产品范围与技术方向以[主开发文档](主开发文档.md)第 20、22 节为依据。本文描述的是开发工作台的循环；产品运行时的任务与代理调度是另一套业务机制。

文档编写与审查本身不授权产品实现、付费调用、发布或部署；后续用户已明确授权“按执行文档开始执行并完成”。工程按该授权推进，不为普通可逆步骤重复请求许可；缺模型/预算或部署信息的实际验证仍需对应外部条件，不能用离线测试替代。

## 1 执行目标与边界

当前推荐 TypeScript、React、Node.js、Pi SDK 和 SQLite，后续包装 Electron。先完成 M0 真实单任务闭环，再完成 M1 受控并行与可卸载插件升级。

部署采用远程主服务＋电脑本地执行节点，电脑与手机共享状态和资产；具体规范见[存储与多设备架构](存储与多设备架构.md)。SQLite 位于单服务端，节点和浏览器通过 API 访问。先本地复现远程服务结构，再在对应部署授权下完成真实双端访问。

界面实现与视觉复核遵循[设计规范](design.md)中的 Factory + ASCII 规则，旧概念图不作为当前组件规范。

每轮交付一个能验证的小能力或明确的诊断结论。代码、测试、记录应形成闭环。不能把建立目录、编写计划、截图或模型自评当作功能完成。

遵守用户当前指令、适用 AGENTS.md 与平台约束。主开发文档定义产品，执行文档定义流程，技术决策记录定义已验证的实现选择。冲突先定位，再在已有授权内解决；涉及产品范围改变时保留待决项。

## 2 开发记录

下列路径是开发启动后按需创建的建议，当前不表示文件已存在。路径均相对仓库根目录。

| 路径 | 内容 |
| --- | --- |
| doc/dev/backlog.md | 持久任务台账、依赖、验收、状态、证据与遗留项 |
| doc/dev/current.md | 当前任务、现场、下一步、工作区和最后验证 |
| doc/dev/iterations/ | 每轮事实记录与失败诊断 |
| doc/adr/ | 版本、接口、环境与重要取舍的决策记录 |
| output/dev-evidence/ | 测试输出、截图、运行事件和固定输入等证据 |
| .env.example | 配置名称和说明，不含密钥 |
| 实际依赖锁文件 | 固定已采用版本 |

开发台账是进度依据，代码和证据是完成依据。只维护一份权威 backlog，current 是恢复摘要。记录不能包含凭据或原始敏感数据。

任务至少记录 ID、里程碑、目标、来源、范围、依赖、验收、验证方式、状态、所有者、证据、阻塞原因、下一步。状态为 todo、ready、doing、verifying、done、blocked、cancelled。进入 done 时必须有当前代码对应的通过证据；后续基线变化保留历史完成事实，并标记当前证据有效性。阶段尚未验收时不宣布里程碑完成。

台账转移：todo 在依赖、授权和输入就绪后进入 ready；协调者认领 ready → doing；实现可验证后 doing → verifying；验收与复核通过后 verifying → done。验证失败 verifying → doing，保留唯一主任务；只有明确外部阻塞才转 blocked 并释放主任务，恢复条件满足后 blocked → ready。取消记录理由。需要改行为时可 done → doing；仅旧证据失效时另建重验任务，保留历史通过事实。

每次失败保存 failureId、原因假设、attempt、证据、修复依据和结论。同一原因的三次尝试跨会话累计；新证据推翻原假设时记录关联并新建诊断，不能通过重命名错误重置计数。任务的历史完成与当前证据有效性分别记录，阶段验收只采用当前基线有效的证据。

## 3 每次启动先恢复现场

1. 阅读适用指引、本执行文档、主文档相关章节和已有开发记录。
2. 检查目录、Git 状态、现有改动、运行服务与最近测试。仓库尚未初始化时记录事实，按开发授权决定是否建立，不假定存在分支或提交。
3. 保留用户或其他 Agent 的改动，不执行破坏性清理或恢复整个工作区。
4. 核对 doing 任务：实际产物、后台进程、最后验证是否仍有效。中断后不能直接标成功，也不能盲目重跑有外部副作用的动作。
5. 确定本次目标、可用模型配置、资源和授权，记录开发验证的模型调用数、token/费用上限与超时；已有授权不重复确认。缺配置或费用授权时继续离线工作，仅阻塞相应真实调用。012用户要求免配置：完成带订阅用量权限的OAuth后自动选择可用模型、使用宿主按任务默认保护，不要求额外填写次数或重复确认；原API费用授权和外部发布边界保持。开发验证成本与产品运行预算分别管理。
   2026-10-06接入补充：可用模型认证可以是API密钥，也可以是经用户明确授权的ChatGPT plan usage OAuth，不预设必须充值API。认证方式、实际用量与美元价格估算分别记录；没有供应商硬输出上限时不宣称本地参数能保证其额度上限。实施与验收见[接入与上线解决计划](dev/接入与上线解决计划.md)，原M0/M1门槛不改变。
6. 更新 current，给出简短进展说明，进入循环。

## 4 核心开发循环

每轮按 Observe → Select → Define → Implement → Verify → Review → Record → Continue 执行。进入下一步需要满足对应条件。

| 步骤 | Agent 行动 | 退出该步骤的条件 |
| --- | --- | --- |
| Observe 观察 | 读取实际代码、状态、错误和记录 | 知道当前问题及可信证据 |
| Select 选择 | 选择依赖就绪且属于当前里程碑的任务 | 有唯一主任务与范围 |
| Define 定义 | 确定输入输出、验收、影响与验证命令 | 验收可观察，风险与前置明确 |
| Implement 实现 | 完成最小贯通改动，复用现有组件 | 功能及必要错误路径可运行 |
| Verify 验证 | 类型检查、相关测试、真实运行和必要视觉检查 | 有通过证据或具体失败 |
| Review 复核 | 查看差异、需求覆盖、权限、状态和回归 | 没有未处置的阻塞问题 |
| Record 记录 | 保存证据、台账、决策与恢复摘要 | 后续 Agent 能接续 |
| Continue 继续 | 选下一个 ready 任务或处理失败 | 继续条件成立，或进入明确等待/结束状态 |

伪代码：

```text
恢复现场
while 当前目标未达到且仍有授权与资源:
    核对用户最新指令和当前改动
    重新计算依赖、证据与授权就绪状态
    优先恢复唯一 doing/verifying 任务，否则选择依赖就绪的最小任务
    若没有可执行任务:
        诊断依赖；记录阻塞；保存现场
        break
    锁定该任务验收与验证计划
    实现最小改动
    运行适当验证
    若失败:
        记录 failureId 与累计尝试；verifying 回 doing，保留任务
        若确属阻塞，则标 blocked、记录恢复条件并释放任务
        continue
    复核差异与验收
    若复核发现未处置问题:
        按失败处理回 doing 或 blocked；保存现场
        continue
    保存证据并更新台账为 done
    若里程碑任务全部完成且没有失效证据或未结缺陷:
        执行里程碑端到端验收
        若验收失败:
            建立或重开关联缺陷任务，失效受影响证据
            保持里程碑未通过；保存现场
            continue
        若缺真实使用证据或必要用户反馈:
            标明阶段待验收，不进入依赖该阶段的开发
            记录等待项；若无独立 ready 任务则保存现场并 break
    更新恢复摘要
报告真实交付与未完成事项
```

## 5 任务拆分与选择

优先修复当前闭环的阻塞问题，再推进依赖就绪的功能。一个任务尽量贯通接口、真实状态和用户可见结果，避免先搭建全部抽象层再证明价值。

无法在一轮验证的任务继续拆分。验证方案复杂可以先做接口探索任务，但探索的完成仅说明获得结论，不能替代功能交付。

技术信息易变化时读取固定依赖版本的官方文档、类型和源码。尚未固定版本时比较候选并建立 ADR。禁止仅凭 main 文档中的接口假定本地包可用。

组件 ADR 记录包名、作者/原始仓库、许可证、固定版本与 commit、接入模式、兼容性证据。读取资料不等于允许安装；候选记录安装脚本和权限，生产加载采用白名单。

## 7 验证策略

每个任务先明确验收，再选择最低成本但足以证明行为的验证。

- 类型与静态检查验证接口约束。
- 单元测试验证重要状态转移和算法边界，避免只镜像实现。
- 集成测试验证数据库、文件、worker 与接口。
- 真实模型任务验证 Pi 与工具执行，不以 mock 代替。
- 浏览器检查验证交互、标签归属、视觉与错误呈现。
- 故障注入验证重连、中断、取消、重复提交与恢复。
- 发布测试仅在明确授权的测试出口进行。

测试和构建命令来自实际 package scripts。尚未建立 scripts 时先定义命令再执行，不伪造工具或声称未运行的检查通过。

证据记录命令、环境版本、时间、退出码、摘要、产物和代码标识。Git 不存在或未提交时记录文件摘要；重要改动后旧证据失效，重新执行受影响检查。

证据失效按被修改的模块、共享契约、依赖版本和覆盖场景判断，记录影响分析。行为已变则重开关联实现任务；行为未变但基线需确认则新建重验任务。不能删除历史证据，也不能把历史通过误报为当前通过。

常规改动完成针对性验证后不无理由重复全套。阶段门槛必须运行端到端测试，覆盖主文档第 20.9 节相关场景。视觉验收使用真实运行截图，概念图仅作为设计参考。

## 8 失败诊断与修复

失败先分类：需求不清、接口不兼容、实现错误、环境配置、外部服务、权限、预算、未知副作用。保存最小错误与复现条件，不输出秘密。

同一原因默认最多三次有不同依据的修复尝试；无新证据时停止重复调用，改用最小复现、官方资料或另一方案。该上限限制无效策略，不要求放弃仍可推进的其他任务。

修复不得通过删测试、放宽权限、吞异常或虚报成功达标。确有需求变化时记录变更和新的验收，不把旧失败抹掉。

遇到缺配置、服务不可用或必要输入，记录具体阻塞与恢复办法，继续独立 ready 任务。外部动作结果未知先对账，禁止自动重复。所有任务都无法推进时保存 current，并清楚说明需要什么输入。

预算或费用授权缺失属于真实调用前置阻塞，不反复尝试调用、轮询凭据或用忙循环等待。收到配置/授权或预算变化后重新核对再恢复。准备中的离线任务可以继续，但不能为填满循环扩大当前里程碑范围。

## 9 复核、协作与变更控制

开发 Agent 在每轮查看 diff，确认改动属于任务、没有覆盖别人工作、没有新增隐含权限或依赖。涉及状态机、持久化、权限、发布与恢复的变更需要对应负面场景验证。

多 Agent 开发须有用户或适用指引授权。协调者持有台账写入权，子 Agent 接收独立任务与允许修改路径；共享文件串行修改。子 Agent 提交产物、测试和未解决项，协调者重新核对集成结果。

评审意见按“问题 → 证据 → 处理 → 验证”记录。发现问题不等于必须增加首版功能；区分必须修复、后续阶段和不采纳，并说明原因。

普通开发循环不能自行修改运行中的稳定底座、扩大授权、部署或对外发布。自我升级实验按主文档第 20.7 节实施。Git 提交或推送遵守用户授权，不为保存现场自动推送或创建发布。

## 10 结束、等待与恢复

继续循环：仍有授权内 ready 任务且资源可用。不要每完成一个小任务就结束等待用户说“继续”。

达到本次目标：任务和阶段验收均有证据，遗留问题说明清楚，再交付。若用户只授权单个任务或探索，以该任务验收为结束条件，同时明确里程碑尚未完成，不要求越界开发整个阶段。
用户暂停：保存现场并停止安排新工作，按要求处理在途操作。
缺必要输入：提出具体问题，继续独立工作；依赖工作等待真实答复。
资源或平台限制：保存现场，记录已用资源和下一步，不宣称完成。
全部阻塞：列明阻塞事实、已尝试与恢复条件，结束当前开发回合。
上下文压缩或新 Agent 接手：先读取 current 和 backlog，对照实际文件与进程再恢复。

后台资源记录 PID、启动时间、cwd、命令摘要、服务实例 ID、健康检查地址、所属 Run 与所有者。连接或清理前核对这些身份；PID/端口单独不能证明归属，未知资源只诊断、不强停。离开开发回合时列明停止、获准继续和等待对账的任务，以及清理/恢复命令；产品后台继续权限不等于开发工具获准永久运行。

涉及平台 goal 工具时遵循其状态规则；开发台账 blocked 不等于自动将平台 goal 标为 blocked。

## 12 启动指令模板

后续授权开发时可使用：

> 阅读 doc/主开发文档.md、doc/开发执行文档.md 和适用仓库指引，恢复已有开发状态。围绕指定里程碑执行观察、选任务、定义验收、实现、验证、复核、记录和继续的循环。每轮完成最小可验证能力；失败按证据诊断，不扩大权限或降低标准。缺少模型配置时继续离线可推进任务，但不宣称真实运行通过。达到里程碑验收或遇到真实无法推进的阻塞时，保存现场并报告。

指令中的“指定里程碑”必须来自用户当前任务；没有指定时按已有开发授权选择最早未完成里程碑，不自动扩展到全部长期愿景。

## 13 文档验收

本执行文档的验收是两个独立审查、一个优化 Agent 和主 Agent 复核，检查范围一致性、循环可执行性、失败恢复、证据真实性和引用有效性。该验收不代表产品代码测试通过。

本版根据[循环与恢复审查](reviews/开发执行审查-loop.md)、[架构与验收审查](reviews/开发执行审查-architecture.md)修订，逐项处置见[优化记录](reviews/开发执行优化记录.md)。正式文档验收结论由主 Agent 复核后记录；优化完成不自动代表复核通过。

主 Agent 最终复核已完成：核对了主文档一致性、任务依赖、阶段门槛和本地链接，并补齐无任务退出、复核失败回流及旧证据失效的明确规则。当前版本通过文档验收；Pi 接口、实际测试命令和所有工程行为仍待后续开发验证。
