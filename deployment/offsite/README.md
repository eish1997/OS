# 加密转存与干净恢复：待云端验收

这是部署Agent操作入口。日常用户无需填写存储端点或模型参数；当前主服务未配置云桶，未上传真实资料，也未重启加载自动转存。040已经接入可选自动流程，并以本地crypt合成资料验证，不能算真实异地备份。[040记录](../../doc/dev/iterations/040-automatic-offsite-backup.md)

## 已有实现

[CLI](../../scripts/offsite-backup.ts)使用固定[rclone版本锁](../rclone-lock.json)与[转存模块](../../server/offsite-backup.ts)。复用rclone crypt加密内容、文件名和目录名；配置中的obscure只是可逆遮盖，配置和密码/盐必须单独保护。[官方加密说明](https://rclone.org/crypt/)、[obscure说明](https://rclone.org/commands/rclone_obscure/)

只接受已通过verifyBackup的普通联合备份。先把manifest及其列出的文件复制到私有工作目录，忽略额外凭据/.env/自动备份回执。使用固定恢复点UUID，copy到专用crypt路径，再完整下载解密并核对所有SHA256；通过后最后写入加密offsite-commit.json并读回确认。恢复要求该提交记录、相同清单哈希与文件数，之后才在新目录恢复业务库/资产/原生会话。[copy语义](https://rclone.org/commands/rclone_copy/)

当前不使用sync、purge或云端删除，不自动覆盖或回退为明文。客户端copy/immutable不等于对象存储不可删除，也不替代厂商权限、锁定/版本和账号保护。来源不变，失败残片没有有效提交记录，不能算作恢复点。重试同ID先检查远端提交记录：相同内容完整读回，不新建恢复点；不同内容拒绝。只有rclone明确返回不存在（退出码3/4）才允许继续上传，网络/认证错误保持待确认状态。已有对象按大小跳过后仍完整解密核对SHA256；不能因为CLI未成功返回就删除云端内容。[退出码](https://rclone.org/docs/)

## 可选自动调度

本机备份通过恢复检查后，固定转存ID写入来源回执并一起提交；未确认副本不参与轮转。转存确认原子替换回执后才允许后续轮换。失败不抹去本机成功，等待副本可能超出保留数量，空间不足停止新增。历史未带转存ID的副本不自动外发。

独立租约和后台进程执行转存，不占用Agent执行租约。启动及后续轮询继续处理原编号；停止/租约失效先取消自有rclone并等待后台退出。三个部署路径由Agent同时配置，没有HTTP配置表，未配置就关闭：

```text
OFFSITE_BINARY=<固定rclone绝对路径>
OFFSITE_CONFIG=<独占权限的配置文件绝对路径>
OFFSITE_WORK_DIR=<私有临时工作目录绝对路径>
```

Linux[环境模板](../linux/workbench.env.example)三项保持注释，[服务模板](../linux/workbench.service)准备独立0700状态目录。配置必须在普通业务备份之外；默认模板未接入任何真实桶。

## 暂存归属与中断恢复

041新增[工作目录记录](../../server/offsite-work.ts)，绑定绝对路径、随机所有者ID和配置摘要。首次仅认领新目录或空目录，不接管已有未标记内容。040留下的未标记工作目录须由Agent核对后选择新的空工作目录，禁止直接补标记并清空。改变配置需要新的工作目录，旧材料保留。

每份暂存记录恢复点ID、操作、是否可回收、宿主PID及传输启动阶段。启动前先记录launching，实际spawn后记录传输PID，收到真实close后才恢复idle。重启只回收本机专用工作目录中、标记匹配、可回收的upload暂存，并要求旧宿主与已记录的传输PID都明确不存在（ESRCH）。PID仍活、权限无法检查、launching窗口无法确认、记录损坏、链接、归属不符及CLI材料全部保留。不会根据记录PID杀进程。

工作目录必须是单主机、同PID命名空间的本地暂存，不能放在跨主机共享目录或共享容器卷；PID不存在只对当前主机/命名空间有意义。这是部署约束，当前模块未验证远程文件系统类型或跨主机身份。删除前重新验证绝对边界、真实路径和目录内无链接；保留不确定材料可导致容量准入拒绝，需要Agent诊断，不自动放宽上限。

[041探针](../../scripts/probe-offsite-crash.ts)验证三处真实SIGKILL：创建暂存后、传输完成但未提交、提交后未收到确认；检查点都在rclone退出后，没有证明传输进行中的硬杀、断电或全机重启。新进程回收已退出且归属明确的暂存，以原ID恢复，并核对已有密文不变。远端残片清理仍未实现。

## Agent准备与命令

1. 从版本锁中的官方固定URL下载对应归档，核对归档SHA256，解压后核对可执行文件SHA256。当前Windows二进制实际执行通过；Linux仅下载/解压/哈希，未执行。官方校验和经HTTPS取得，发布签名尚未验证，不能称为签名验证。
2. 使用[rclone配置模板](rclone.conf.example)配置已授权的私有桶与专用crypt子路径；密码和盐分别生成，使用rclone obscure的标准输入方式处理，不能放在命令参数、Git或普通备份里。模板为空密码，不能直接启动。
3. Linux配置必须归运行账号所有且0600，父目录0700；Windows配置必须有当前账号独占DACL。放在独立秘密目录，例如/var/lib/workbench-offsite/config，不能放在被备份的项目内。Agent检查模型凭据不混入此配置。
4. 私有工作目录需有空间容纳两份明文恢复包；当前准入上限8GiB，磁盘保留12GiB，每个rclone步骤最大传输4GiB、最长5分钟、仅一次工具尝试，自动流程总时限20分钟。不是OS配额或多进程空间预留。CLI保留验证/失败材料；自动流程通过工作目录/尝试记录回收本次暂存与已确认退出的历史自动暂存。rclone同时使用自身max-duration与HARD停止策略，宿主超时另保留；未实测5分钟等待或传输中硬杀。[时限说明](https://rclone.org/docs/)
5. 密码、盐及必要配置要在独立于主机与加密桶的位置保存恢复材料，并核验可读取。原主机消失后没有这些材料无法解密。上传成功的点ID也需要独立记录；可用rclone lsd workbench-offsite:snapshots列举候选ID，列表包含未提交残片，必须通过recover校验才算可用。

命令由Agent在已授权环境执行，路径带空格时作为独立参数传递；不要把秘密放入终端或运行日志：

```text
Node24 --import tsx scripts/offsite-backup.ts upload <固定rclone绝对路径> <私有配置路径> <私有工作目录> <已验证备份目录> [固定恢复点ID]
Node24 --import tsx scripts/offsite-backup.ts recover <固定rclone绝对路径> <私有配置路径> <私有工作目录> <恢复点ID> <新数据目录>
```

上传前由Agent生成并保存固定ID；未知结果重试沿用。未传ID的CLI仍生成新UUID，不能因此盲目重试。CLI仅输出恢复点ID、清单摘要和成功结果；rclone输出不进入产品或普通日志。普通备份继续排除ChatGPT授权和设备/浏览器登录，恢复后需重新配置它们；受控授权交接另走[ADR-023](../../doc/adr/023-chatgpt-session-transfer.md)。

## 验收范围

[独立探针](../../scripts/probe-offsite-backup.ts)实际使用Windows rclone、合成业务资料与本地加密目录，包含原生SDK重开、原件/恢复件字节、额外凭据排除、错密钥/密文损坏/缺提交记录/配置改变拒绝。不是云端S3、跨网络、不同机器或真实Linux证据；探针中的密钥只用于合成资料。

[040自动探针](../../scripts/probe-automatic-offsite.ts)实际验证后台失败保留、重启同ID、丢本地确认后远端密文字节不变、ID冲突拒绝、暂存回收及原生SDK恢复。039的13个进程是当时版本的历史证据；040增加的远端提交探测会改变进程数量。两者都没有真实云端、Linux、第二台机器或事故恢复证据。

真实部署还需验证：TLS端点与私有桶权限、传输/读回成本、传输中的宿主硬杀与遗留子进程、实际断网/断电、配额、恢复时间和独立机器事故演练，以及远端保留/残片清理。自动源码与产品状态已衔接，当前主服务未重启加载、未配置转存，不能宣称每日云备份已经运行。

当前云方案的40GiB落地卷不自动改变内置自动备份8GiB上限；保留7份和临时恢复的容量需按真实恢复包重新核算配置，不能根据云盘大小宣称7份最大容量备份已通过。资源费用与范围（旧文档已移除，参见 Git 历史）
