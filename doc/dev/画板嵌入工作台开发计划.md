# 画板嵌入工作台开发计划

日期：2026-10-16。状态：EMB-00–07 与 V01–12 隔离证据已落地（见 current 097）；审查记录 [074](iterations/074-canvas-embedding-plan-review.md)、残余闭合 [097](iterations/097-canvas-residual-closure.md)、[使用说明](画板嵌入使用说明.md)。默认仍关闭嵌入；未正式部署或推送。

## 1. 交付目标与现状

在现有工作台的 CanvasLayer 中接入真实 OpenPencil 画板：中层透明区域可直接编辑底层画板，顶层浮窗保持不透明；顶部项目选择切换业务内容与对应画板，切换工作空间只改变窗口配置。保留 Pi、插件、资产、布局保存、窗口切换和浮窗显式停靠行为。

基线为本地 main 合并提交 `1a9a44e`，包含 bluegill 的 `5a64f5f`，尚未推送。工作树另有插件功能未提交改动，应逐文件保护；不能 reset、覆盖整个工作树或把这些改动混入接入提交。

| 已有代码事实 | 接入缺口 |
| --- | --- |
| `src/workbench/canvas-layer.tsx` 已有底层容器；`layers.css` 已实现透明穿透和实底浮窗 | 尚无实际编辑器、通信桥或画板上下文 |
| `project-context.ts` 同步切换资产/Pi，并保存各项目窗口内容 | 尚无切换前保存屏障和项目—画板绑定 |
| `apps/canvas` 固定上游、Bun 与 57 个补丁，Vue 编辑器独立开发 | 需可复现构建、嵌入模式及宿主资源路由 |
| `local/dev.mjs` 启动 Vite/Bun 与带令牌的本地存储服务；`desktop-entry.mjs` 有私有 stdin 启动协议 | 开发预览不是工作台生产部署，需宿主管理服务生命周期 |
| 本地服务已有画板、目录、历史、作品包与恢复能力 | 不能另造一份场景存储；尚未纳入工作台备份和项目归属 |

合并时画板单元测试为 55 通过、2 失败，缺 `.runtime/open-pencil-upstream/packages/fig/dist/index.js`。独立分支历史验证不能替代当前合并基线验证；规模性能、离线字体等未完成项保留原限制。

## 2. 第一版技术与产品决策

1. **独立构建的编辑器，通过 iframe 挂载底层。** React 工作台不直接依赖 Vue 内部 store；固定上游及补丁继续在 `apps/canvas` 管理，新增补丁从 0058 起编号。不能只修改被忽略的 `.runtime` 源码。
2. 生产目标为工作台同源 `/canvas/` 静态入口及受鉴权保护的 `/api/canvas/` 有限代理。先验证资源 base、WASM、字体、worker、下载和 CSP。不得以固定 14220 端口、开发服务器或本机其他工作树作为交付依赖。同源 iframe 是工程隔离，不是运行不可信代码的安全沙箱。
3. 服务端保留原画板存储服务为唯一场景写入者。宿主启动受管子进程，通过私有管道提供随机令牌与管理区路径，回环随机端口；借鉴 desktop-entry 协议，先核实其打包相对路径和运行时依赖，再决定复用入口或增加适配入口。令牌不进前端、URL、布局、日志或作品包。
4. 工作台只维持一个活动编辑器实例，切项目换文档，切工作空间不销毁画板；不为每个窗口/空间创建 iframe。画布位于工作区，导航、顶部栏和状态栏仍由宿主负责。
5. 项目可登记多张画板，但第一版只展示一张活动画板，记住每个项目最近打开项。无项目时使用独立“个人草稿”上下文，首次实际编辑才落盘；空白打开不自动创建作品。已有独立画板通过明确“关联已有画板”接入，不自动按同名项目或目录猜测。
6. 嵌入模式隐藏重复的应用导航，保留编辑工具、缩放、图层/属性、保存状态、画板/目录入口和错误恢复。第一版保留编辑器自己的面板，不同时改成工作台窗口；提供宿主“显示画板工具/专注画板”入口，临时隐藏中层并可恢复原布局，不永久改写用户配置。
7. 宿主主题通过语义颜色和线宽传入编辑器外壳；不能修改作品节点颜色、世界坐标或画板内容。画板缩放/视口跟随画板存储，不进入窗口布局 JSON。

第一版不包含重写编辑器、替换 Pi、迁移全部历史目录、跨机协作、重新开发完整目录/节点能力、把图层属性拆成独立宿主窗口。已有能力回归失败时仍须修复接入引入的问题。

生产路由前置：`server/app.ts` 当前全局 `X-Frame-Options: DENY` 与 CSP `frame-ancestors 'none'` 会阻止本方案。仅画板静态入口允许 SAMEORIGIN / `frame-ancestors 'self'`，宿主其它页面继续禁止嵌入；为画板制定独立的脚本、WASM、worker、字体、样式策略并实际验证，不全局放宽 CSP。EMB-01 必须经真实宿主响应头验证，开发代理成功不能替代它。

## 3. 桥接、项目切换与保存

新增共享、可校验的桥协议（建议 `shared/canvas-bridge.ts`）。信封含 `protocolVersion / instanceId / requestId / contextEpoch / projectId / canvasId / type / payload`。只接收当前 iframe 的 `event.source` 与精确同源 origin；校验消息类型、字段、大小和当前实例，不使用 `*` 发送目标。握手协商能力，版本不兼容显示可恢复错误；ACK、超时、有界队列、重复请求与旧实例消息均有明确结果。

最小消息包含 READY、INIT、OPEN_CONTEXT、PREPARE_SWITCH、SAVE、DOCUMENT_STATE、THEME、SET_INTERACTION、ACK、ERROR、REQUEST_OPEN。状态区分未加载、加载中、可编辑、脏、保存中、已保存、保存失败、冲突、服务离线。保存 ACK 对应指定文档及修订，只有真实持久化确认才显示“已保存”；不能把收到消息、排队或本地缓存当作保存成功。

宿主现有“已保存”指布局，应明确为“布局已保存”；画板另显示“画板保存中/已保存/失败”。布局菜单的保存不冒充作品保存，布局成功而画板失败时错误仍清晰可见。

项目切换是协调流程，替换现有直接 `selectProject` 调用：

1. 捕获旧项目、画板、修订与切换代次，进入短暂切换屏障；旧文档停止产生新编辑或明确排入后续修订。
2. 保存旧画板并取得对应修订确认；失败停留原项目，提供重试/取消，明确放弃须有确认且保留可恢复快照。
3. 校验目标项目权限与存在性，解析绑定并加载目标文档；失败保留旧文档及旧项目，不呈现“项目 B 配画板 A”。
4. 目标加载成功才提交宿主项目、资产/Pi上下文和编辑器活动上下文；关闭屏障。旧项目中的 Pi 任务不停止，异步回写仍路由原项目。
5. 连续 A→B→C 合并尚未执行的切换意图；已开始的保存先完成，过时代次结果不得覆盖当前项目。取消返回原状态。

浏览器刷新恢复、布局导入/恢复、跨标签布局更新、项目归档、编辑器内部“本机画布/目录/子目录”切换都必须走同一协调入口或明确的受校验通知，不能只拦截顶部下拉。目录导航可改变活动 canvasId，但不能暗中更改 projectId 或跳过项目绑定检查。

项目映射属于宿主业务数据，建议独立表保存项目/个人上下文、画板 ID、最近打开项、修订；不要塞入 workspace/window.view。创建画板和写绑定跨两个存储，使用操作 ID、可恢复登记和幂等重试；中断不得重复建画板或留下被误认为已提交的绑定。现有 FIG 导出会改变节点 ID，不能以 FIG ID 充当业务身份。

现有画板服务的 `/canvases` 是全局列表，没有项目边界。嵌入入口默认只列当前上下文已绑定画板，宿主逐请求检查画板、目录挂载、历史、导入目标和节点执行关联；不能只过滤列表后允许任意 ID 读写。未绑定的历史画板通过独立“关联已有画板”操作选取，第一版每张画板只归属一个项目/个人上下文，其他项目不得隐式复用；跨项目需要显式复制并保留来源。目录已有画板归属其他项目时提示切换所属项目或取消，不自动改绑。用户仍可管理自己的独立资料库，但这不是嵌入会话绕过上下文的通道。

`local/workspace-store.mjs` 已实现 expectedRevision 比较及 operationId 幂等，接入必须保留这些约束。多浏览器同时编辑同一画板时，第一版要求修订冲突可见，禁止后写静默覆盖；验证桥、自动保存与导入不会绕过检查。冲突后保留本地草稿，提供另存副本或明确重载，不自动覆盖远端。此机制不等于实时协作，也不替代管理区的进程所有权。

## 4. 三层交互与焦点

透明区域依赖浏览器原生命中 iframe，不合成转发鼠标事件。中层正文、输入、按钮、标题、分割线阻挡事件；中层空白、空分区穿透；普通及置顶浮窗整个矩形都阻挡。不能把中层整体设为 pointer-events:auto，也不能让浮窗空白透下去。

宿主拖动/缩放可能跨入 iframe 导致 pointermove/up 丢失，需在开始时获取 pointer capture，必要时使用仅拖动期间的透明事件屏障。pointerup、pointercancel、lostpointercapture、窗口失焦和 Esc 都结束屏障；普通编辑时不存在全屏挡板。分割线视觉宽度使用同一设置 token，命中区独立扩大，不把可见边线加粗。

手势所有权必须双向验证：在画板内开始拖节点、框选或连线，再越过中层正文、浮窗或画板边界，必须完成或明确取消，不能卡住或触发窗口拖动。浮窗阻挡新手势，不抢走已经由画板捕获的手势；当前编辑器不同工具的捕获实现不能一概假定可靠。V02 包含反向跨层、边界外松手、Esc 与捕获丢失。

宿主模态框打开时禁止编辑器继续编辑，焦点留在模态；关闭按仍有效的焦点目标恢复。iframe 内模态不能越过 iframe z-index：涉及全局确认/文件关联的交互通过桥请求宿主呈现，避免被中层挡住或同时出现两个有效模态。菜单开启、编辑器弹层及全局快捷键明确焦点所有者。

iframe 内的 pointerdown/keydown 不冒泡到宿主 document；当前 controls.tsx 的菜单关闭监听和窗口列表监听因此无法自动收到画板点击。桥需发送校验过的 INTERACTION_STARTED / FOCUS_CHANGED 通知，关闭宿主非模态菜单并保留这一次画板原生操作，不用常驻遮罩要求点两次。嵌入可用时空布局不再显示覆盖画板的整块 welcome；使用可收起的小入口或一次性引导，刷新、清空布局和无窗口时仍可直接编辑底层。

“专注画板”临时隐藏中层并收拢顶层浮窗，Pi任务与窗口实例继续常驻；顶部退出入口始终可达。此状态只影响当前页面呈现，不写入持久布局，不改变浮窗坐标、置顶、收拢配置；退出恢复原配置。V03 验证置顶浮窗完全遮住工具时仍可找回，退出及刷新后没有错误保存临时状态。

Ctrl/Cmd+Z、复制粘贴、Delete、Space、滚轮缩放、Ctrl/Cmd+S 只交给当前焦点所在区域；聊天输入与中文 IME 组合态不能触发画板删除/快捷键。程序不得尝试依靠 beforeunload 异步保存；持续保存加本地恢复快照，关闭页只做同步离开提醒。剪贴板或下载权限失败应显示失败原因，不伪造成功。

## 5. 服务、鉴权、数据与回滚

- 宿主服务端验证现有登录/会话、项目访问权、来源及写请求 CSRF；浏览器传入 projectId 不构成授权。有限代理校验规范化路径/方法/内容类型，不暴露任意 URL、文件路径代理或任意命令。作品包采用有上限的流式请求、取消与超时，不套用小 JSON 请求限制，也不无限缓存 350 MB 内容。
- 明确单一服务所有者和管理区锁；同时打开两个工作台进程不能争写同一管理区。子进程启动失败、退出、宿主异常终止需能识别与回收，重启有次数上限和退避，保留未保存恢复数据。开发验证使用独立目录与端口，不启动/停止身份不明的现有服务。
- 新画板管理区放入明确配置路径，默认应跟随工作台数据根；独立画板旧 `.runtime/canvas-data` 不自动移动或删除。关联/导入前核对 ID、目录身份、作品包和原件边界。用户外部目录不会自动变成工作台资产，也不被备份复制或删除。
- `server/storage.ts` 的容量保护不自动覆盖画板子进程写入。EMB-02 设计、EMB-06 验收共享容量预算和预留：场景历史、嵌入资源、导入暂存、导出操作、索引/日志及后台扫描写入均须计量和准入；并发预留不得超卖，失败释放预留，留足修复/恢复空间。返回可识别的容量错误（如507），用户可导出/清理后重试，不能以永久禁写阻断恢复。外部成果目录需单独检查目标空间和权限，不能宣称受工作台总量配额完全约束。
- 备份涵盖宿主绑定和画板场景、历史、资源及元数据。结合 `server/backup.ts` 的维护机制，协调所有画板写入者（包括后台目录观察）建立一致性检查点，使用 SQLite 正确快照而非裸复制活跃 WAL。记录共同检查点/修订清单，恢复后核对绑定可达和内容摘要。外部原件仍按既有引用边界处理。
- 现行 `verifyBackup` 只允许 workbench.sqlite、assets 和 sessions 路径，不能仅把画板文件放入数据根就称已备份。EMB-06 必须同时更新备份清单版本、路径白名单、校验和恢复逻辑；保留读取 schema 1 老备份的能力，拒绝未知新格式。恢复不重放未完成的导出/节点执行，不自动重新启用可执行内容。
- 功能开关先默认关闭，隔离环境通过后启用。关闭嵌入只卸载视图，不删除作品和绑定；重试不能用空白场景覆盖失败加载的文档。回滚保留新增数据，旧代码不能误清理新表；有迁移时提供升级前备份和兼容性说明。
- 服务离线时工作台、Pi 和布局仍可用；画板显示局部状态及重试入口。禁止无限重载 iframe、自动放弃脏内容、通过重启整个工作台处理普通画板错误。

EMB-02 的生产产物验收必须在全新非仓库目录进行，不能通过链接引用原 checkout、`.runtime` 或开发 node_modules。`local/package-export.mjs` 当前动态导入固定上游的 fig 构建，需调整为随包依赖并验证 Node24 下实际作品包导出/导入、解析器和 WASM 资源；只关闭开发服务器不足以证明可独立运行。

归属检查覆盖 mount/file ID、output operationId、package-import ID 及其重试/继续接口，不只覆盖 canvasId。V08 增加 A 上下文提交 B 的这些 ID 被拒绝，V05/V09 增加配额耗尽、并发预留、507 后恢复及后台写入容量验证。

## 8. Agent 长时循环与交付条件

沿用 `doc/开发执行文档.md` 的 Observe → Select → Define → Implement → Verify → Review → Record → Continue。每轮只推进一个依赖就绪的 EMB 任务：

1. 恢复 current/backlog、读取 diff 和活动进程身份；确认上一轮未完成命令及样例数据位置，不重复启动服务。
2. 写清本轮验收、涉及文件、失败回退与命令；实现后跑相关验证，保存失败原因和实际退出码。
3. 失败修复后再验，不删断言/跳过失败来达标；同因三次无进展记录诊断和恢复条件，继续独立可推进项，不盲目循环。
4. 更新 backlog 的任务状态、证据和 next action；current 记录端口/PID及验证时间、未完成句柄、数据路径和未提交改动归属。长任务在可恢复边界停下。
5. 阶段依赖通过后自动进入下一阶段，无须为可逆常规实现反复询问。授权范围仍以用户后续指令为准；计划不自行授权正式部署、发布或真实模型调用。

只有 EMB-00–07 的门槛及 V01–12 对应证据成立，且没有未处置的数据丢失/上下文串写/交互阻断问题，才可称“已嵌入并完成交付”。若仅技术探针或部分阶段通过，准确说明范围。交付提供启动入口、构建方式、数据与恢复说明、限制、差异审查以及可继续工作的现场。

## 9. 子 agent 审查

分别审查架构/生命周期、交互/产品、数据/交付；审查只读代码与本文，不实施。输出具体问题、严重度、证据路径、建议及验收。主 agent 逐条采纳或说明未采纳原因，并把结果写入审查记录；未解决的关键问题保持阶段门槛，不只留在聊天中。
