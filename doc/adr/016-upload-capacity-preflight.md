# ADR-016：一次上传的前置容量约束共同测量

2026-10-06。022将整体与分组容量测量合并为一次新鲜遍历，但同一次上传在写入暂存前仍依次测量暂存、资产、数据库三次，并额外遍历资产目录。新测默认661资产建档约172秒，保留全部配额、恢复空间和崩溃边界，优化重复测量。

StorageCapacity.assertAll接收同一预期写入阶段的多个独立约束，一次重新测量整体目录、各组、磁盘空间与异常，再逐个判断原增长估算和control恢复预留。它不是多个独立写入的预算合计接口，也不跨写入、暂存变化、SQL更新或事务缓存测量。原assert委托单个约束，行为和返回void保持。

资产提交在已有排他锁内，用同一新鲜结果检查暂存、资产、数据库的原增长预测；资产原quotaBytes同时根据此结果中的完整资产分组核对。不再额外扫描已测资产目录；没有StorageCapacity的旧直接调用保留原路径。未知根文件仍计入整体、嵌套资产计入资产、链接和测量错误仍拒写；SQL阶段仍独立重新测量，数据库页上限和事务累计估算不改变。

不会提高原2 GiB整体/500 MiB资产等默认值，也不扩大4 MiB恢复预留。该检查仍是受控应用准入，不替代OS文件系统配额、WAL实际物理限制或外部程序竞争空间的防护。

新增回归核对同时约束只测量一次、整体恢复预留/控制写入、两次调用间外部未知文件变化、外部资产增长在暂存前拒绝、原内容保持。旧上传配额、故障占用和四阶段实际进程中断同时回归。完整661资产的相同脚本/依赖/内容清单新测对比约172秒→121秒，仅是本机各一次测量；单次写入峰值仍约596毫秒，不等同生产HTTP界面响应门槛通过。工程与产品证据见[024](../dev/iterations/024-batch-write.md)。
