## 发现与修复

[恢复实现](../../../server/backup.ts)原先用字符串前缀和当前宿主relative处理备份来源地址。旧Windows地址在POSIX中被当成文件名；不同盘符大小写/分隔符形式可能被清空，前缀相似的邻居目录也可能被误认作数据子目录。

[故障记录](../../../output/dev-evidence/portable-backup-failure.json)保存修复前实际本机备份/SQLite恢复测试退出1：来源Z盘地址与等价小写正斜线地址导致恢复Run.sessionPath为undefined。不是实际Linux执行证据。

修复根据sourceRoot选择Windows或POSIX路径语义，求相对地址并核对包含关系，再由目标宿主拼接新路径。Run与session_binding共用这一重定位；拒绝相邻目录、父目录逃逸、其他盘符、相对地址和POSIX反斜线转换陷阱。保留旧schema1清单兼容，不修改原生JSONL原件或复制凭据。

[两项回归](../../../tests/backup-portable.test.ts)覆盖Windows→POSIX、POSIX→Windows的路径语义和UNC/边界拒绝；实际本机对合成Windows与POSIX来源地址的恢复包进行SQLite/原生SDK重开，核对Run、binding、cwd、新位置、会话ID、历史标记、原件与恢复件字节和旧worker清理。路径语义测试不等于Linux进程或真实两机迁移。
