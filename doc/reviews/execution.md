# 主开发文档审查：执行、调度与交付

审查日期：2026-10-05。范围：主文档第 6、9、10、14、15、18、19 节。主文档只读；以下为实现建议，尚未构成用户确认的产品决策。

## 总体判断

文档明确了正确的分层、隔离与验证方向，但仍属于产品架构基线。当前缺少运行生命周期、任务状态转移、资源调度契约和可重复验收场景。直接交给开发 Agent，容易出现界面可用、实际执行无法恢复，或不同模块各自实现一套状态的情况。

## P0：开发前需要补齐

### 1. “离开后继续执行”的部署前提未定义

位置：6.2、10、16。缺口：没有确定关闭标签页、关闭客户端、电脑休眠、断网与进程崩溃分别意味着什么。一个持久化任务记录不等于任务能在后台继续运行。

建议：先确定首版本地后台执行服务与界面的生命周期边界。关闭项目标签页不停止 Run；客户端关闭后是否继续由明确设置决定；电脑关机或休眠不承诺执行。失去执行进程后将 Run 标记为 interrupted/reconciling，检查产物和外部结果，再由策略决定恢复，不能直接显示运行中或盲目重试。远程长期执行列为后续部署能力。

验收：启动长任务后关闭标签页、刷新界面，重新打开可以查看持续事件；杀掉执行服务后重启，任务显示真实中断状态，部分产物不丢失。

### 2. Task、Run、验证结果缺少分离与状态机

位置：8、9、10。缺口：任务“运行完成”和成果“验收通过”容易被混为成功；重试与恢复究竟复用 Run 还是新建 Run，没有定义。暂停仅说明停止调度，但数据状态没有“暂停”及其语义。

建议：Task 表示目标与验收，Run 表示一次执行尝试；每次重试新建 Run，保留 parentRunId/attempt。Run 至少包含 queued、running、waiting_user、completed、failed、cancelled、interrupted；Task 的 acceptanceStatus 独立为 pending、passed、failed、needs_review。暂停作为调度控制，记录 pauseRequested 和暂停原因，不伪装成已停止执行。Task 仅在产物登记且验收通过后交付成功。

验收：Agent 返回“完成”但产物缺失时不得成功；工具成功但验收失败保留结果与失败依据；重复/迟到事件不能把已取消 Run 改回运行中。

### 3. 缺少调度唯一权威与崩溃恢复机制

位置：6.2、9、10。缺口：主助手“安排”和调度器“管理”边界未形成契约，多个会话可能重复启动同一任务；执行中崩溃无法判断所有权。

建议：主助手只提交任务计划和控制命令，唯一调度服务取得执行租约后启动 worker；持久化 queue、lease owner、heartbeat、expiresAt、attempt 和幂等键。事件追加存储并有 Run 内单调序号，前端支持游标重连。worker 失联先对账再重试，对外写入存在未知结果时进入等待核实。首版不需要分布式调度，但需要防止单机重启和双实例重复执行。

验收：双击执行或重复发送同一命令只创建一次受控执行；worker 强制退出后可定位为中断；重连不漏事件、不重复资产。

### 4. 首版范围过宽，且自我升级前置依赖没有门槛

位置：14、15。缺口：首版同时包含完整资产管理、子代理和自我升级，未限制项目类型、扩展类型、页面种类与恢复深度。容易在建立可靠执行前投入动态页面和插件发布。

建议：划分两个可交付里程碑：M0 为固定项目页面 + Pi 单次执行 + 文件成果 + 持久化事件 + 崩溃识别；M1 才增加两个受控子代理和“新增一个可卸载插件”的自我扩展。首版不修改运行内核、不迁移业务数据结构。自我升级开始前必须通过任务恢复、资产对账、基础版本恢复检查。

## P1：进入多代理和自我升级前补齐

### 5. 并发预算缺少可执行规则

位置：10。缺口：并发数、预算和超时只有原则，没有全局/项目/Run 的继承、抢占、供应商限流及费用误差规则。

建议：首版固定全局最多 2 个执行 worker，每项目最多 1 个写入 worker，委派深度最多 1 层。总预算包含子代理，不允许每个子代理重新获得完整预算。明确超时是排队超时、工具超时还是整个 Run 时限。记录 token、实际可得费用与估算费用；无法获得实时费用时以调用数/token 和预留额度执行限制。优先级只影响未开始任务，首版不承诺自动抢占运行任务。

### 6. 子代理交接缺少接口与部分失败处理

位置：10。建议规定 handoff 字段：taskId、projectId、输入资产版本、允许工具、工作目录、deadline、预算、预期产物 schema、acceptanceCriteria、完成/失败/需用户结果。父代理等待所有必需依赖；可选支路失败可交付部分成果，但必须标记未完成项。子代理异常不能自动获得更多权限或无限委派。取消父任务需传播到子任务并收集实际停止结果。

### 7. 工作目录隔离不足以支撑代码项目并行

位置：10、12。缺口：共享端口、依赖、环境变量、GPU、文件监听和残留进程仍会冲突。

建议：开发任务采用每 Run 独立分支/工作副本、端口登记、进程树归属与清理、环境清单及凭据注入。新服务先通过健康检查才展示预览。项目预览失败区分服务未启动、测试失败和 UI 断连。资源紧张时排队，不依赖模型自行协调。

### 8. 回滚验收只检查“能启动”不够

位置：11、14 阶段四。建议验证旧项目打开、原工具可调用、已存在资产仍可读取、权限不扩大、任务记录可回放，以及停用新插件后不影响在途任务。对于新插件首次自我升级，固定插件 API、运行基线、测试集和发布清单；新旧版本不能同时写同一个业务对象。

### 9. 缺少面向用户的故障诊断与运维入口

位置：4.4、18。建议补充诊断页面：模型认证、网络、Pi 进程、扩展加载、磁盘、队列与预览服务状态；展示最后事件时间、卡住原因和下一步操作。日志贯穿 projectId/taskId/runId/toolCallId；提供脱敏诊断导出和事件保留/清理策略。错误信息须说明是否已产生部分结果、是否可安全重试。

## 建议加入文档的首版端到端验收剧本

使用本地固定样例资料，避免依赖变化中的外部网站；真实 Pi 与模型执行，外部发布只用测试出口。

1. 从主页创建项目 A，在对话中要求读取一份本地 CSV，生成一份 HTML 图表与有数据依据的短文；图表由程序产生，避免模型编造数值。
2. 创建项目 B，要求整理另一份资料。分别使用不同目录和上下文，切换标签页后指令始终作用于正确对象。
3. M0 验证单 worker 排队；M1 由主助手委派两个独立子任务，确保全局并发上限、交接产物和依赖顺序。
4. 查看真实事件、文件成果与验收结果；关闭页面重新打开，文件和状态一致。
5. 注入一个工具错误、重复提交及执行服务退出，验证失败原因、中断识别、部分成果和新 Run 重试记录。
6. 取消一个长任务，检查工具终止结果、子任务状态与残留进程；未能终止时明确显示仍在收尾。
7. M1 再要求新增“两个图表版本比较”插件，在独立副本开发、验证和启用；通过对话及界面执行同一操作。
8. 停用插件并恢复版本，确认旧项目、资产、原有工具和会话仍可使用。

验收证据包应含固定输入、实际输出、事件记录、验证报告、失败注入结果和版本信息；禁止只提交页面截图或 Agent 自评。

## P2：稳定使用后增加

补充备份与恢复演练、磁盘配额与归档、长期任务通知、成本看板及真实使用指标。产品成功标准可操作化为：目标到首个可验证成果的时间、验收通过率、人工介入次数、恢复成功率和能力复用次数；先记录基线，再设目标。
